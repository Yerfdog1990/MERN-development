# Introduction to React

---

## What is React?

**React** is a JavaScript **library** (not a framework) for building user interfaces. It was developed by Facebook and is used by major companies like Netflix, YouTube, Spotify, and Airbnb to build their front-end applications.

> **Library vs Framework:** A library provides helpful functions you can call in your code. A framework controls the structure of your entire application. React only handles the UI layer — you choose your own tools for routing, state management, and other concerns.

---

## Why React? — The Problem with Vanilla JavaScript

### The Duplication Problem

In a multi-page website, common elements like a navbar and footer appear on every page. With plain HTML and JavaScript, you have to write and maintain the same code in every file:

```
index.html      → navbar + sidebar + content + footer
about.html      → navbar + sidebar + content + footer
products.html   → navbar + sidebar + content + footer
```

Any change to the navbar means updating every single file. This is error-prone and hard to maintain.

**React solves this** with **reusable components** — write once, use everywhere.

### The DOM Update Problem

When a user interacts with a page (clicking a button, adding an item to a cart), vanilla JavaScript has to manually find the right DOM element and update it. If not done carefully, the entire page or large sections of it get re-rendered — even parts that haven't changed.

**React solves this** with the **Virtual DOM** — it only updates the specific part of the page that actually changed.

---

## JavaScript vs React — Key Differences

| | Plain JavaScript | React |
|---|---|---|
| DOM manipulation | Manual — `document.getElementById`, `addEventListener` | Automatic — React handles updates via Virtual DOM |
| UI updates | Manually update each element when data changes | Automatically re-renders when state changes |
| Code structure | Procedural — you write every step | Component-based — reusable, modular pieces |
| HTML in JS | Not supported natively | JSX — write HTML-like syntax inside JavaScript |
| State management | Manual — track variables yourself | Built-in with `useState` and other hooks |
| Scalability | Becomes hard to manage in large apps | Scales well — components keep code organized |
| SEO | Limited — all rendering in browser | Supports server-side rendering for better SEO |
| Data flow | No convention | One-way data binding — parent passes data to child via props |

### 1. Reusable Components

A component is a function that returns a piece of UI. Create it once and use it anywhere:

```jsx
// Create once
function Navbar() {
  return <nav>...</nav>;
}

// Use on every page
function HomePage() {
  return (
    <>
      <Navbar />
      <main>Home content</main>
    </>
  );
}

function ProductsPage() {
  return (
    <>
      <Navbar />
      <main>Products content</main>
    </>
  );
}
```

### 2. Virtual DOM

The Virtual DOM is a lightweight copy of the real DOM kept in memory. When something changes:

1. React creates a new Virtual DOM snapshot
2. Compares it with the previous one (called **diffing**)
3. Identifies exactly what changed
4. Updates **only that part** of the real DOM

This means clicking a "save" button only re-renders the save button — not the navbar, sidebar, and every card on the page.

### 3. Declarative Nature

**Imperative** (vanilla JS) — you describe *how* to do something step by step:

```js
// Imperative — tell it every step
const button = document.getElementById('myButton');
button.addEventListener('click', function() {
  const p = document.createElement('p');
  p.textContent = 'Hello!';
  document.body.appendChild(p);
});
```

**Declarative** (React) — you describe *what* you want, React figures out how:

```jsx
// Declarative — describe what you want
function App() {
  const [clicked, setClicked] = useState(false);

  return (
    <div>
      <button onClick={() => setClicked(true)}>Click me</button>
      {clicked && <p>Hello!</p>}
    </div>
  );
}
```

### 4. Hooks

Hooks are functions that let you add features like state and side effects to components. They optimize performance and simplify logic. Common hooks include `useState`, `useEffect`, `useRef`, `useMemo`, and `useCallback`.

## Vanilla JavaScript vs React — Side by Side

The same feature implemented both ways shows exactly what React improves.

### Example: A Counter with Add and Reset

---

#### Vanilla JavaScript Version

```html
<!DOCTYPE html>
<html>
<body>
  <h1 id="count">0</h1>
  <button id="addBtn">Add</button>
  <button id="resetBtn">Reset</button>

  <script>
    // Step 1: Find the elements
    const countEl = document.getElementById('count');
    const addBtn  = document.getElementById('addBtn');
    const resetBtn = document.getElementById('resetBtn');

    // Step 2: Track state manually
    let count = 0;

    // Step 3: Update the DOM manually every time state changes
    addBtn.addEventListener('click', function() {
      count++;
      countEl.textContent = count; // manually update DOM
    });

    resetBtn.addEventListener('click', function() {
      count = 0;
      countEl.textContent = count; // manually update DOM
    });
  </script>
</body>
</html>
```

**Problems with this approach:**
- You must manually find every DOM element
- You must manually update the DOM every time state changes
- As complexity grows, tracking which elements need updating becomes error-prone
- Adding features (like disabling the reset button when count is 0) requires more manual DOM updates

---

#### React Version

```jsx
import { useState } from 'react';

function Counter() {
  // React manages the state and DOM updates automatically
  const [count, setCount] = useState(0);

  return (
    <div>
      <h1>{count}</h1>
      <button onClick={() => setCount(count + 1)}>Add</button>
      <button onClick={() => setCount(0)}>Reset</button>
    </div>
  );
}
```

**What React does automatically:**
- Tracks the state value (`count`)
- Re-renders only the `<h1>` when count changes — nothing else on the page
- No manual DOM queries or updates needed

### Example: A Product Card List

This shows the power of reusable components combined with array rendering.

#### Vanilla JavaScript Version

```html
<div id="products"></div>

<script>
  const products = [
    { id: 1, name: 'Laptop',     price: 999  },
    { id: 2, name: 'Phone',      price: 699  },
    { id: 3, name: 'Headphones', price: 199  },
  ];

  const container = document.getElementById('products');

  // Manually build and insert HTML for every item
  products.forEach(function(product) {
    const card = document.createElement('div');
    card.innerHTML = `
      <h2>${product.name}</h2>
      <p>$${product.price}</p>
      <button>Add to Cart</button>
    `;
    container.appendChild(card);
  });
</script>
```

**Problems:** The card structure is defined inline inside a string. To reuse it elsewhere, you'd copy and paste. Any change to the card layout means updating every place it appears.

---

#### React Version

```jsx
// Define the card once as a reusable component
function ProductCard({ name, price }) {
  return (
    <div className="card">
      <h2>{name}</h2>
      <p>${price}</p>
      <button>Add to Cart</button>
    </div>
  );
}

// Use it anywhere, with any data
function ProductList() {
  const products = [
    { id: 1, name: 'Laptop',     price: 999  },
    { id: 2, name: 'Phone',      price: 699  },
    { id: 3, name: 'Headphones', price: 199  },
  ];

  return (
    <div>
      {products.map((product) => (
        <ProductCard
          key={product.id}
          name={product.name}
          price={product.price}
        />
      ))}
    </div>
  );
}
```

**What improved:** `ProductCard` is defined once and reused for every item. Change the card layout in one place — it updates everywhere instantly.

## JavaScript Prerequisites for React

React is built on JavaScript. Before learning React, you need to be comfortable with these concepts — React uses them constantly.

### 1. Arrow Functions

Used everywhere in React — for components, callbacks, and event handlers:

```js
// Regular function
function greet(name) {
  return 'Hello ' + name;
}

// Arrow function — React style
const greet = (name) => 'Hello ' + name;

// Used in components and event handlers
<button onClick={() => setCount(count + 1)}>Click</button>
```

### 2. Destructuring

React uses destructuring heavily for props and state:

```js
// Array destructuring — useState returns an array
const [count, setCount] = useState(0);
const [user, setUser]   = useState(null);

// Object destructuring — extracting props in a component
function UserCard({ name, email, age }) {
  return <p>{name} — {email} — {age}</p>;
}

// Without destructuring (harder to read)
function UserCard(props) {
  return <p>{props.name} — {props.email} — {props.age}</p>;
}
```

### 3. Spread and Rest Operators

Used for passing props, copying state, and collecting arguments:

```js
// Spread — copy and extend an object (common in state updates)
const user = { name: 'John', age: 30 };
const updatedUser = { ...user, age: 31 }; // { name: 'John', age: 31 }

// Spread props onto a component
const buttonProps = { disabled: true, className: 'btn' };
<button {...buttonProps}>Click</button>

// Rest — collect remaining props
function Button({ children, ...rest }) {
  return <button {...rest}>{children}</button>;
}
```

### 4. Array Methods — `map`, `filter`, `reduce`

React renders lists using `map`, and filters data using `filter`:

```js
const users = [
  { id: 1, name: 'Alice', active: true  },
  { id: 2, name: 'Bob',   active: false },
  { id: 3, name: 'Carol', active: true  },
];

// map — render a list of components
{users.map((user) => (
  <UserCard key={user.id} name={user.name} />
))}

// filter + map — show only active users
{users
  .filter((user) => user.active)
  .map((user) => (
    <UserCard key={user.id} name={user.name} />
  ))
}

// reduce — calculate totals for a cart
const total = cartItems.reduce((acc, item) => acc + item.price, 0);
```

### 5. Promises and `async`/`await`

React fetches data from APIs inside `useEffect`. You need to understand async code:

```js
// Using async/await inside useEffect
useEffect(() => {
  async function fetchUsers() {
    try {
      const response = await fetch('https://api.example.com/users');
      const data     = await response.json();
      setUsers(data);
    } catch (error) {
      setError(error.message);
    }
  }

  fetchUsers();
}, []);
```

### 6. Modules — `import` / `export`

React components live in separate files and are imported/exported:

```js
// Exporting a component
export default function Navbar() {
  return <nav>...</nav>;
}

// Named export
export function Button({ children }) {
  return <button>{children}</button>;
}

// Importing
import Navbar           from './Navbar';
import { Button }       from './Button';
import { useState }     from 'react';
import { BrowserRouter } from 'react-router-dom';
```

### 7. Ternary Operator and Short-Circuit Evaluation

React uses these for conditional rendering:

```jsx
// Ternary — show one thing or another
{isLoggedIn ? <Dashboard /> : <LoginPage />}

// Short-circuit — show something or nothing
{isLoading && <Spinner />}
{error && <ErrorMessage message={error} />}

// Multiple conditions
{status === 'loading'  && <Spinner />}
{status === 'error'    && <ErrorMessage />}
{status === 'success'  && <DataList data={data} />}
```

### 8. Higher-Order Functions and Callbacks

React's event handlers, `useEffect`, and custom hooks all use callbacks:

```jsx
// Callback as event handler
<button onClick={() => handleDelete(item.id)}>Delete</button>

// useEffect takes a callback
useEffect(() => {
  // side effect here
}, [dependency]);

// Custom hook — a function that uses other hooks
function useFetch(url) {
  const [data, setData]   = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetch(url)
      .then((res) => res.json())
      .then((data) => {
        setData(data);
        setLoading(false);
      });
  }, [url]);

  return { data, loading };
}
```

### Prerequisites Summary

| Concept | Why it matters in React |
|---|---|
| Arrow functions | Components, event handlers, callbacks |
| Destructuring | Props, `useState`, API responses |
| Spread / rest | State updates, passing props |
| `map` / `filter` / `reduce` | Rendering lists, filtering data, computing totals |
| Promises / `async`/`await` | Fetching data inside `useEffect` |
| `import` / `export` | Every component lives in its own file |
| Ternary / `&&` | Conditional rendering |
| Higher-order functions | Event handlers, hooks, custom logic |
| Closures | How hooks maintain state between renders |

## Core React Features

### 1. Component-Based Architecture

React breaks the UI into small, reusable components. Each component represents one part of the interface — a button, a card, a navbar — and can be used anywhere in the app. This improves reusability, scalability, and makes applications easier to maintain.

### 2. JSX (JavaScript XML)

JSX is a syntax extension for JavaScript that lets you write HTML-like markup directly inside JavaScript files. It makes UI code more readable and declarative:

```jsx
// JSX — HTML-like syntax inside JavaScript
function Welcome() {
  const name = 'John';
  return <h1>Hello, {name}!</h1>;  // curly braces for JS expressions
}
```

JSX compiles down to regular JavaScript function calls under the hood — it is not actual HTML.

### 3. Virtual DOM

React maintains a lightweight copy of the real DOM in memory called the Virtual DOM. When state changes:

1. React creates a new Virtual DOM snapshot
2. Compares it with the previous one (**diffing**)
3. Updates **only the changed parts** of the real DOM

Only the component or part that changes gets updated — not the entire page.

### 4. State Management

State is data managed inside a component. When state changes, React automatically re-renders the component to reflect the update:

```jsx
import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0); // state lives here

  return (
    <div>
      <p>{count}</p>
      <button onClick={() => setCount(count + 1)}>Add</button>
    </div>
  );
}
```

### 5. One-Way Data Binding

Data flows in one direction — from **parent to child** through **props**. This makes data flow predictable and easier to debug:

```jsx
// Parent passes data down
function App() {
  return <UserCard name="Alice" email="alice@example.com" />;
}

// Child receives it as props (read-only)
function UserCard({ name, email }) {
  return <p>{name} — {email}</p>;
}
```

### 6. React Hooks

Hooks are functions that add React features to functional components. They always start with `use`:

| Hook | Purpose |
|---|---|
| `useState` | Add state to a component |
| `useEffect` | Run side effects (fetch data, timers, subscriptions) |
| `useContext` | Access shared data without passing props manually |
| `useRef` | Access a DOM element or keep a mutable value |
| `useMemo` | Cache expensive calculations |
| `useCallback` | Cache a function reference |

### 7. Server-Side Rendering (SSR)

React supports rendering components on the server before sending them to the browser. This improves initial page load speed and makes React applications more SEO-friendly than client-only JavaScript apps.

## Core React Concepts — Quick Reference

| Concept | What it is |
|---|---|
| **Component** | A function that returns JSX (a piece of UI) |
| **JSX** | HTML-like syntax written inside JavaScript |
| **Props** | Read-only data passed from parent to child component |
| **State** | Data a component remembers — changes trigger re-renders |
| **Hooks** | Functions like `useState`, `useEffect` that add React features to components |
| **Virtual DOM** | React's copy of the DOM — used to find and apply minimal updates |

## Common Use Cases

React is used for:

- **Single-page applications (SPAs)** — content changes without full page reloads (Gmail, Trello)
- **Dashboards and admin panels** — reusable data components that update in real time
- **E-commerce** — product cards, cart, checkout flows with shared components
- **Social feeds** — lists of posts, comments, likes — all rendered from data
- **Form-heavy apps** — controlled inputs, validation, multi-step forms

---

## Summary

- React is a **JavaScript library** for building reusable UI components, maintained by Facebook
- It solves the **duplication problem** (write a component once, use it everywhere) and the **DOM update problem** (Virtual DOM updates only what changed)
- React is **declarative** — you describe what the UI should look like, React figures out how to update the DOM
- **Key features:** component-based architecture, JSX, Virtual DOM, state management, one-way data binding, hooks, and server-side rendering
- Plain JavaScript requires **manual DOM manipulation** at every step; React handles updates automatically when state changes
- **One-way data binding** means data flows from parent to child via props — making data flow predictable and debuggable
- React is built entirely on JavaScript — strong knowledge of arrow functions, destructuring, array methods, promises, modules, and closures is essential before starting React
- The jump from vanilla JS to React is mostly a shift from *manually managing the DOM* to *describing the UI as a function of state*
