# React's Data Flow and State Management Evolution

---

## The Evolution of State Management

As React applications grow in complexity, the approach to managing shared data must evolve. Each solution solves the limitations of the previous one:

| Approach | Description | Limitation | Solution |
|---|---|---|---|
| **Props Drilling** | Pass data manually through props at every level | Cumbersome for deeply nested trees | Context API |
| **Context API** | React built-in for passing state globally | Performance issues, large data limits | Redux / Flux |
| **Individual State** | Each component manages its own state | Multiple points of failure, hard to debug | Single Source of Truth |
| **Flux Architecture** | Unidirectional data flow, centralised store | Manual boilerplate | Redux |
| **Redux** | Centralised state, reducers, actions | Initial complexity | Redux Toolkit (RTK) |
| **Redux Persist** | Persist state to local storage for rehydration | None specified | Redux Persist |

---

## Why Context API Falls Short at Scale

Context API is ideal for small, localised state sharing — theming, auth, language preferences. But as applications grow:

- **Performance overhead** — every consumer re-renders when any part of the context changes, even if their slice of data did not change
- **Data size limitations** — large context states degrade performance globally
- **Multiple points of failure** — each component managing its own state makes bugs hard to trace and reproduce
- **Not designed for complex business logic** — no built-in support for structured update flows or debugging tools

---

## Flux Architecture — The Philosophy Behind Redux

Flux emerged to solve state management challenges in complex UIs. Its core idea:

> **Unidirectional data flow** — data flows in one direction only, avoiding circular dependencies and unpredictable mutations.

**The bank analogy:** A bank is a single authoritative entity that manages all money. You cannot directly change your account balance — you must go through the bank's controlled transaction flow. Redux works the same way — no component can directly change the store; all changes go through a defined process.

**Single Source of Truth (SST):** One entity — the store — manages the entire application state. If the data is wrong anywhere, you always know exactly where to look.

## Redux

### What is Redux?

Redux is a state management library for JavaScript applications. It provides a **centralised store** to manage the entire application state, making state predictable, traceable, and easy to debug.

Redux is tiny (2kB) but has a rich ecosystem. It can be used with React or any other view library.

### Core Concepts

| Concept | Description | Example |
|---|---|---|
| **Store** | Single source of truth — holds the entire app state | Empty warehouse that stores state |
| **Action** | Plain object describing what happened `{ type, payload }` | `{ type: 'addTodo', payload: 'Buy milk' }` |
| **Reducer** | Pure function that updates state based on an action | `increment`, `decrement`, `addTodo` |
| **Slice** | Combines reducer + actions for a specific feature | `todoSlice`, `counterSlice` |
| **Dispatch** | Method to send actions to the store | `dispatch(addTodo('Buy milk'))` |
| **Selector** | Function/hook to read specific data from the store | `useSelector(state => state.todos)` |

### Redux Data Flow

```
User Action (click, submit)
        ↓
dispatch(action)
        ↓
Reducer processes action
        ↓
Store updates state
        ↓
UI re-renders via useSelector
```

Data flows **unidirectionally** — always in one direction, always traceable. This is what makes debugging and time-travel possible.

### Time Travel Debugging

Because every state change flows through a reducer in response to a dispatched action, the Redux DevTools can:

- Record every action and state snapshot
- Rewind and replay actions to reproduce bugs
- Jump to any point in state history

> If the data is wrong in the Redux store, it is always traceable which dispatched action resulted in that wrong state.

## Redux Toolkit (RTK)

Redux Toolkit is the **official, recommended** way to write Redux logic. It wraps the Redux core and eliminates the boilerplate of classic Redux:

- No need to manually write action type constants
- No need to write separate action creator functions
- Built-in **Immer** allows writing "mutating" syntax in reducers — Immer detects changes to a draft state and produces a brand new immutable state underneath
- `createSlice` generates reducers and action creators together
- `configureStore` simplifies store setup

---

## Setting Up Redux Toolkit — Step by Step

### Step 1 — Install

```bash
npm install @reduxjs/toolkit react-redux
```

### Step 2 — Create a Slice

A **slice** combines the initial state, reducer logic, and action creators for one feature. This is the core unit of Redux Toolkit.

```js
// features/todoSlice.js
import { createSlice } from "@reduxjs/toolkit";

const todoSlice = createSlice({
  name: "todos",
  initialState: [],
  reducers: {
    addTodo: (state, action) => {
      // Immer allows this "mutation" — it produces a new immutable state
      state.push({
        id: Date.now(),
        text: action.payload,
        completed: false,
      });
    },
    removeTodo: (state, action) => {
      return state.filter((todo) => todo.id !== action.payload);
    },
    toggleTodo: (state, action) => {
      const todo = state.find((todo) => todo.id === action.payload);
      if (todo) todo.completed = !todo.completed;
    },
  },
});

export const { addTodo, removeTodo, toggleTodo } = todoSlice.actions;
export default todoSlice.reducer;
```

### Step 3 — Create the Store

```js
// app/store.js
import { configureStore } from "@reduxjs/toolkit";
import todoReducer from "../features/todoSlice";

const store = configureStore({
  reducer: {
    todos: todoReducer,
  },
});

export default store;
```

As your app grows, you add more slices here. Each key in `reducer` becomes a named slice of the global state tree (e.g. `state.todos`, `state.user`, `state.cart`).

### Step 4 — Provide the Store

Wrap your application with the `Provider` component so all components have access to the store:

```jsx
// main.jsx
import { Provider } from "react-redux";
import store from "./app/store";

ReactDOM.createRoot(document.getElementById("root")).render(
  <Provider store={store}>
    <App />
  </Provider>
);
```

### Step 5 — Use in Components

**Reading state with `useSelector`:**

```jsx
// ViewTodo.jsx
import { useSelector, useDispatch } from "react-redux";
import { removeTodo } from "./features/todoSlice";

const ViewTodo = () => {
  const todos = useSelector((state) => state.todos); // reads from store
  const dispatch = useDispatch();

  return (
    <ul>
      {todos.map((todo) => (
        <li key={todo.id}>
          {todo.text}
          <button onClick={() => dispatch(removeTodo(todo.id))}>Delete</button>
        </li>
      ))}
    </ul>
  );
};
```

**Writing state with `useDispatch`:**

```jsx
// AddTodo.jsx
import { useDispatch } from "react-redux";
import { addTodo } from "./features/todoSlice";
import { useState } from "react";

const AddTodo = () => {
  const [text, setText] = useState("");
  const dispatch = useDispatch();

  const handleSubmit = (e) => {
    e.preventDefault();
    dispatch(addTodo(text)); // sends action to store
    setText("");
  };

  return (
    <form onSubmit={handleSubmit}>
      <input value={text} onChange={(e) => setText(e.target.value)} />
      <button type="submit">Add Todo</button>
    </form>
  );
};
```

### Key Hooks

| Hook | Purpose |
|---|---|
| `useSelector` | Read (select) data from the Redux store |
| `useDispatch` | Get the `dispatch` function to send actions to the store |

## Legacy Redux vs Redux Toolkit

**Legacy Redux (class Redux)** — verbose, lots of boilerplate:

```js
import { createStore } from "redux";

function counterReducer(state = { value: 0 }, action) {
  switch (action.type) {
    case "counter/incremented":
      return { value: state.value + 1 };
    case "counter/decremented":
      return { value: state.value - 1 };
    default:
      return state;
  }
}

const store = createStore(counterReducer);
store.dispatch({ type: "counter/incremented" }); // { value: 1 }
```

**Redux Toolkit** — concise, same behaviour:

```js
import { createSlice, configureStore } from "@reduxjs/toolkit";

const counterSlice = createSlice({
  name: "counter",
  initialState: { value: 0 },
  reducers: {
    incremented: (state) => { state.value += 1; },
    decremented: (state) => { state.value -= 1; },
  },
});

export const { incremented, decremented } = counterSlice.actions;

const store = configureStore({ reducer: counterSlice.reducer });
store.dispatch(incremented()); // { value: 1 }
```

## Redux Persist — Surviving Page Refreshes

Normal Redux state is lost when the page refreshes — everything resets to initial state. **Redux Persist** solves this by:

1. Persisting the Redux store to the browser's **local storage**
2. On reload, **rehydrating** (restoring) the store from local storage before the first render

This is analogous to how e-commerce platforms save your shopping cart — you can close the browser, come back hours later, and your cart is still there.

---

## When to Use What

| Tool | Best For |
|---|---|
| `useState` | Local component state |
| `useContext` + Context API | Small-to-medium global state (theme, auth, language) |
| **Redux Toolkit** | Medium-to-large apps with complex shared state across many components |
| **Redux Persist** | State that must survive page refreshes (cart, user preferences) |

> Redux is overkill for simple apps. Use Context API or `useState` instead. Once state becomes complex and shared across many unrelated components, Redux pays for itself.

## Skeleton UI

### What is Skeleton UI?

A **Skeleton UI** (or Skeleton Screen) is a placeholder loading state that mimics the layout of actual content before it loads. Instead of showing a spinner or "Loading..." text, it shows animated grey shapes that represent the structure of the page.

Modern apps — YouTube, Facebook, LinkedIn — all use skeleton screens.

### Why Use Skeleton UI?

- **Better UX** — users perceive faster load times when they see structure immediately
- **Reduced layout shift** — content does not jump around when data loads
- **Visual feedback** — users know something is loading and what shape to expect
- **Professional appearance** — matches the quality bar of major web applications

### Basic Skeleton Component with Tailwind CSS

```jsx
const Skeleton = () => {
  return (
    <div className="border rounded-xl overflow-hidden shadow-sm">
      {/* Image placeholder */}
      <div className="h-48 bg-gray-200 animate-pulse" />

      {/* Content placeholders */}
      <div className="p-4 space-y-3">
        <div className="h-5 bg-gray-200 rounded-md animate-pulse w-3/4" />
        <div className="h-4 bg-gray-200 rounded-md animate-pulse w-1/2" />
        <div className="h-6 bg-gray-200 rounded-md animate-pulse w-1/3" />
        <div className="h-10 bg-gray-200 rounded-xl animate-pulse w-full" />
      </div>
    </div>
  );
};
```

`animate-pulse` (Tailwind) adds a subtle fade in/out animation that creates the shimmer/loading effect.

### Implementation Pattern — with `useEffect` and `useState`

```jsx
import { useState, useEffect } from "react";
import Card from "./Card";
import Skeleton from "./Skeleton";

const App = () => {
  const [loading, setLoading] = useState(true);
  const [data, setData] = useState(null);

  useEffect(() => {
    fetch("https://api.example.com/products")
      .then((res) => res.json())
      .then((result) => {
        setData(result);
        setLoading(false);
      });
  }, []);

  return loading ? <Skeleton /> : <Card data={data} />;
};
```

### With `React.lazy` and `Suspense`

```jsx
import { lazy, Suspense } from "react";
import Skeleton from "./Skeleton";

const Card = lazy(() => import("./Card"));

const App = () => {
  return (
    <Suspense fallback={<Skeleton />}>
      <Card />
    </Suspense>
  );
};
```

### Skeleton Design Tips

- Match the skeleton layout exactly to the real content — same dimensions, same spacing
- Use `animate-pulse` (Tailwind) or CSS animation for the shimmer effect
- Keep consistent border radius and spacing
- Use varying widths for text lines to look natural (`w-3/4`, `w-1/2`, `w-1/3`)

## Lazy Loading in React

### What is Lazy Loading?

Lazy loading is a technique where components are loaded **only when they are needed** (on-demand), rather than loading everything upfront. This reduces the initial bundle size and improves app performance.

### Why Use Lazy Loading?

- **Faster initial load** — smaller initial JavaScript bundle downloaded on first visit
- **Better performance** — code loads only when the user navigates to that section
- **Code splitting** — Vite/Webpack automatically splits code into separate chunks
- **Reduced bandwidth** — users never download code for pages they never visit
- **Improves TTI** — Time to Interactive is reduced for large applications

### `React.lazy()`

`React.lazy()` takes a function that calls `import()` dynamically. React loads that chunk only when the component is first rendered.

```jsx
import { lazy } from "react";

// Instead of (eager — loads everything upfront):
// import HeavyComponent from "./HeavyComponent";

// Lazy (loads only when needed):
const HeavyComponent = lazy(() => import("./HeavyComponent"));
```

**Rule:** `React.lazy` only works with **default exports**.

### `Suspense` — The Fallback Boundary

`Suspense` shows a fallback UI while the lazy component's chunk is being fetched:

```jsx
import { lazy, Suspense } from "react";

const HeavyComponent = lazy(() => import("./HeavyComponent"));

const App = () => {
  return (
    <Suspense fallback={<div>Loading...</div>}>
      <HeavyComponent />
    </Suspense>
  );
};
```

### Route-Based Lazy Loading (Best Practice)

Lazy loading at the **route level** gives the biggest performance benefit — entire page bundles are deferred until the user navigates there:

```jsx
import { lazy, Suspense } from "react";
import { Routes, Route } from "react-router-dom";

const Home = lazy(() => import("./pages/Home"));
const About = lazy(() => import("./pages/About"));
const Dashboard = lazy(() => import("./pages/Dashboard"));

const App = () => {
  return (
    <Suspense fallback={<p>Loading page...</p>}>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
        <Route path="/dashboard" element={<Dashboard />} />
      </Routes>
    </Suspense>
  );
};
```

### With Skeleton UI as the Fallback

```jsx
import { lazy, Suspense } from "react";
import Skeleton from "./Skeleton";

const Card = lazy(() => import("./Card"));

const App = () => {
  return (
    <Suspense fallback={<Skeleton />}>
      <Card />
    </Suspense>
  );
};
```

### How Lazy Loading Works Behind the Scenes

1. Vite/Webpack detects the dynamic `import()` call during build
2. It splits the lazy component into a **separate chunk file**
3. On initial load, only the main bundle is downloaded
4. When the component is needed, React fetches the chunk file from the server
5. `Suspense` shows the fallback while the chunk is loading
6. Once the chunk loads, the component renders normally

### Rules for Using Lazy Loading

- `React.lazy` only works with **default exports**
- Always wrap lazy components in `<Suspense>`
- Place `<Suspense>` at a logical boundary — route level or major section level
- Multiple `<Suspense>` boundaries can be nested for granular control

## Tailwind CSS — Setup with Vite

Tailwind CSS is a utility-first CSS framework that works by scanning your HTML and JSX for class names, generating only the styles you actually use, and writing them to a static CSS file. Zero runtime, no unused CSS in production.

### Installation with Vite

**Step 1 — Create a Vite project (if needed):**

```bash
npm create vite@latest my-project
cd my-project
```

**Step 2 — Install Tailwind CSS and the Vite plugin:**

```bash
npm install tailwindcss @tailwindcss/vite
```

**Step 3 — Configure the Vite plugin in `vite.config.js`:**

```js
import { defineConfig } from "vite";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [
    tailwindcss(),
  ],
});
```

**Step 4 — Import Tailwind in your main CSS file:**

```css
/* src/index.css */
@import "tailwindcss";
```

**Step 5 — Start the dev server:**

```bash
npm run dev
```

**Step 6 — Use Tailwind classes in JSX:**

```jsx
function App() {
  return (
    <h1 className="text-3xl font-bold underline text-blue-600">
      Hello world!
    </h1>
  );
}
```

### Tailwind in React — Key Points

- Use `className` (not `class`) in JSX — this is standard React
- Classes are applied directly in JSX — no separate CSS files needed
- Tailwind scans all your `.jsx` and `.tsx` files automatically
- Only the classes you actually use are included in the final CSS bundle
- Works seamlessly with Vite, Next.js, and Create React App

## Summary

| Concept | Key Takeaway |
|---|---|
| **State Management Evolution** | Props → Context API → Flux → Redux — each solving the limitations of the last |
| **Context API** | Great for small global state; degrades with large or frequently updating data |
| **Flux** | Introduced unidirectional data flow and Single Source of Truth |
| **Redux** | Centralised store — all state in one place, all changes through reducers |
| **Redux Toolkit** | Official modern Redux — eliminates boilerplate with `createSlice` and Immer |
| **Redux Persist** | Survives page refreshes by syncing store to local storage |
| **`useSelector`** | Read data from the Redux store in any component |
| **`useDispatch`** | Send actions to the Redux store from any component |
| **Skeleton UI** | Show layout placeholders while data loads — better UX than spinners |
| **`animate-pulse`** | Tailwind class that creates the shimmer loading animation |
| **Lazy Loading** | `React.lazy()` + `Suspense` — load components on demand, not upfront |
| **Route-based splitting** | Biggest performance gain — defer entire page bundles until navigation |
| **Tailwind CSS** | Utility-first styling — classes applied directly in JSX, zero unused CSS |
