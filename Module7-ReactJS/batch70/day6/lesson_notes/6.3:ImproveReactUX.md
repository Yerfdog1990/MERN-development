# Improve React UX with Skeleton UIs

A **skeleton screen** is a UI that doesn't contain actual content but instead offers a low-fidelity page wireframe before content fully loads. It helps users understand how to navigate the page once real content appears, and is also known as a **content placeholder**, **content loader**, or **ghost element**.

Big tech products — Slack, YouTube, Facebook, Pinterest, and Medium — all use skeleton screens to boost perceived performance while data loads.

---

## How Skeleton Screens Improve UX

A skeleton screen mimics a page's layout/structure before content loads, usually with grey or off-white blocks representing where real elements will appear. Animated skeletons (shimmer or pulse effects) make load times feel shorter than they actually are.

**Blank screen vs. skeleton screen** — comparing a page with no skeleton (just a blank grey area under the header) to the same page with a skeleton (outlined post shapes, search bar, etc.):

- Both screens take the *same actual time* to load real content.
- The **blank screen feels slower** — there's nothing to anchor the user's expectation of what's coming.
- The **skeleton screen feels faster and richer** — it gives users a preview of the layout and encourages them to keep waiting rather than bouncing.

---

## Different Types of Skeleton UIs

There are two major categories:

1. **Content placeholders** — grey/off-white shapes standing in for text, avatars, and images. Used by Medium, Slack, and YouTube. These are **easy to build** since they don't need any actual content data — just the layout shape.
2. **Color/image placeholders** — used by image-heavy sites like Pinterest and Unsplash. These are **harder to build**, since they require real metadata about the underlying image (e.g., its dominant color) to render a placeholder that closely resembles the final image.

### How image/color placeholders typically work
1. Load a skeleton (gray/off-white) in place of the image.
2. Once metadata is fetched, render the image's actual dominant color (derived from backend processing done at upload time) as an interim placeholder.
3. Lazy-load the real image using the **Intersection Observer API** once it scrolls into view.

## Popular Skeleton UI Packages for React

Three well-maintained packages are commonly used, each with different tradeoffs.

### 1. `react-content-loader`

**Pros**
- SVG-based API — supports any SVG shape (rectangles, circles, custom paths) for the skeleton.
- Comes with a pulse animation out of the box.
- Ships prestyled loaders (e.g., Facebook-style, Instagram-style) and can model very complex layouts because SVG is so flexible.

**Cons**
- You must build a custom skeleton component for every UI component — time-consuming.
- SVG markup/positioning has a steeper learning curve than plain CSS/HTML.
- Browser rendering of SVG can be inconsistent, so the skeleton may look slightly different across browsers.

```jsx
import ContentLoader from "react-content-loader";

// API supports all SVG shapes — rect is the SVG shape for a rectangle
const SkeletonComponent = () => (
  <ContentLoader>
    <rect x="0" y="0" rx="5" ry="5" width="70" height="70" />
    <rect x="80" y="17" rx="4" ry="4" width="300" height="13" />
    <rect x="80" y="40" rx="3" ry="3" width="250" height="10" />
  </ContentLoader>
);
```

The `ContentLoader` wrapper also exposes props for `width`, `height`, `backgroundColor`, and animation speed.

---

### 2. `react-placeholder`

**Pros**
- Component-based API for building custom skeleton UIs from placeholder components.
- Supports a pulse animation controllable via props.

**Cons**
- Like `react-content-loader`, you must maintain a separate skeleton component per UI component — styling changes require updating both.
- Multiple component types for different needs means a less linear learning curve.

```jsx
import ReactPlaceholder from "react-placeholder";

export default function Skeleton() {
  return (
    <div>
      <ReactPlaceholder
        showLoadingAnimation={true}
        type="media"
        ready={false}
        rows={4}
      >
        Hello I am the inner content
      </ReactPlaceholder>
    </div>
  );
}
```

- `type` selects a built-in layout (`media`, `rect`, `text`, `round`, and more).
- `ready` is a boolean: `false` shows the skeleton, `true` renders the real children.

You can also supply your own custom shapes via `customPlaceholder`:

```jsx
import { TextBlock, RectShape } from "react-placeholder/lib/placeholders";
import ReactPlaceholder from "react-placeholder";

const customPlaceholder = (
  <div>
    <RectShape color="blue" style={{ width: 30, height: 30 }} />
    <TextBlock rows={7} color="yellow" />
  </div>
);

export default function Skeleton() {
  return (
    <div>
      <ReactPlaceholder
        showLoadingAnimation={true}
        type="media"
        ready={false}
        customPlaceholder={customPlaceholder}
        rows={4}
      >
        Hello I am the inner content
      </ReactPlaceholder>
    </div>
  );
}
```

`RectShape` and `TextBlock` are built-in helper components for quickly assembling custom skeleton layouts.

---

### 3. `react-loading-skeleton`

**Pros**
- The simplest API of the three — a single `Skeleton` component with customization props. Easy to learn.
- Can be used standalone or embedded directly inside any component.
- Supports animation and app-wide theming (via `SkeletonTheme`).

**Cons**
- Great for simple skeletons, but less suited to highly complex, custom skeleton interfaces (where SVG-based tools like `react-content-loader` offer more shape flexibility).

```jsx
import Skeleton, { SkeletonTheme } from "react-loading-skeleton";

const SkeletonComponent = () => (
  <SkeletonTheme color="#202020" highlightColor="#444">
    <section>
      <Skeleton count={3} />
      <Skeleton width={100} />
      <Skeleton circle={true} height={50} width={50} />
    </section>
  </SkeletonTheme>
);
```

All three libraries handle simple use cases well — the right choice depends on how complex your skeleton layouts need to be and how much control over shape/animation you want.

## Building a Custom Skeleton UI with Framer Motion

Beyond ready-made packages, you can build a fully custom skeleton UI with plain CSS plus **Framer Motion** for animation. This example replicates a YouTube-style video grid.

### Designing the skeleton layout

The real (loaded) app renders sections of videos, each pulled from mock data:

```jsx
// App.js
import React from "react";
import CardList from "./components/CardList";
import youtubeData from "./data";
import "./App.css";

const App = () => {
  return (
    <div className="App">
      {youtubeData.map((list, index) => (
        <section key={index}>
          <h2 className="section-title">{list.section}</h2>
          <CardList list={list} />
          <hr />
        </section>
      ))}
    </div>
  );
};

export default App;
```

Mock data (`data.js`) looks like:

```js
// data.js
const youtubeData = [
  {
    section: "JavaScript Tutorials by freeCodeCamp",
    channel: "freeCodeCamp.org",
    items: [
      {
        id: "PkZNo7MFNFg",
        image: "https://img.youtube.com/vi/PkZNo7MFNFg/maxresdefault.jpg",
        title: "Learn JavaScript - Full Course for Beginners",
        views: "1.9M views",
        published: "9 months ago",
      },
      // ...more items
    ],
  },
  // ...more sections
];

export default youtubeData;
```

To simulate a real network request, delay setting the data with `setTimeout`:

```jsx
// App.js
import React, { useState, useEffect } from "react";
import CardList from "./components/CardList";
import youtubeData from "./data";
import "./App.css";

const App = () => {
  const [videos, setVideos] = useState([]);

  useEffect(() => {
    const timer = setTimeout(() => {
      setVideos(youtubeData);
    }, 5000);
    return () => clearTimeout(timer); // cancel on unmount
  }, []);

  return (
    <div className="App">
      {videos.map((list, index) => {
        /* ... */
      })}
    </div>
  );
};
```

### The `CardList` and `Card` components

```jsx
// CardList.js
import Card from "./Card";

const CardList = ({ list }) => {
  return (
    <ul className="list">
      {list.items.map((item, index) => (
        <Card key={index} item={item} channel={list.channel} />
      ))}
    </ul>
  );
};

export default CardList;
```

```jsx
// Card.js
const Card = ({ item, channel }) => {
  return (
    <li className="card">
      <a
        href={`https://www.youtube.com/watch?v=${item.id}`}
        target="_blank"
        rel="noopener noreferrer"
        className="card-link"
      >
        <img src={item.image} alt={item.title} className="card-image" />
        <h4 className="card-title">{item.title}</h4>
        <p className="card-channel">
          <i>{channel}</i>
        </p>
        <div className="card-metrics">
          {item.views} &bull; {item.published}
        </div>
      </a>
    </li>
  );
};

export default Card;
```

Before `videos` populates, the app renders a blank screen — this is the gap the skeleton UI fills.

### Creating the base `Skeleton` component

```jsx
// Skeleton.js
import "../skeleton.css";

const Skeleton = ({ type }) => {
  const classes = `skeleton ${type}`;
  return <div className={classes}></div>;
};

export default Skeleton;
```

`type` (e.g., `title`, `text`, `avatar`, `thumbnail`, `half-text`) determines which CSS class shapes the placeholder.

### Assembling the YouTube skeleton screen with Framer Motion

```jsx
// youtube.js
import { motion } from "framer-motion";
import Skeleton from "../components/Skeleton";
import Shimmer from "../components/Shimmer";

const Youtube = () => {
  return (
    <motion.section
      initial={{ opacity: 0 }}
      animate={{ opacity: 1 }}
      className="skeleton-wrapper"
    >
      <h2 className="section-title">
        <Skeleton type="title" />
      </h2>
      <ul className="list">
        {Array(9)
          .fill()
          .map((item, index) => (
            <li className="card" key={index}>
              <Skeleton type="thumbnail" />
              <h4 className="card-title">
                <Skeleton type="title" />
              </h4>
              <p className="card-channel">
                <Skeleton type="text" />
              </p>
              <div className="card-metrics">
                <Skeleton type="half-text" />
              </div>
            </li>
          ))}
      </ul>
      <Shimmer />
    </motion.section>
  );
};

export default Youtube;
```

- `motion.section` is a Framer Motion-enhanced `<section>`.
- `initial={{ opacity: 0 }}` and `animate={{ opacity: 1 }}` create a fade-in effect for the whole skeleton block as it mounts.
- `Array(9).fill().map(...)` generates 9 placeholder video cards to match a typical grid size.

### Creating the shimmer animation

```jsx
// Shimmer.js
import { motion } from "framer-motion";

const Shimmer = () => {
  return (
    <motion.div
      initial={{ x: -600 }}
      animate={{ x: 1000 }}
      transition={{
        duration: 1.5,
        repeat: Infinity,
        repeatDelay: 1,
      }}
      className="shimmer"
    ></motion.div>
  );
};

export default Shimmer;
```

- The `.shimmer` CSS class defines a semi-transparent white strip absolutely positioned at the left of `.skeleton-wrapper`.
- `initial={{ x: -600 }}` starts it off-screen to the left; `animate={{ x: 1000 }}` slides it far to the right.
- `transition` settings (`duration: 1.5`, `repeat: Infinity`, `repeatDelay: 1`) make it sweep across repeatedly with a short pause between passes — producing the classic "shimmer" loading effect.

### Wiring the skeleton into the app with `isLoading` state

```jsx
// App.js
import { useEffect, useState } from "react";
import CardList from "./components/CardList";
import YoutubeSkeleton from "./skeleton-screens/Youtube";
import youtubeData from "./data";

export default function App() {
  const [videos, setVideos] = useState([]);
  const [isLoading, setIsLoading] = useState(true);

  useEffect(() => {
    setIsLoading(true);
    const timer = setTimeout(() => {
      setVideos(youtubeData);
      setIsLoading(false);
    }, 5000);
    return () => clearTimeout(timer);
  }, []);

  return (
    <div className="App">
      {isLoading && <YoutubeSkeleton />}
      {!isLoading &&
        videos.map((list, index) => (
          <section key={index}>
            <h2 className="section-title">{list.section}</h2>
            <CardList list={list} />
            <hr />
          </section>
        ))}
    </div>
  );
}
```

At this point the skeleton correctly shows while loading — but swapping it out for real content causes an abrupt flicker as it unmounts.

### Smoothing the transition with `AnimatePresence`

Wrapping content in Framer Motion's `AnimatePresence` enables an `exit` animation, so the skeleton fades out gracefully instead of disappearing instantly:

```jsx
// App.js
import { useEffect, useState } from "react";
import { AnimatePresence, motion } from "framer-motion";
import CardList from "./components/CardList";
import YoutubeSkeleton from "./skeleton-screens/Youtube";
import youtubeData from "./data";

export default function App() {
  const [videos, setVideos] = useState([]);
  const [isLoading, setIsLoading] = useState(true);

  useEffect(() => {
    setIsLoading(true);
    const timer = setTimeout(() => {
      setVideos(youtubeData);
      setIsLoading(false);
    }, 5000);
    return () => clearTimeout(timer);
  }, []);

  return (
    <div className="App">
      <AnimatePresence>
        {isLoading && <YoutubeSkeleton exit={{ opacity: 0 }} />}
        {!isLoading && (
          <motion.div initial={{ opacity: 0 }} animate={{ opacity: 1 }}>
            {videos.map((list, index) => (
              <section key={index}>
                <h2 className="section-title">{list.section}</h2>
                <CardList list={list} />
                <hr />
              </section>
            ))}
          </motion.div>
        )}
      </AnimatePresence>
    </div>
  );
}
```

Since `YoutubeSkeleton` doesn't natively accept an `exit` prop as a component, the `Youtube` component must forward incoming props (like `exit`) onto its own root `motion.section`:

```jsx
// youtube.js
import { motion } from "framer-motion";
import Skeleton from "../components/Skeleton";
import Shimmer from "../components/Shimmer";

const Youtube = ({ ...props }) => {
  return (
    <motion.section
      initial={{ opacity: 0 }}
      animate={{ opacity: 1 }}
      className="skeleton-wrapper"
      {...props}
    >
      {/* ...skeleton markup... */}
    </motion.section>
  );
};

export default Youtube;
```

Now `exit={{ opacity: 0 }}` reaches the actual `motion.section`, and `AnimatePresence` animates the fade-out before removing the skeleton from the DOM — eliminating the flicker and producing a smooth crossfade from skeleton to real content.

## Comparing the Approaches

| Approach | Effort | Flexibility | Best for |
|---|---|---|---|
| `react-content-loader` | Medium–High (SVG per component) | Very high (any SVG shape) | Complex, highly custom skeleton illustrations |
| `react-placeholder` | Medium | High (composable shape components) | Component-driven apps wanting reusable placeholder pieces |
| `react-loading-skeleton` | Low | Medium | Quick, simple skeletons with minimal setup |
| Custom CSS + Framer Motion | Medium–High (build from scratch) | Full control | Fully bespoke skeleton UIs with custom shimmer/exit animations, no extra placeholder-shape dependency |

---

## Conclusion

Skeleton screens meaningfully improve perceived UX by:
- Replacing jarring blank screens with a preview of the page's structure
- Making load times *feel* shorter through shimmer/pulse animation
- Giving users confidence to keep waiting instead of bouncing

You don't need a library to get these benefits — a handful of styled `<div>` elements (rectangles and circles matching your real layout) combined with a CSS or Framer Motion animation is enough to build an effective, fully custom skeleton UI. For simpler needs, `react-loading-skeleton` offers the fastest path to a polished result; for highly custom illustrations, `react-content-loader`'s SVG-based API offers the most flexibility.
