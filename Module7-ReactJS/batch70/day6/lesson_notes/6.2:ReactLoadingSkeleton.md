# React Loading Skeleton

**React Loading Skeleton** is a library for rendering placeholder UI ("skeleton screens") that mimic real content while data is being fetched. Loading skeletons improve perceived performance and visual stability compared to spinners or loading text — they prevent layout shift and give users a sense of the shape of the content that's about to appear.

This note covers installation, basic usage, prop-based customization, theming, real-world patterns (post pages, card lists, partial image loading), gradient/animation customization, dynamic dark/light theming, and a dependency-free Tailwind alternative.

---

## Spinner vs. Skeleton

- **Loading spinner / loading text**: shows a generic "please wait" indicator with no relationship to the content's final shape. Feels abrupt when content pops in.
- **Loading skeleton**: shows gray placeholder shapes matching the eventual layout (avatar circle, title bar, text lines), making the transition from loading → loaded feel smooth and expected.

---

## Installation

```bash
npm install react-loading-skeleton
```

## Basic Usage

Import `Skeleton` and its stylesheet, then conditionally render it in place of real content while `isLoading` is `true`:

```jsx
import Skeleton from 'react-loading-skeleton';
import 'react-loading-skeleton/dist/skeleton.css';

export default function Post() {
  const { data: post, error, isLoading } = useQuery({ /* your query here */ });

  return (
    <article>
      <h1 className="text-xl md:text-2xl font-medium mb-6">
        {isLoading ? <Skeleton /> : post.title}
      </h1>
      {/* Render other content here */}
    </article>
  );
}
```

Because `<Skeleton />` is rendered **directly in place of the real element**, it automatically inherits surrounding font size and spacing — no need to manually match dimensions in simple cases.

## Customizing Skeleton with Props

`Skeleton` accepts props to control shape, size, color, and animation speed:

```jsx
<div className="flex items-center gap-4 p-4">
  {isLoading ? (
    <Skeleton circle width={48} height={48} />
  ) : (
    <img
      src={`https://picsum.photos/seed/${user.id}/200`}
      alt={`${user?.name}'s profile`}
      className="w-12 h-12 rounded-full object-cover"
    />
  )}
  <div className="flex-1">
    <h3 className="font-semibold text-gray-800">
      {isLoading ? <Skeleton width="50%" /> : user.name}
    </h3>
    <p className="text-gray-600 text-sm">
      {isLoading ? (
        <Skeleton
          width={500}
          baseColor="#ffcccb"
          highlightColor="#add8e6"
          duration={2}
        />
      ) : (
        user.email
      )}
    </p>
  </div>
</div>
```

### Key props

| Prop | Purpose |
|---|---|
| `width` / `height` | Size in pixels or percentage |
| `circle` | Renders a circular placeholder (ideal for avatars) |
| `duration` | Controls animation speed (seconds) |
| `baseColor` | Background color of the skeleton |
| `highlightColor` | Color of the moving highlight/shimmer |
| `count` | Number of repeated lines to render |

## Theming with `SkeletonTheme`

Manually repeating `baseColor`/`highlightColor`/`duration` on every `<Skeleton>` doesn't scale. `SkeletonTheme` lets you define these once at the top of the app, and every `<Skeleton>` in the tree inherits them:

```jsx
import { SkeletonTheme } from 'react-loading-skeleton';
import 'react-loading-skeleton/dist/skeleton.css';

createRoot(document.getElementById('root')!).render(
  <SkeletonTheme baseColor="#d5d4d3" highlightColor="#f2f0ef" duration={2}>
    <RouterProvider router={router} />
  </SkeletonTheme>
);
```

The stylesheet import only needs to happen once, at this top-level file.

## Real-World Example 1: A Post Page

**Before** (spinner-based):

```jsx
<div className="max-w-4xl mx-auto">
  <GoBack />
  {isLoading && <div className="text-xl font-medium">A moment please...</div>}
  {error && <div className="text-red-700">{`Error fetching post data: ${error}`}</div>}
  <article>
    <h1 className="text-xl md:text-2xl font-medium mb-6">{post?.title}</h1>
    <p>{post?.body}</p>
  </article>
</div>
```

**After** (skeleton-based):

```jsx
import Skeleton from 'react-loading-skeleton';

export default function Post() {
  // ...
  return (
    <div className="max-w-4xl mx-auto">
      <GoBack />
      {error && <div className="text-red-700">{`Error fetching post data: ${error}`}</div>}
      <article>
        <h1 className="text-xl md:text-2xl font-medium mb-6">
          {isLoading ? <Skeleton /> : post.title}
        </h1>
        <p>{isLoading ? <Skeleton count={2} /> : post.body}</p>
      </article>
    </div>
  );
}
```

The `count` prop on the paragraph skeleton renders **multiple lines** (2 here), mimicking a block of body text.

## Real-World Example 2: A Post/Card List

**Before** (spinner-based list):

```jsx
<ul className="grid grid-cols-[repeat(auto-fit,minmax(250px,1fr))] gap-2 px-2">
  {isLoading && (
    <div className="min-h-[300px] justify-items-center content-center">
      <RiLoader2Fill className="size-6 animate-spin" />
    </div>
  )}
  {users?.map((user) => (
    <UserCard
      user={{ ...user, imageUrl: `https://picsum.photos/seed/${user.id}/200` }}
      key={user.id}
    />
  ))}
</ul>
```

**Dedicated `CardSkeleton` component:**

```jsx
import Skeleton from 'react-loading-skeleton';

const CardSkeleton = ({ cardItems }: { cardItems: number }) => {
  const skeletonItems = Array(cardItems).fill(0);

  return skeletonItems.map((_, index) => (
    <li
      className="border-b border-gray-100 text-sm sm:text-base flex gap-4 items-center p-4"
      key={index}
    >
      <Skeleton circle width={48} height={48} />
      <Skeleton count={1.7} containerClassName="flex-1" />
    </li>
  ));
};

export default CardSkeleton;
```

- `cardItems` controls how many placeholder cards render (e.g., matching the typical page size).
- `count={1.7}` produces **one full-width line plus a shorter partial line beneath it**, mimicking a title + subtitle look, using a fraction instead of a whole number.
- `containerClassName="flex-1"` lets the skeleton grow inside a flex layout.

**Alternative without `containerClassName`:**

```jsx
<div className="flex-1">
  <Skeleton count={1.7} />
</div>
```

**Using `CardSkeleton` in the list:**

```jsx
import CardSkeleton from './CardSkeleton';

const CardList = () => {
  // ...
  return (
    <ul className="grid grid-cols-[repeat(auto-fit,minmax(250px,1fr))] gap-2 px-2">
      {isLoading && <CardSkeleton cardItems={12} />}
      {users?.map((user) => (
        // ...
      ))}
    </ul>
  );
};

export default CardList;
```

This replaces the generic spinner with 12 skeleton cards shaped like the real `UserCard` components.

## Skeletons for Partial Data Loading (Images)

Text data (like a user's name) often arrives before slower resources like images. Track each resource's own loading state so text can appear immediately while the image placeholder persists until it finishes loading:

```jsx
export const UserCard = ({ user }: UserCardProps) => {
  const [isImageLoaded, setIsImageLoaded] = useState(false);

  const handleImageLoad = () => {
    setIsImageLoaded(true);
  };

  return (
    <div className="w-12 h-12 relative">
      {!isImageLoaded && <Skeleton circle width={48} height={48} />}
      <img
        src={user.imageUrl}
        alt={`${user.name}'s profile`}
        className={`w-12 h-12 rounded-full object-cover ${
          isImageLoaded ? 'opacity-100' : 'opacity-0'
        }`}
        onLoad={handleImageLoad}
      />
    </div>
  );
};
```

The `<img>` is rendered (with `opacity-0`) at the same time as the skeleton, so the browser starts loading it immediately; once `onLoad` fires, the skeleton disappears and the image fades in.

## Customizing the Gradient Effect

The `customHighlightBackground` prop lets you replace the default highlight sweep with a fully custom CSS gradient — applied per-`Skeleton` or globally via `SkeletonTheme`:

```jsx
<SkeletonTheme
  baseColor="#d5d4d3"
  highlightColor="#f2f0ef"
  duration={2}
  customHighlightBackground="linear-gradient(
    90deg,
    var(--base-color) 30%,
    #ffcccb 45%,
    var(--highlight-color) 60%,
    #add8e6 80%,
    var(--base-color) 100%
  )"
>
  <RouterProvider router={router} />
</SkeletonTheme>
```

`var(--base-color)` and `var(--highlight-color)` reference the theme's own colors, so the custom gradient can blend with additional accent colors while still respecting the base theme.

## Dynamic Theme Customization (Dark/Light Mode)

Hardcoding `baseColor`/`highlightColor` breaks dark/light mode switching. Instead, define color sets per theme and pick the active one dynamically:

```jsx
const isDarkTheme = true;

const darkThemeStyles = {
  baseColor: '#374151',
  highlightColor: '#151c2b',
};

const lightThemeStyles = {
  baseColor: '#ebebeb',
  highlightColor: '#f5f5f5',
};

createRoot(document.getElementById('root')!).render(
  <SkeletonTheme
    baseColor={isDarkTheme ? darkThemeStyles.baseColor : lightThemeStyles.baseColor}
    highlightColor={
      isDarkTheme ? darkThemeStyles.highlightColor : lightThemeStyles.highlightColor
    }
    duration={2}
  >
    <RouterProvider router={router} />
  </SkeletonTheme>
);
```

Swap `isDarkTheme` for your actual theme state (e.g., from context or a `useTheme` hook) so skeletons always match the active theme.

## Building a Skeleton Loader Without External Dependencies

If you'd rather avoid adding a dependency, Tailwind CSS alone can produce the same effect.

### A reusable `CustomSkeleton` primitive

```jsx
import { cn } from '../lib/utils';

export function CustomSkeleton({
  className,
  ...props
}: React.HTMLAttributes<HTMLDivElement>) {
  return (
    <div
      className={cn('animate-pulse rounded-md bg-[#d5d4d3]', className)}
      {...props}
    />
  );
}
```

`animate-pulse` provides the pulsing fade animation; `className` lets each usage define its own width/height/shape.

### Rebuilding `CardSkeleton` with the custom primitive

```jsx
import { CustomSkeleton } from './CustomSkeleton';

const CardSkeleton = ({ cardItems }: { cardItems: number }) => {
  const skeletonItems = Array(cardItems).fill(0);

  return skeletonItems.map((_, index) => (
    <li
      className="border-b border-gray-100 text-sm sm:text-base flex gap-4 items-center p-4"
      key={index}
    >
      <div className="flex items-center space-x-4">
        <CustomSkeleton className="h-12 w-12 rounded-full" />
        <div className="space-y-2">
          <CustomSkeleton className="h-4 w-48" />
          <CustomSkeleton className="h-4 w-28" />
        </div>
      </div>
    </li>
  ));
};

export default CardSkeleton;
```

Shape and size are fully controlled through Tailwind utility classes (`h-12`, `w-48`, `rounded-full`, etc.) — no library-specific props to learn.

### Custom shimmer animation (instead of pulse)

Extend the Tailwind config with a `shimmer` keyframe/animation:

```js
// tailwind.config.js
module.exports = {
  theme: {
    extend: {
      keyframes: {
        shimmer: {
          '0%': { backgroundPosition: '-200% 0' },
          '100%': { backgroundPosition: '200% 0' },
        },
      },
      animation: {
        shimmer: 'shimmer 2s linear infinite',
      },
    },
  },
};
```

Then apply it via a pseudo-element gradient sweep instead of the default pulse:

```jsx
import { cn } from '../lib/utils';

export function CustomSkeleton({
  className,
  ...props
}: React.HTMLAttributes<HTMLDivElement>) {
  return (
    <div
      className={cn(
        'relative overflow-hidden rounded-md',
        'before:absolute before:inset-0 before:animate-shimmer',
        'before:bg-gradient-to-r before:from-[#d5d4d3] before:via-[#f2f0ef] before:to-[#d5d4d3] before:bg-[length:200%_100%]',
        className
      )}
      style={{ backgroundColor: '#d5d4d3' }}
      {...props}
    />
  );
}
```

This produces a smooth, sliding shimmer gradient across the skeleton rather than a fading pulse — a more "polished" loading effect used by many production apps.

## Reference: Prop / Feature Cheat Sheet

| Feature | API |
|---|---|
| Basic placeholder | `<Skeleton />` |
| Circular avatar placeholder | `<Skeleton circle width={48} height={48} />` |
| Multiple lines | `<Skeleton count={2} />` |
| Partial extra line (title + short subtitle) | `<Skeleton count={1.7} />` |
| Grow inside flex layout | `<Skeleton containerClassName="flex-1" />` |
| Per-instance colors/speed | `<Skeleton baseColor="#..." highlightColor="#..." duration={2} />` |
| App-wide theme | `<SkeletonTheme baseColor="#..." highlightColor="#..." duration={2}>{children}</SkeletonTheme>` |
| Custom gradient highlight | `customHighlightBackground` prop (on `Skeleton` or `SkeletonTheme`) |
| Dark/light adaptive theme | Pass computed `baseColor`/`highlightColor` into `SkeletonTheme` based on theme state |

---

## Conclusion

Loading skeletons meaningfully improve UX during asynchronous data fetching by:
- **Reducing perceived wait time** compared to spinners or blank screens
- **Preventing layout shift**, since the skeleton occupies the same space as the eventual content
- **Providing visual continuity**, especially when paired with partial-loading patterns (text appears immediately, images fade in when ready)

`react-loading-skeleton` makes this fast to implement with sensible defaults, prop-based customization, and app-wide theming via `SkeletonTheme`. For projects that want to avoid the extra dependency, the same visual result (including a custom shimmer animation) can be achieved directly with Tailwind CSS utility classes and `animate-pulse`/custom keyframes.
