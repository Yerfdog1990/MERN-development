# React State

---

## What is State?

**State** is data that changes over time inside a component. It controls what the component displays and how it behaves.

Examples of state:
- A counter value that increases when a button is clicked
- Whether a dropdown menu is open or closed
- The current value typed into a search input
- Whether a user is logged in or not

When state changes, React **automatically re-renders** the component to reflect the updated data on screen.

---

## State vs Props

| | Props | State |
|---|---|---|
| Where it comes from | Passed in from a parent component | Defined and managed inside the component |
| Who can change it | Only the parent (read-only in child) | Only the component itself |
| When it changes | When the parent re-renders | When the component's event handler calls `setState` |
| Purpose | Configure a component from outside | Track internal, changing data |

---

## The `useState` Hook

React provides the `useState` hook to create and manage state in functional components.

### Step 1 — Import `useState`

```js
import { useState } from 'react';
```

### Step 2 — Define a piece of state

```jsx
const App = () => {
  const [counter, setCounter] = useState(0);
  // ...
};
```

`useState(0)` returns an **array of two elements**:

| Element | What it is | Convention |
|---|---|---|
| `counter` | The current state value | The state name |
| `setCounter` | A function to update the state | `set` + state name |

The argument passed to `useState()` (here `0`) is the **initial value** — what the state starts as when the component first renders.

### Step 3 — Update state using the setter function

```js
setCounter(newValue);
```

---

## The Golden Rule — Never Modify State Directly

React watches for state changes through the setter function. If you change state directly, React doesn't know it changed and **won't re-render the component**:

```jsx
// ❌ Wrong — directly modifying state
counter = counter + 1; // React has no idea this changed

// ✅ Correct — using the setter function
setCounter(counter + 1); // React knows, triggers re-render
```

Always use the setter function returned by `useState` to update state. Directly mutating state causes bugs that are difficult to track down.

---

## Initial Values for Different State Types

The initial value passed to `useState` can be any JavaScript value:

```js
// Number
const [count, setCount] = useState(0);

// String
const [name, setName] = useState('');

// Boolean
const [isOpen, setIsOpen] = useState(false);

// Array
const [items, setItems] = useState([]);

// Object
const [user, setUser] = useState({});
```

---

## How Re-Rendering Works

When you call the setter function, React:

1. Updates the state value
2. Re-executes the component function from the top
3. Compares the new output with the previous Virtual DOM
4. Updates only the changed parts of the real DOM

```
State changes (setCounter called)
         ↓
React re-runs the component function
         ↓
New JSX is returned
         ↓
React diffs new vs previous Virtual DOM
         ↓
Only changed parts of the real DOM are updated
```

This happens very fast — typically in milliseconds.

## Building a Counter App

A counter with increment and decrement buttons is the classic state example.

### `index.js`

```jsx
import ReactDOM from 'react-dom/client';
import App from './App.js';

const el = document.querySelector('#root');
const root = ReactDOM.createRoot(el);
root.render(<App />);
```

### `App.js` — with named handler functions

```jsx
import { useState } from 'react';

const App = () => {
  // Define state — counter starts at 0
  const [counter, setCounter] = useState(0);

  // Event handler functions
  const increment = () => setCounter(counter + 1);
  const decrement = () => setCounter(counter - 1);

  return (
    <>
      <header>
        <h1>Counter</h1>
      </header>
      <main>
        <p>{counter}</p>
        <div>
          <button type="button" onClick={decrement}>-</button>
          <button type="button" onClick={increment}>+</button>
        </div>
      </main>
    </>
  );
};

export default App;
```

### `App.js` — concise version with inline arrow functions

```jsx
import { useState } from 'react';

const App = () => {
  const [counter, setCounter] = useState(0);

  return (
    <>
      <header>
        <h1>Counter</h1>
      </header>
      <main>
        <p>{counter}</p>
        <div>
          <button type="button" onClick={() => setCounter(counter - 1)}>-</button>
          <button type="button" onClick={() => setCounter(counter + 1)}>+</button>
        </div>
      </main>
    </>
  );
};

export default App;
```

Both versions work identically. The inline version is more concise; the named function version is easier to read when the logic grows.

### How it works step by step:

1. `useState(0)` creates a `counter` state with an initial value of `0`
2. `{counter}` in the JSX displays the current value
3. Clicking `-` calls `setCounter(counter - 1)` → state updates → React re-renders → the new value shows on screen
4. Clicking `+` calls `setCounter(counter + 1)` → same process

## Multiple Pieces of State

A component can have as many `useState` calls as it needs — each one is independent:

```jsx
const App = () => {
  const [count,    setCount]    = useState(0);
  const [name,     setName]     = useState('');
  const [isActive, setIsActive] = useState(false);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>

      <input
        value={name}
        onChange={(e) => setName(e.target.value)}
        placeholder="Enter name"
      />
      <p>Hello, {name}</p>

      <button onClick={() => setIsActive(!isActive)}>
        {isActive ? 'Active' : 'Inactive'}
      </button>
    </div>
  );
};
```

Changing any one piece of state only causes that component to re-render — it doesn't affect other components or other state values.

## State with Objects

When state is an object, you must spread the existing object when updating — otherwise you'll overwrite the whole object:

```jsx
const [user, setUser] = useState({ name: 'John', age: 30 });

// ❌ Wrong — overwrites the entire object, losing 'age'
setUser({ name: 'Jane' });

// ✅ Correct — spread existing values, override only what changed
setUser({ ...user, name: 'Jane' });
// Result: { name: 'Jane', age: 30 }
```

---

## State with Arrays

When state is an array, never mutate it directly. Use methods that return a new array:

```jsx
const [items, setItems] = useState(['Apple', 'Banana']);

// ✅ Adding an item
setItems([...items, 'Cherry']);

// ✅ Removing an item
setItems(items.filter((item) => item !== 'Banana'));

// ✅ Updating an item
setItems(items.map((item) => item === 'Apple' ? 'Apricot' : item));

// ❌ Wrong — mutating the array directly (push, splice, etc.)
items.push('Cherry'); // React won't re-render
```

## Summary

- **State** is data that changes over time and controls a component's output and behaviour.
- Use `useState()` to create a state variable and its setter function: `const [value, setValue] = useState(initialValue)`.
- The argument to `useState()` is the **initial value** — can be a number, string, boolean, array, or object.
- **Always use the setter function** to update state — never modify state directly. Direct mutation won't trigger a re-render.
- When state changes, React **re-renders the component** automatically — you don't manually update the DOM.
- A component can have **multiple independent state values** — each `useState` call manages its own piece.
- When state is an **object or array**, always create a new value (using spread or `.filter()`/`.map()`) rather than mutating in place.
