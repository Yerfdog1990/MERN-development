# React JSX Key Prop

---

## Rendering a List in React

In React, you often need to display a list of elements from an array of data. The standard way to do this is with the JavaScript **`map()` method** — it transforms an array of data into an array of JSX elements.

```jsx
const App = () => {
  const names = ['Anthony Pham', 'Alex Johnson', 'Bob Climo'];

  const renderedNames = names.map((name) => {
    return <li>{name}</li>;
  });

  return <ul>{renderedNames}</ul>;
};
```

Output:

```
• Anthony Pham
• Alex Johnson
• Bob Climo
```

This renders correctly in the browser, but opens the console and you'll see this warning:

```
Warning: Each child in a list should have a unique "key" prop.
```

---

## What is the `key` Prop?

The `key` prop is a **special prop** that React uses to uniquely identify each element in a list. It helps React track which items have changed, been added, or been removed — so it can update the DOM efficiently without re-rendering the entire list.

### Why React needs keys

When a list changes, the least efficient approach is to delete the whole list and re-render it from scratch. React avoids this by **comparing the previous list with the new one** and only updating what actually changed. To do this comparison correctly, React needs a stable, unique identity for each item — that's what the `key` prop provides.

```
Previous list          New list
─────────────          ─────────
key=1  Anthony   →     key=1  Anthony    (no change)
key=2  Alex      →     key=2  Alex       (no change)
key=3  Bob       →     key=4  Carol      (key=3 removed, key=4 added)
```

Without keys, React can't reliably tell which item changed and may re-render the whole list unnecessarily.

---

## Rules for Keys

- Keys must be **unique within the list** — no two siblings can share the same key
- Keys must be **stable** — they should not change between renders
- Keys are **not passed as props** to the component — the child component cannot access `props.key`
- Keys only need to be unique **among siblings**, not globally across the entire app

---

## Where Keys Come From

| Source | Approach |
|---|---|
| **Database records** | Use the record's primary key (e.g. `id`) — already unique by design |
| **Locally generated data** | Use `crypto.randomUUID()` or a library like `uuid` to generate unique IDs |

---

## Adding Keys — Basic Example

Add a `key` prop to each element returned inside `map()`:

```jsx
const App = () => {
  const names = ['Anthony Pham', 'Alex Johnson', 'Bob Climo'];

  const renderedNames = names.map((name) => {
    return <li key={crypto.randomUUID()}>{name}</li>;
  });

  return <ul>{renderedNames}</ul>;
};
```

The `crypto.randomUUID()` method generates a unique UUID string each time it is called. The warning disappears.

---

## Using Data IDs as Keys (Best Practice)

When your data comes from an API or database, use the existing unique `id` field as the key — this is more reliable than generating random IDs on every render:

```jsx
const App = () => {
  const users = [
    { id: 1, name: 'Anthony Pham' },
    { id: 2, name: 'Alex Johnson' },
    { id: 3, name: 'Bob Climo' },
  ];

  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
};
```

Using `user.id` as the key is preferred because the same item always gets the same key — even if the list is re-ordered or re-fetched.

---

## Why Not Use the Array Index as a Key?

It's tempting to use the array index as a key since it's always available:

```jsx
// ⚠️ Avoid this
names.map((name, index) => <li key={index}>{name}</li>);
```

This can cause bugs when the list is reordered, filtered, or items are added/removed. The index shifts and React loses track of which element is which, leading to incorrect updates and UI glitches.

**Use the array index as a key only when:**
- The list is static and will never change
- The list is never reordered or filtered

## Refactoring the Book App — Before and After

The key prop pattern becomes more useful when your data is stored as an array of objects.

### Before — manually repeating each component

```jsx
const App = () => {
  return (
    <main>
      <h1>Favourite Books</h1>
      <div>
        <Book title="Mastering React"  author="Anthony Pham"  cover={MasteringReact}  />
        <Book title="Practical React"  author="Alex Johnson"  cover={PracticalReact}  />
        <Book title="React in Action"  author="Bob Climo"     cover={ReactInAction}   />
      </div>
    </main>
  );
};
```

### After — data-driven with `map()` and `key`

```jsx
import Book from './Book';
import MasteringReact from './mastering-react.svg';
import PracticalReact from './practical-react.svg';
import ReactInAction from './react-in-action.svg';
import './style.css';

const App = () => {
  // Step 1 — store data in an array of objects
  const books = [
    { title: 'Mastering React',  author: 'Anthony Pham',  cover: MasteringReact  },
    { title: 'Practical React',  author: 'Alex Johnson',  cover: PracticalReact  },
    { title: 'React in Action',  author: 'Bob Climo',     cover: ReactInAction   },
  ];

  // Step 2 — transform the array into an array of components
  const renderedBooks = books.map((book) => {
    return (
      <Book
        key={crypto.randomUUID()}
        title={book.title}
        author={book.author}
        cover={book.cover}
      />
    );
  });

  // Step 3 — render the list
  return (
    <main>
      <h1>Favourite Books</h1>
      <div className="book-list">{renderedBooks}</div>
    </main>
  );
};

export default App;
```

**What changed:**

| Before | After |
|---|---|
| Each `<Book />` written manually | Data in an array, rendered with `map()` |
| Adding a book = adding a new JSX line | Adding a book = adding one object to the array |
| Hard to maintain at scale | Easy to scale — data and rendering are separated |

## The Key Prop — Three Patterns

### Pattern 1 — Inline `map()` with key

```jsx
return (
  <ul>
    {names.map((name) => (
      <li key={crypto.randomUUID()}>{name}</li>
    ))}
  </ul>
);
```

### Pattern 2 — `map()` result stored in a variable first

```jsx
const renderedNames = names.map((name) => (
  <li key={crypto.randomUUID()}>{name}</li>
));

return <ul>{renderedNames}</ul>;
```

### Pattern 3 — Using data `id` as key (preferred when available)

```jsx
const renderedUsers = users.map((user) => (
  <li key={user.id}>{user.name}</li>
));
```

All three patterns are valid — choose based on readability.

---

## Common Mistakes

**Forgetting the key entirely:**

```jsx
// ❌ Warning in console
names.map((name) => <li>{name}</li>);

// ✅ No warning
names.map((name) => <li key={crypto.randomUUID()}>{name}</li>);
```

**Putting the key on the wrong element** — the key goes on the outermost element returned from `map()`, not on a child inside it:

```jsx
// ❌ Wrong — key is on the inner element
names.map((name) => (
  <div>
    <li key={crypto.randomUUID()}>{name}</li>
  </div>
));

// ✅ Correct — key is on the outermost returned element
names.map((name) => (
  <div key={crypto.randomUUID()}>
    <li>{name}</li>
  </div>
));
```

**Generating the key inside the component** — keys must be assigned at the point where `map()` is called, not inside the child component itself.

---

## Summary

- Use the **`map()` method** to transform an array of data into an array of JSX elements or components.
- Always add a **`key` prop** to each element returned from `map()` — React uses it to identify which items changed, were added, or removed.
- Keys must be **unique within the list** and **stable between renders**.
- The **best source for keys** is an existing unique `id` from your data (e.g. a database primary key).
- Use **`crypto.randomUUID()`** to generate unique keys when no id is available.
- **Avoid using the array index** as a key unless the list is completely static.
- The key prop goes on the **outermost element** returned inside `map()`.
- Storing list data as an **array of objects** and using `map()` makes components much easier to scale and maintain.
