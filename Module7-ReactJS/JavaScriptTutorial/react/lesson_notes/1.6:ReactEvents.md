# React Events

---

## What are React Events?

In React apps, **events** are triggered by user interactions — things like mouse clicks, typing in an input, submitting a form, hovering over an element, and so on.

React lets you respond to these events by attaching **event handlers** — functions that execute when a specific event occurs — directly to JSX elements as props.

---

## Adding an Event Handler

There are two steps:

1. **Define** a function (the event handler) that will run when the event occurs
2. **Pass** that function as a prop on the JSX element

```jsx
// Step 1 — define the event handler
const handleClick = () => {
  alert('Clicked!');
};

// Step 2 — pass it as a prop
return <button onClick={handleClick}>Click me</button>;
```

Full example:

```jsx
const App = () => {
  const handleClick = () => {
    alert('Clicked!');
  };

  return <button onClick={handleClick}>Click me</button>;
};

export default App;
```

When the button is clicked, `handleClick` runs and shows an alert.

---

## Naming Conventions

React follows consistent naming conventions for event handlers and their props:

| | Convention | Example |
|---|---|---|
| **Event handler function** | Starts with `handle` | `handleClick`, `handleSubmit`, `handleChange` |
| **Event prop on JSX element** | Starts with `on` | `onClick`, `onSubmit`, `onChange` |

```jsx
// Event handler name: handleClick
// Event prop name: onClick
<button onClick={handleClick}>Click me</button>

// Event handler name: handleSubmit
// Event prop name: onSubmit
<form onSubmit={handleSubmit}>...</form>

// Event handler name: handleChange
// Event prop name: onChange
<input onChange={handleChange} />
```

---

## Function Reference vs Function Call

This is one of the most common mistakes in React events.

**Pass the function reference — not a call:**

```jsx
// ✅ Correct — passes the function reference
// handleClick will only run when the button is clicked
<button onClick={handleClick}>Click me</button>

// ❌ Wrong — calls the function immediately when the component renders
// The alert fires before the user even clicks
<button onClick={handleClick()}>Click me</button>
```

The difference is subtle but important:
- `handleClick` — a **reference** to the function (what we want)
- `handleClick()` — **calls** the function immediately (not what we want)

**When you need to pass arguments**, wrap the call in an arrow function:

```jsx
// Pass an argument to the event handler
<button onClick={() => handleClick('hello')}>Click me</button>

// Or call it directly inline
<button onClick={() => alert('Clicked!')}>Click me</button>
```

The arrow function `() => handleClick('hello')` is itself a function reference — it only runs when the button is clicked, and when it does, it calls `handleClick('hello')`.

## The Event Object

Event handlers automatically receive an **event object** as their first argument. This object contains detailed information about the event that occurred — such as which element triggered it, the current value, the mouse position, etc.

React's event object is a **cross-browser wrapper** around the native browser event — it works consistently across all browsers.

### Reading input value with `event.target.value`

```jsx
const App = () => {
  const handleChange = (event) => {
    console.log(event.target.value); // logs the current input value
  };

  return <input type="text" onChange={handleChange} />;
};
```

`event.target` refers to the DOM element that triggered the event. `event.target.value` gives the current value of the input.

### Using the event object inline

```jsx
const App = () => {
  return (
    <button onClick={(event) => console.log(event.type)}>
      Click me
    </button>
  );
};
// Logs: "click"
```

## Inline Event Handlers

For short, simple handlers, you can define the function directly inline in the JSX — no need for a separate named function:

```jsx
// Inline arrow function
const App = () => {
  return <button onClick={() => alert('Clicked!')}>Click me</button>;
};
```

**Named handler vs inline — when to use each:**

| | Named handler | Inline handler |
|---|---|---|
| Code length | Longer JSX, cleaner logic | Shorter, all in one place |
| Reusability | Can be called from multiple places | Single-use only |
| Readability | Better for complex logic | Better for simple one-liners |
| Recommended for | Form submissions, complex logic | Simple toggles, quick alerts |

## Preventing Default Browser Behaviour

Some HTML elements have built-in default behaviour:
- A `<form>` submit reloads the entire page
- Clicking an `<a>` tag navigates to a new URL
- Pressing Enter in an input inside a form submits the form

To stop this default behaviour, call `event.preventDefault()` inside your event handler:

```jsx
const App = () => {
  const handleSubmit = (event) => {
    event.preventDefault();        // stops the page reload
    console.log('Form submitted'); // your custom logic runs instead
  };

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="email">
        Email:
        <input type="email" name="email" id="email" />
      </label>
      <button type="submit">Submit</button>
    </form>
  );
};

export default App;
```

Without `event.preventDefault()`, clicking Submit would reload the page and you'd never see `'Form submitted'` in the console.

## Common React Event Props

| Event prop | Triggers when | Common use |
|---|---|---|
| `onClick` | Element is clicked | Buttons, links, cards |
| `onChange` | Input value changes | Text inputs, checkboxes, selects |
| `onSubmit` | Form is submitted | Form handling |
| `onKeyDown` | A key is pressed down | Keyboard shortcuts |
| `onKeyUp` | A key is released | Search on key press |
| `onFocus` | Element gains focus | Input highlighting |
| `onBlur` | Element loses focus | Validation on blur |
| `onMouseEnter` | Mouse enters an element | Hover effects |
| `onMouseLeave` | Mouse leaves an element | Hover effects |

## Putting it Together — A Complete Example

```jsx
const App = () => {
  // Named handler — shows an alert
  const handleClick = () => {
    alert('Button clicked!');
  };

  // Named handler — reads event object
  const handleChange = (event) => {
    console.log('Input value:', event.target.value);
  };

  // Named handler — prevents page reload
  const handleSubmit = (event) => {
    event.preventDefault();
    console.log('Form submitted');
  };

  return (
    <div>
      {/* Passing function reference */}
      <button onClick={handleClick}>Click me</button>

      {/* Reading input value */}
      <input type="text" onChange={handleChange} />

      {/* Preventing default form submission */}
      <form onSubmit={handleSubmit}>
        <input type="email" placeholder="Email" />
        <button type="submit">Submit</button>
      </form>

      {/* Inline handler with argument */}
      <button onClick={() => alert('Hello!')}>Say Hello</button>
    </div>
  );
};

export default App;
```

---

## Summary

- React events are triggered by user interactions — clicks, input changes, form submits, etc.
- To handle an event: **define** a function and **pass it as a prop** on the JSX element (`onClick`, `onChange`, `onSubmit`)
- By convention, event handler functions start with `handle` and event props start with `on`
- Always pass a **function reference** (`onClick={handleClick}`) — never a function call (`onClick={handleClick()}`) unless wrapped in an arrow function
- When you need to pass arguments, wrap the call: `onClick={() => handleClick(id)}`
- Event handlers receive an **event object** automatically — use `event.target.value` to read input values
- Call `event.preventDefault()` to stop default browser behaviour like page reloads on form submit
- For simple one-line handlers, define them **inline** directly in JSX; for complex logic, use named functions defined inside the component
