# React `useState` Hook

---

## What is `useState`?

`useState` is a React Hook that lets you add a **state variable** to a functional component. State is data that changes over time — and when it changes, React automatically re-renders the component to reflect the update on screen.

---

## Basic Syntax

### Step 1 — Import `useState`

```js
import { useState } from 'react';
```

### Step 2 — Declare a state variable

```js
const [state, setState] = useState(initialValue);
```

`useState()` returns an **array of exactly two elements**:

| Element | Description |
|---|---|
| `state` | The current state value — equals `initialValue` on the first render |
| `setState` | A function that updates the state and triggers a re-render |

### Naming convention

By convention, if the state variable is `count`, the setter function is `setCount`:

```js
const [count,   setCount]   = useState(0);
const [name,    setName]    = useState('');
const [isOpen,  setIsOpen]  = useState(false);
const [items,   setItems]   = useState([]);
const [user,    setUser]    = useState({});
```

The `set` prefix + variable name makes it immediately clear what each function updates.

---

## Basic Example — Counter

```jsx
import { useState } from 'react';

const Counter = () => {
  const [count, setCount] = useState(0);

  const increment = () => {
    setCount(count + 1);
  };

  return (
    <div>
      <h1>Current count: {count}</h1>
      <button onClick={increment}>Increment</button>
    </div>
  );
};

export default Counter;
```

**How it works:**
1. `useState(0)` creates `count` with an initial value of `0`
2. `{count}` in the JSX displays the current value
3. Clicking the button calls `increment()` → `setCount(count + 1)` → state updates → React re-renders → new count is shown

## Two Ways to Update State

### 1. Direct Update

Pass the new value directly — use when you don't need the previous state:

```js
setCount(1);       // sets count to 1 regardless of current value
setName('Alice');  // sets name to 'Alice'
```

### 2. Functional Update

Pass a function that receives the **previous state** and returns the new state — use when the new value depends on the current value:

```js
setCount(prevCount => prevCount + 1); // increments based on previous value
```

> **When to use functional update:** Whenever your new state depends on the old state — especially when multiple state updates happen in the same event handler (see batching below).

---

## State and Re-renders

React re-renders a component whenever state changes via the setter function. You can observe this with `useEffect`:

```jsx
import { useState, useEffect } from 'react';

const Counter = () => {
  const [count, setCount] = useState(0);

  useEffect(() => {
    console.log('Component rendered or re-rendered');
  });

  const increment = () => setCount(count + 1);

  return (
    <div>
      <h1>Current count: {count}</h1>
      <button onClick={increment}>Increment</button>
    </div>
  );
};
```

Every click triggers a re-render and logs the message. The `useEffect` without a dependency array runs after every render.

### No re-render if state does not change

If you call the setter but the value stays the same, React skips the re-render:

```js
// Setting count to the same value — React does NOT re-render
const increment = () => {
  setCount(count); // no change → no re-render
};
```

---

## State Updates are Asynchronous

React does **not** immediately apply state updates. It schedules them for the next render. This means if you log the state right after calling the setter, you'll see the old value:

```js
const increment = () => {
  setCount(count + 1);
  console.log(count); // logs the OLD value — update hasn't been applied yet
};
```

React schedules the update and applies it before the next render — not instantly when `setCount` is called.

---

## State Batching

React **batches** multiple state updates in the same event handler into a single re-render for performance:

```js
const increment = () => {
  setCount(count + 1); // uses current count (e.g. 0) → schedules count = 1
  setCount(count + 2); // uses current count (still 0) → schedules count = 2
  setCount(count + 3); // uses current count (still 0) → schedules count = 3
  console.log(count);  // logs 0 (old value)
};
// Result: one re-render, count becomes 3 (not 6!)
```

All three calls read the **same current value** of `count` — they don't stack on top of each other. The last call wins, so count becomes `0 + 3 = 3`.

Pattern progression if count starts at 0:
```
Click 1: count → 3
Click 2: count → 6
Click 3: count → 9
```

### Fix — use functional updates to stack correctly

When multiple updates need to build on each other, use the functional form so each update receives the latest value:

```js
const increment = () => {
  setCount(prevCount => prevCount + 1); // 0 → 1
  setCount(prevCount => prevCount + 2); // 1 → 3
  setCount(prevCount => prevCount + 3); // 3 → 6
  console.log(count); // still logs old value (0)
};
// Result: count becomes 6, not 3
```

Pattern progression if count starts at 0:
```
Click 1: count → 6
Click 2: count → 12
Click 3: count → 18
```

**Direct update vs functional update — summary:**

| | Direct update `setCount(count + 1)` | Functional update `setCount(prev => prev + 1)` |
|---|---|---|
| Uses | New fixed value | Previous state value |
| When batching multiple updates | Each reads the same stale `count` | Each receives the latest updated value |
| Safe for chaining? | ❌ No | ✅ Yes |
| Use when | Single update, no dependency on prev state | Multiple updates, or when new value depends on old |

## Handling Complex State

### Arrays — Always create a new array

Never mutate the array directly. Create a new one using the spread operator:

```jsx
const FruitList = () => {
  const [fruits, setFruits] = useState([]);

  const addFruit = () => {
    const newFruit = '🍎 apple';

    // ✅ Correct — creates a new array
    setFruits([...fruits, newFruit]);

    // ❌ Wrong — mutates the existing array, React won't re-render
    fruits.push(newFruit);
    setFruits(fruits); // same array reference → no re-render
  };

  return (
    <div>
      <ul>
        {fruits.map((fruit, index) => (
          <li key={index}>{fruit}</li>
        ))}
      </ul>
      <button onClick={addFruit}>Add Fruit</button>
    </div>
  );
};
```

**Common array state operations:**

```js
// Add item
setFruits([...fruits, newFruit]);

// Remove item
setFruits(fruits.filter(f => f !== 'apple'));

// Update item
setFruits(fruits.map(f => f === 'apple' ? 'apricot' : f));

// Clear all
setFruits([]);
```

### Objects — Always create a new object

Never mutate the object directly. Spread existing properties and override what changed:

```jsx
const Person = () => {
  const [person, setPerson] = useState({ name: 'John', age: 20 });

  const handleIncrement = () => {
    // ✅ Correct — creates a new object
    setPerson({ ...person, age: person.age + 1 });

    // ❌ Wrong — mutates the existing object
    person.age += 1;
    setPerson(person); // same object reference → no re-render
  };

  return (
    <div>
      <p>Name: {person.name}</p>
      <p>Age: {person.age}</p>
      <button onClick={handleIncrement}>Increment Age</button>
    </div>
  );
};
```

`{ ...person, age: person.age + 1 }` copies all existing properties (`name`, `age`) and then **overrides** `age` with the new value. The `name` stays untouched.

## Lazy Initialization

Sometimes the initial state requires an **expensive computation** — like reading from `localStorage` or performing a heavy calculation. By default, `useState(expensiveComputation())` runs that function on **every render**, not just the first:

```jsx
// ❌ getTheme() is called on every re-render — wasteful
const [theme, setTheme] = useState(getTheme());
```

**Fix — pass a function reference instead of a function call:**

```jsx
// ✅ getTheme() is called ONLY once on the initial render
const [theme, setTheme] = useState(() => getTheme());
```

The difference:
- `useState(getTheme())` — calls `getTheme()` immediately every render before passing the result to `useState`
- `useState(() => getTheme())` — passes a function; `useState` calls it only on the first render

**Full example:**

```jsx
import { useState } from 'react';

function getTheme() {
  console.log('Getting theme from localStorage'); // only logs once
  return localStorage.getItem('theme') || 'light';
}

const Theme = () => {
  // lazy initialization — getTheme() runs only once
  const [theme, setTheme] = useState(() => getTheme());

  const handleClick = () => {
    const newTheme = theme === 'light' ? 'dark' : 'light';
    setTheme(newTheme);
    localStorage.setItem('theme', newTheme);
  };

  return (
    <div>
      <p>Current Theme: {theme}</p>
      <button onClick={handleClick}>Switch Theme</button>
    </div>
  );
};
```

**When to use lazy initialization:**
- Reading from `localStorage` or `sessionStorage`
- Parsing large data structures
- Any expensive computation needed only for the initial value

## Common Mistakes

**Modifying state directly:**
```js
// ❌ Never do this
count = count + 1;       // direct variable assignment
fruits.push('apple');    // mutating array in place
person.age = 25;         // mutating object in place

// ✅ Always use the setter
setCount(count + 1);
setFruits([...fruits, 'apple']);
setPerson({ ...person, age: 25 });
```

**Reading state immediately after setting it:**
```js
setCount(count + 1);
console.log(count); // ❌ shows the old value — update is async
```

**Using the wrong update pattern when chaining:**
```js
// ❌ All three use the same stale value
setCount(count + 1);
setCount(count + 2);
setCount(count + 3);

// ✅ Each builds on the previous update
setCount(prev => prev + 1);
setCount(prev => prev + 2);
setCount(prev => prev + 3);
```

## Quick Reference

| Task | Code |
|---|---|
| Declare state | `const [value, setValue] = useState(initial)` |
| Update state | `setValue(newValue)` |
| Update based on previous | `setValue(prev => prev + 1)` |
| Add to array | `setValue([...value, newItem])` |
| Remove from array | `setValue(value.filter(x => x !== item))` |
| Update object property | `setValue({ ...value, key: newVal })` |
| Lazy initialization | `useState(() => expensiveFn())` |

---

## Summary

- `useState()` adds a state variable to a functional component — import it from `'react'`
- It returns `[currentValue, setterFunction]` — always use array destructuring
- **Always call the setter function** to update state — never modify the variable directly
- React re-renders the component when state changes; if the new value equals the old, no re-render happens
- State updates are **asynchronous** — logging state right after calling the setter shows the old value
- React **batches** multiple state updates into one re-render — use **functional updates** (`prev => prev + 1`) when updates depend on each other
- For **arrays and objects**, always create a new copy (spread operator) — never mutate in place
- Use **lazy initialization** `useState(() => fn())` when the initial state is expensive to compute
