# React JSX

---

## What is JSX?

**JSX** stands for **JavaScript XML**. It is a syntax extension to JavaScript that lets you write HTML-like code directly inside JavaScript files.

```jsx
// JSX — HTML-like syntax inside a JavaScript function
function App() {
  return <h1>Hello, React!</h1>;
}
```

JSX combines the strength of JavaScript with the simplicity of HTML, making it much faster and more readable to build user interfaces. Before the browser receives the code, React uses **Babel** to transpile JSX into native JavaScript.

---

## Returning Valid JSX

### Single line — no parentheses needed

```jsx
const App = () => {
  return <h1>Hello, React!</h1>;
};
```

### Multiple lines — wrap in parentheses

When JSX spans multiple lines, wrap it in parentheses `()`. The opening parenthesis **must be on the same line as `return`**:

```jsx
const App = () => {
  return (
    <div>
      <h1>Hello, React!</h1>
    </div>
  );
};
```

> **Important:** If the opening parenthesis is not on the same line as `return`, JavaScript assumes the function returns `undefined` due to Automatic Semicolon Insertion.

```js
// ❌ This returns undefined — opening paren is on the next line
const App = () => {
  return
    (
      <h1>Hello!</h1>
    );
};
```

---

## JSX Must Have One Root Element

When returning multiple elements, they must all be wrapped inside a single parent element. Returning two sibling elements without a wrapper causes a compile error:

```jsx
// ❌ Error — two elements with no wrapper
const App = () => {
  return (
    <h1>Hello, React!</h1>
    <p>I love React.</p>
  );
};
```

```
Error: Adjacent JSX elements must be wrapped in an enclosing tag.
```

**Fix 1 — wrap in a `div`:**

```jsx
// ✅ Wrapped in a div
const App = () => {
  return (
    <div>
      <h1>Hello, React!</h1>
      <p>I love React.</p>
    </div>
  );
};
```

**Fix 2 — use a React Fragment (no extra DOM node):**

If adding a `div` would break your CSS or add unwanted nesting, use an empty JSX element `<>...</>` — called a **React Fragment**:

```jsx
// ✅ React Fragment — renders no extra HTML element
const App = () => {
  return (
    <>
      <h1>Hello, React!</h1>
      <p>I love React.</p>
    </>
  );
};
```

Fragments produce no extra element in the browser — the rendered HTML is just:

```html
<h1>Hello, React!</h1>
<p>I love React.</p>
```

## Self-Closing Tags

In HTML, some elements like `<input>` and `<img>` don't have a closing tag. In JSX, all self-closing elements must include a forward slash before the closing `>`:

```jsx
// ✅ Self-closing in JSX
<input type="text" />
<img src="photo.png" alt="photo" />
<br />

// ❌ Invalid in JSX — missing the slash
<input type="text">
```

## Using Variables in JSX

To display a JavaScript variable or expression inside JSX, wrap it in **curly braces `{}`**:

```jsx
const App = () => {
  const name = 'John';
  const age = 25;

  return (
    <p>Hi, I'm {name}. I'm {age} years old.</p>
  );
};
// Output: Hi, I'm John. I'm 25 years old.
```

### What JSX can and cannot display

| Value type | Displays? | Notes |
|---|---|---|
| String | ✅ Yes | Renders as text |
| Number | ✅ Yes | Renders as text |
| Boolean (`true`/`false`) | ❌ No | Renders nothing — useful for conditional rendering |
| `null` | ❌ No | Renders nothing |
| `undefined` | ❌ No | Renders nothing |
| Array | ⚠️ Partial | Concatenates all elements into one string — no spaces |
| Object | ❌ Error | Throws: "Objects are not valid as a React child" |

**Boolean, null, undefined example:**

```jsx
const App = () => {
  const active = true;
  let jobTitle = null;

  return (
    <ul>
      <li>Status: {active}</li>      {/* renders nothing */}
      <li>Job Title: {jobTitle}</li> {/* renders nothing */}
    </ul>
  );
};
// Output:
// Status:
// Job Title:
```

**Array example — concatenated without spaces:**

```jsx
const App = () => {
  const skills = ['JS', 'React', 'Node.js'];
  return <p>Skills: {skills}</p>;
};
// Output: Skills: JSReactNode.js  ← no spaces between items
```

**Object — causes an error:**

```jsx
const App = () => {
  const person = { name: 'John', age: 25 };
  return <p>{person}</p>; // ❌ throws error
};
// Error: Objects are not valid as a React child
```

To display object data, access its properties individually:

```jsx
return <p>{person.name} is {person.age} years old.</p>; // ✅
```

## Using Expressions in JSX

Any valid JavaScript **expression** can go inside curly braces — including ternary operators, function calls, and arithmetic:

```jsx
const App = () => {
  const name = 'John';
  const age = 25;
  const active = true;

  return (
    <ul>
      <li>Name: {name}</li>
      <li>Age: {age}</li>
      <li>Status: {active ? 'Active' : 'Inactive'}</li>
      <li>Next year: {age + 1}</li>
      <li>Uppercase: {name.toUpperCase()}</li>
    </ul>
  );
};
// Output:
// Name: John
// Age: 25
// Status: Active
// Next year: 26
// Uppercase: JOHN
```

## Adding Props (Attributes)

In React, attributes of JSX elements are called **props**.

**String props** — wrap in double quotes:

```jsx
<input type="text" name="email" placeholder="Enter email" />
```

**JavaScript variable props** — wrap in curly braces (no quotes):

```jsx
const App = () => {
  const inputType = 'range';
  return (
    <input type={inputType} min="0" max="100" />
  );
};
```

---

## JSX vs HTML — Important Differences

Some HTML attributes are reserved keywords in JavaScript. JSX uses different names for them:

| HTML | JSX | Reason |
|---|---|---|
| `class` | `className` | `class` is a reserved keyword in JavaScript |
| `for` | `htmlFor` | `for` is a reserved keyword in JavaScript |

```jsx
// ❌ HTML way — causes a warning in React
<button class="btn">OK</button>
<label for="email">Email</label>

// ✅ JSX way
<button className="btn">OK</button>
<label htmlFor="email">Email</label>
```

## Applying CSS Styles

### Using `className`

```jsx
const App = () => {
  return (
    <button className="btn" type="button">
      OK
    </button>
  );
};
```

### Inline styles — using a JavaScript object

Inline styles in JSX are passed as a **JavaScript object**, not a CSS string. CSS properties with hyphens become **camelCase**:

| CSS property | JSX style property |
|---|---|
| `background-color` | `backgroundColor` |
| `margin-top` | `marginTop` |
| `font-size` | `fontSize` |
| `border-radius` | `borderRadius` |

```jsx
// Inline style directly in JSX
// Note: double curly braces — outer {} for JSX expression, inner {} for the object
const App = () => {
  return (
    <button
      type="button"
      style={{
        padding: '0.25rem 0.75rem',
        backgroundColor: '#F9DC5C',
        border: 'none',
        borderRadius: '4px',
        cursor: 'pointer',
      }}
    >
      OK
    </button>
  );
};
```

The two pairs of curly braces explained:
- **Outer `{}`** — tells JSX "a JavaScript expression follows"
- **Inner `{}`** — the JavaScript object containing the style properties

**Cleaner alternative — define the style object as a variable:**

```jsx
const App = () => {
  const btnStyle = {
    padding: '0.25rem 0.75rem',
    backgroundColor: '#F9DC5C',
    border: 'none',
    borderRadius: '4px',
    cursor: 'pointer',
  };

  return (
    <button type="button" style={btnStyle}>
      OK
    </button>
  );
};
```

## JSX Quick Reference

| Concept | HTML | JSX |
|---|---|---|
| Class attribute | `class="btn"` | `className="btn"` |
| Label for | `for="email"` | `htmlFor="email"` |
| Self-closing tag | `<input>` | `<input />` |
| Inline style | `style="color: red"` | `style={{ color: 'red' }}` |
| JS variable | N/A | `{variableName}` |
| JS expression | N/A | `{2 + 2}`, `{condition ? 'A' : 'B'}` |
| Multiple elements | Allowed | Must have one root element or Fragment |

---

## Summary

- **JSX** is a JavaScript syntax extension that lets you write HTML-like code inside JavaScript — Babel transpiles it to plain JavaScript before the browser sees it.
- The opening parenthesis in a multi-line `return` must be on the **same line** as `return` — otherwise JavaScript returns `undefined`.
- JSX must return a **single root element** — wrap siblings in a `div` or a **React Fragment** (`<>...</>`) to avoid adding unwanted DOM nodes.
- **Self-closing tags** must end with `/>` — e.g. `<input />`, `<img />`.
- Use **curly braces `{}`** to embed JavaScript variables, expressions, and function calls inside JSX.
- JSX can display strings and numbers, but silently ignores booleans, `null`, and `undefined`. Arrays are concatenated without spaces. Objects throw an error.
- Use `className` instead of `class`, and `htmlFor` instead of `for`.
- Inline styles are passed as a **JavaScript object** with camelCase properties — `backgroundColor` not `background-color`.
