# React `useRef` Hook

The `useRef` hook serves two main purposes in React:

1. **Access DOM elements directly** — similar to `document.querySelector()` in plain JavaScript.
2. **Persist mutable values between renders** — without triggering a re-render when the value changes.

This is the key distinction from `useState`: updating a ref's `.current` value does **not** cause the component to re-render.

---

## Steps to Use `useRef`

### Step 1 — Import `useRef`

```js
import { useRef } from 'react';
```

---

### Step 2 — Create the Ref Object

Call `useRef()` with an initial value. It returns a **mutable ref object** with a single `.current` property.

```js
const myRef = useRef(initialValue);
// myRef = { current: initialValue }
```

---

### Step 3 — Attach the Ref to a DOM Element

Pass the ref object to the `ref` attribute of a JSX element. React will set `myRef.current` to that DOM node after rendering.

```jsx
<input ref={myRef} type="text" />
```

---

### Step 4 — Use the Ref

Access the DOM element or stored value via `.current` inside event handlers, effects, or anywhere in your component.

```js
const handleClick = () => {
  console.log(myRef.current.value); // reads the input's current value
};
```

---

### Step 5 — Update the Ref

Directly assign a new value to `.current`. This does **not** trigger a re-render.

```js
myRef.current = newValue;
```

---

## Use Case 1 — Accessing DOM Elements Directly

The most common use of `useRef` is to interact with a DOM node directly — for example, programmatically focusing an input field.

```jsx
import { useRef } from 'react';

const SubscriberForm = () => {
  const inputRef = useRef(null);

  const handleClick = () => {
    inputRef.current.focus(); // directly calls focus() on the input DOM node
  };

  return (
    <div>
      <label htmlFor="email">Email:</label>
      <input type="email" id="email" ref={inputRef} />
      <button type="submit" onClick={handleClick}>
        Submit
      </button>
    </div>
  );
};

export default SubscriberForm;
```

### How it works

1. `useRef(null)` creates a ref initialised to `null`. Before the component mounts, `.current` is `null`.
2. `ref={inputRef}` tells React to assign the input DOM node to `inputRef.current` after the component renders.
3. When the **Submit** button is clicked, `handleClick` calls `inputRef.current.focus()` — directly invoking the native DOM `focus()` method on the input.
4. The input receives focus without any state update or re-render.

> This is equivalent to `document.getElementById('email').focus()` in plain JavaScript, but done the React way.

## Use Case 2 — Storing Mutable Values Without Re-rendering

`useRef` can hold any mutable value that needs to **persist across renders** but should **not trigger a re-render** when it changes. Think of it like an instance variable on a class component.

```jsx
import { useRef } from 'react';

const Counter = () => {
  const countRef = useRef(0);

  const incrementCount = () => {
    countRef.current++;           // update the ref — no re-render
    alert(countRef.current);      // shows the updated count
  };

  return <button onClick={incrementCount}>Increment Count</button>;
};

export default Counter;
```

### How it works

1. `useRef(0)` initialises the ref with a value of `0`.
2. Each click increments `countRef.current` directly.
3. The component **never re-renders** — the button label stays the same, but the count value persists and grows with each click.
4. The `alert` confirms the current count has been tracked correctly.

> Compare this with `useState`: if you used `const [count, setCount] = useState(0)`, every `setCount()` call would re-render the component. With `useRef`, no re-render happens.

## Use Case 3 — Storing the Previous State Value

A common pattern is using `useRef` to remember the **previous value** of a state variable across renders.

```jsx
import { useRef, useState, useEffect } from 'react';

const PreviousValue = () => {
  const [name, setName] = useState('');
  const prevNameRef = useRef('');

  useEffect(() => {
    prevNameRef.current = name; // store current name after every render
  }, [name]);

  return (
    <div>
      <input
        value={name}
        onChange={(e) => setName(e.target.value)}
        placeholder="Type your name"
      />
      <p>Current name: {name}</p>
      <p>Previous name: {prevNameRef.current}</p>
    </div>
  );
};

export default PreviousValue;
```

### How it works

1. `useState` manages the current `name` and triggers re-renders on change.
2. After every render, `useEffect` stores the current `name` into `prevNameRef.current`.
3. Because updating `.current` doesn't cause a re-render, `prevNameRef.current` always holds the value from the **previous** render when displayed.

## Use Case 4 — Storing a Timer ID

`useRef` is ideal for holding references to timers or intervals so they can be cancelled later — without causing unnecessary re-renders.

```jsx
import { useRef, useState } from 'react';

const Timer = () => {
  const [isRunning, setIsRunning] = useState(false);
  const timerRef = useRef(null);

  const startTimer = () => {
    setIsRunning(true);
    timerRef.current = setInterval(() => {
      console.log('Tick...');
    }, 1000);
  };

  const stopTimer = () => {
    clearInterval(timerRef.current); // cancel using the stored ID
    timerRef.current = null;
    setIsRunning(false);
  };

  return (
    <div>
      <button onClick={startTimer} disabled={isRunning}>Start</button>
      <button onClick={stopTimer} disabled={!isRunning}>Stop</button>
    </div>
  );
};

export default Timer;
```

### How it works

1. `setInterval` returns a timer ID. Storing it in `timerRef.current` persists it across renders without triggering any.
2. When **Stop** is clicked, `clearInterval(timerRef.current)` uses the stored ID to cancel the timer.
3. If `useState` were used instead, updating the timer ID would cause a re-render on every start/stop.

## `useRef` vs `useState`

| Feature | `useRef` | `useState` |
|---|---|---|
| **Purpose** | Persist mutable values without re-rendering | Manage state that affects rendering |
| **Initial Value** | `useRef(initialValue)` | `useState(initialValue)` |
| **Return Value** | Object with `.current` property | Array: `[value, setter]` |
| **Causes Re-render?** | No | Yes |
| **Reactivity** | Not reactive — changes not tracked by React | Reactive — changes trigger re-render |
| **Update Method** | Directly set `.current` | Call the setter function |
| **Value Persistence** | Persists between renders | Persists between renders |
| **Reset Behaviour** | Must be reset manually | Reset via setter or on re-mount |
| **Common Use Cases** | DOM access, timers, previous values, instance variables | Form inputs, toggles, counters displayed in UI |

### When to use which

- Use **`useState`** when the value is **displayed in the UI** and you need the component to re-render when it changes.
- Use **`useRef`** when the value is used **internally** (not rendered) or when you need to access a DOM element directly.

```jsx
// useState — shown in the UI, needs re-render
const [count, setCount] = useState(0);
return <p>Count: {count}</p>;

// useRef — not shown in UI, no re-render needed
const renderCount = useRef(0);
renderCount.current++;
```

## Common Mistakes to Avoid

**1. Reading a ref immediately after setting it in render**

Refs are updated by React *after* the render is committed to the DOM. Do not read `.current` inside the render body expecting the latest DOM value.

```jsx
// BAD — ref may not be attached yet during first render
const inputRef = useRef(null);
console.log(inputRef.current.value); // null on first render

// GOOD — read inside an effect or event handler
useEffect(() => {
  console.log(inputRef.current.value); // safe after mount
}, []);
```

**2. Using `useRef` for values that should be displayed**

If a value needs to appear in the UI, use `useState`. Changes to `.current` won't update what's shown on screen.

```jsx
// BAD — UI won't update when countRef.current changes
const countRef = useRef(0);
return <p>Count: {countRef.current}</p>;

// GOOD — use useState so React knows to re-render
const [count, setCount] = useState(0);
return <p>Count: {count}</p>;
```

**3. Not cleaning up refs in `useEffect`**

Always clean up timers or subscriptions stored in refs to avoid memory leaks.

```jsx
useEffect(() => {
  timerRef.current = setInterval(() => { /* ... */ }, 1000);

  return () => clearInterval(timerRef.current); // cleanup on unmount
}, []);
```

---

## Summary

- `useRef` returns a mutable object `{ current: value }` that **persists across renders**.
- Updating `.current` does **not** trigger a re-render — this is its defining difference from `useState`.
- Use it to **access DOM nodes directly** (focus, scroll, measure) or to **store values** that don't need to be reflected in the UI.
- Common patterns include DOM focus management, storing timer IDs, tracking previous state values, and holding instance-like variables.
