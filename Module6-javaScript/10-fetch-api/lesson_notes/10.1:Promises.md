# JavaScript Promises

A **Promise** is an object that encapsulates the result of an asynchronous operation. It represents a value that may not be available yet but will be resolved at some point in the future — either successfully or with an error.

---

## Why Promises? — The Problem They Solve

### Synchronous Code (No Delay)

In a simple synchronous flow, functions execute one after another and return results immediately.

```js
function getUsers() {
  return [
    { username: 'john', email: 'john@test.com' },
    { username: 'jane', email: 'jane@test.com' },
  ];
}

function findUser(username) {
  const users = getUsers();
  const user = users.find((user) => user.username === username);
  return user;
}

console.log(findUser('john'));
// { username: 'john', email: 'john@test.com' }
```

This works perfectly in a synchronous context. But in the real world, `getUsers()` might fetch data from a database or an API — operations that take time.

---

### The Async Problem — `setTimeout` Simulation

Using `setTimeout` to simulate a 1-second network delay breaks the synchronous flow:

```js
function getUsers() {
  let users = [];

  setTimeout(() => {
    // This runs AFTER getUsers() has already returned
    users = [
      { username: 'john', email: 'john@test.com' },
      { username: 'jane', email: 'jane@test.com' },
    ];
  }, 1000);

  return users; // Returns empty array immediately
}

function findUser(username) {
  const users = getUsers(); // Gets empty array
  const user = users.find((user) => user.username === username);
  return user;
}

console.log(findUser('john')); // undefined
```

**Why it fails:** `getUsers()` returns the empty `users` array before `setTimeout` has had a chance to populate it. JavaScript does not wait for the timeout.

---

### The Callback Approach — A Partial Fix

One classical solution is to pass a **callback function** that is called once the async operation completes:

```js
function getUsers(callback) {
  setTimeout(() => {
    callback([
      { username: 'john', email: 'john@test.com' },
      { username: 'jane', email: 'jane@test.com' },
    ]);
  }, 1000);
}

function findUser(username, callback) {
  getUsers((users) => {
    const user = users.find((user) => user.username === username);
    callback(user);
  });
}

findUser('john', console.log);
// { username: 'john', email: 'john@test.com' }
```

This works, but as the number of async operations grows, callbacks nest deeper inside each other — known as **callback hell**:

```js
getUsers((users) => {
  findUser(users, (user) => {
    getOrders(user, (orders) => {
      processOrder(orders, (result) => {
        // Deeply nested, hard to read and maintain
      });
    });
  });
});
```

**Promises solve this** by providing a cleaner, chainable, and more readable way to handle async operations.

---

## Understanding Promise States

A promise object can be in one of three states:

| State | Description |
|---|---|
| **Pending** | Initial state — the async operation is still in progress |
| **Fulfilled** | The async operation completed successfully — has a resolved value |
| **Rejected** | The async operation failed — has an error reason |

**Key rules:**
- A promise starts in `pending`.
- It can only transition to either `fulfilled` or `rejected` — never both.
- Once settled (fulfilled or rejected), it **cannot change state again**.

```
Pending  →  Fulfilled (resolve called)
Pending  →  Rejected  (reject called)
```

---

## Creating a Promise

Use the `Promise()` constructor, which accepts an **executor function**. The executor receives two callbacks: `resolve` and `reject`.

```js
const promise = new Promise((resolve, reject) => {
  // Perform an async operation...

  if (/* success */) {
    resolve(value);   // Moves state to fulfilled
  } else {
    reject(error);    // Moves state to rejected
  }
});
```

### Example — Basic Promise

```js
const promise = new Promise((resolve, reject) => {
  setTimeout(() => {
    const success = true;

    if (success) {
      resolve('Operation completed successfully!');
    } else {
      reject('Something went wrong.');
    }
  }, 1000);
});
```

- The executor runs immediately when the promise is created.
- After 1 second, if `success` is `true`, the promise is **fulfilled** with the string value.
- If `success` is `false`, it is **rejected** with an error message.

## Consuming a Promise

### 1. The `then()` Method

`then()` is called when a promise is **fulfilled**. It accepts two optional callbacks: `onFulfilled` and `onRejected`.

```js
promise.then(onFulfilled, onRejected);
```

**Example:**

```js
function getUsers() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      resolve([
        { username: 'john', email: 'john@test.com' },
        { username: 'jane', email: 'jane@test.com' },
      ]);
    }, 1000);
  });
}

// Using named functions
function onFulfilled(users) {
  console.log(users);
}

const promise = getUsers();
promise.then(onFulfilled);

// Output (after 1 second):
// [
//   { username: 'john', email: 'john@test.com' },
//   { username: 'jane', email: 'jane@test.com' }
// ]
```

**Using arrow functions (more concise):**

```js
getUsers().then((users) => {
  console.log(users);
});
```

---

### Handling Both Fulfilled and Rejected in `then()`

Pass both `onFulfilled` and `onRejected` as arguments to `then()`:

```js
let success = true;

function getUsers() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (success) {
        resolve([
          { username: 'john', email: 'john@test.com' },
          { username: 'jane', email: 'jane@test.com' },
        ]);
      } else {
        reject('Failed to fetch-get the user list.');
      }
    }, 1000);
  });
}

function onFulfilled(users) {
  console.log('Users:', users);
}

function onRejected(error) {
  console.log('Error:', error);
}

getUsers().then(onFulfilled, onRejected);

// If success = true  → Users: [ { username: 'john', ... }, ... ]
// If success = false → Error: Failed to fetch-get the user list.
```

---

### 2. The `catch()` Method

`catch()` handles only **rejected** promises. It is shorthand for `.then(undefined, onRejected)` and is the preferred way to handle errors.

```js
promise.catch(onRejected);
```

**Example:**

```js
let success = false;

function getUsers() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (success) {
        resolve([
          { username: 'john', email: 'john@test.com' },
          { username: 'jane', email: 'jane@test.com' },
        ]);
      } else {
        reject('Failed to fetch-get the user list.');
      }
    }, 1000);
  });
}

getUsers()
  .then((users) => {
    console.log(users);
  })
  .catch((error) => {
    console.log('Caught error:', error);
    // Caught error: Failed to fetch-get the user list.
  });
```

**Why use `catch()` instead of the second argument of `then()`?**

Using a separate `catch()` at the end of a chain catches errors from **any** `then()` in the chain, not just the last one. It is cleaner and easier to manage.

---

### 3. The `finally()` Method

`finally()` runs a callback **regardless** of whether the promise was fulfilled or rejected. It is useful for cleanup tasks like hiding a loading spinner or closing a database connection.

**Without `finally()` — duplicated code:**

```js
const render = () => console.log('Rendering UI...');

getUsers()
  .then((users) => {
    console.log(users);
    render(); // Duplicated
  })
  .catch((error) => {
    console.log(error);
    render(); // Duplicated
  });
```

**With `finally()` — clean and DRY:**

```js
const render = () => console.log('Rendering UI...');

getUsers()
  .then((users) => {
    console.log(users);
  })
  .catch((error) => {
    console.log(error);
  })
  .finally(() => {
    render(); // Always runs — fulfilled or rejected
  });
```

## Promise Chaining

Because `then()` returns a new promise, you can **chain** multiple async operations sequentially. This eliminates callback hell.

```js
function getUsers() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve([
        { username: 'john', email: 'john@test.com' },
        { username: 'jane', email: 'jane@test.com' },
      ]);
    }, 1000);
  });
}

function findUser(users, username) {
  return new Promise((resolve, reject) => {
    const user = users.find((u) => u.username === username);
    if (user) {
      resolve(user);
    } else {
      reject(`User '${username}' not found.`);
    }
  });
}

// Chaining promises
getUsers()
  .then((users) => findUser(users, 'john'))
  .then((user) => {
    console.log('Found user:', user);
    // Found user: { username: 'john', email: 'john@test.com' }
  })
  .catch((error) => {
    console.log('Error:', error);
  })
  .finally(() => {
    console.log('Done.');
  });
```

**How it works:**
1. `getUsers()` resolves with a user array after 1 second.
2. The first `then()` receives the users and calls `findUser()`, returning a new promise.
3. The second `then()` receives the matched user and logs it.
4. `catch()` handles any rejection from any step in the chain.
5. `finally()` always runs last.

## Returning Values in `.then()` Chains

### The Problem — Forgetting to Return

After a `.then()` that doesn't return anything, the **next** `.then()` receives `undefined`, not the previous value.

```js
getUsers()
  .then((users) => findUser(users, 'john'))
  .then((user) => {
    console.log('Found user:', user);
    // ❌ No return here — user is lost
  })
  .then((user) => {
    console.log('Username:', user.username); // ❌ TypeError: Cannot read properties of undefined
  });
```

**Fix it by returning the value each time you want to pass it forward:**

```js
getUsers()
  .then((users) => findUser(users, 'john'))

  .then((user) => {
    console.log('Found user:', user);
    return user; // ✅ pass to next then()
  })

  .then((user) => {
    console.log('Username:', user.username);
    return user; // ✅ pass again
  })

  .then((user) => {
    console.log('Email:', user.email);
  })

  .catch((error) => {
    console.log('Error:', error);
  })

  .finally(() => {
    console.log('Done.');
  });
```

### The Rule

Each `.then()` receives:
- The **resolved value** from the original promise, or
- The **value returned** by the previous `.then()`

If nothing is returned, the next `.then()` gets `undefined`.

| What you return | What the next `.then()` receives |
|---|---|
| A value (`return user`) | That value |
| A promise (`return fetchData(x)`) | The resolved value of that promise |
| Nothing | `undefined` |
| Throws an error | Jumps to `.catch()` |

**Visual flow:**

```
Promise -> then(user) -> return user
                     ↓
               then(user) -> return user
                     ↓
               then(user)
```

---

### Implicit Returns in Arrow Functions

Arrow functions **without curly braces** have an implicit return — they return the expression automatically.

So this:

```js
.then((users) => findUser(users, 'john'))
```

is exactly equivalent to:

```js
.then((users) => {
  return findUser(users, 'john');
})
```

This is why the first `.then()` in the chaining example doesn't need an explicit `return` keyword — the concise arrow function syntax returns `findUser(...)` implicitly.

**Full chain flow explained:**

```
getUsers() resolves with users array
        ↓
first then() returns findUser(...)   ← implicit return via arrow function
        ↓
findUser resolves with user object
        ↓
next then(user) receives user
```

---

### Return Patterns — Examples

```js
// Return a value — next then() receives x + 1
.then((x) => x + 1)

// Return a promise — next then() receives the resolved value of fetchData(x)
.then((x) => fetchData(x))

// Return nothing — next then() receives undefined
.then((x) => {
  console.log(x);
})
```

**Demonstrating the difference:**

```js
// ✅ Works — users passed to second then()
getUsers()
  .then((users) => {
    console.log(users);
    return users;
  })
  .then((users) => {
    console.log('Second then:', users); // receives users
  });

// ❌ Breaks — second then() gets undefined
getUsers()
  .then((users) => {
    console.log(users);
    // no return
  })
  .then((users) => {
    console.log(users); // undefined
  });
```

> **Key idea:** Each `.then()` returns a **new promise**. If you return a value, the next `.then()` receives it. If you return nothing, the next `.then()` gets `undefined`. If you throw an error, execution jumps to `.catch()`.

## Practical Example — Loading JSON from a Server

The following example loads a JSON file from a server using `XMLHttpRequest` wrapped in a Promise.

**HTML:**

```html
<!DOCTYPE html>
<html>
<head>
  <title>JavaScript Promise Demo</title>
</head>
<body>
  <div id="message"></div>
  <button id="btnGet">Get Message</button>
  <script src="promise-demo.js"></script>
</body>
</html>
```

**`promise-demo.js`:**

```js
// Wraps XMLHttpRequest in a Promise
function load(url) {
  return new Promise(function (resolve, reject) {
    const request = new XMLHttpRequest();

    request.onreadystatechange = function () {
      if (this.readyState === 4 && this.status === 200) {
        resolve(this.response); // Success — resolve with the response
      } else if (this.readyState === 4) {
        reject(this.status);    // Failure — reject with HTTP status code
      }
    };

    request.open('GET', url, true);
    request.send();
  });
}

const url = 'https://www.javascripttutorial.net/sample/promise/api.json';
const btn = document.querySelector('#btnGet');
const msg = document.querySelector('#message');

btn.addEventListener('click', () => {
  load(url)
    .then((response) => {
      const result = JSON.parse(response);
      msg.innerHTML = result.message; // Display message from JSON
    })
    .catch((error) => {
      msg.innerHTML = `Error getting the message, HTTP status: ${error}`;
    });
});
```

**How it works:**

1. When the button is clicked, `load(url)` is called and returns a promise.
2. The executor creates an `XMLHttpRequest` and sends a `GET` request.
3. If the server responds with HTTP status `200`, `resolve()` is called with the response data.
4. If it fails, `reject()` is called with the HTTP status code.
5. `then()` parses the JSON and displays the message on the page.
6. `catch()` displays a friendly error message if the request fails.

## Quick Reference — `then`, `catch`, `finally`

```js
someAsyncOperation()
  .then((result) => {
    // Runs if the promise is fulfilled
    console.log('Success:', result);
  })
  .catch((error) => {
    // Runs if the promise is rejected (from any step in the chain)
    console.log('Error:', error);
  })
  .finally(() => {
    // Always runs — regardless of outcome
    console.log('Finished.');
  });
```

## `async` / `await`

`async` and `await` are syntactic sugar built on top of Promises. They let you write asynchronous code that reads like synchronous code — no chaining, no callbacks.

---

### 1. `async` Functions

Marking a function with `async` makes it always return a Promise — even if you return a plain value:

```js
async function greet() {
  return 'Hello';
}

greet().then((message) => {
  console.log(message); // Hello
});
```

JavaScript automatically wraps the returned string in a resolved Promise. The above is equivalent to:

```js
function greet() {
  return Promise.resolve('Hello');
}
```

---

### 2. `await`

`await` pauses execution inside an `async` function until the Promise settles, then gives you the resolved value directly.

```js
function getUser() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve('John');
    }, 2000);
  });
}

async function displayUser() {
  console.log('Loading...');
  const user = await getUser(); // pauses here until resolved
  console.log(user);
}

displayUser();
// Loading...
// John  (after 2 seconds)
```

**Comparing the two styles:**

```js
// With .then()
getUser().then((user) => {
  console.log(user);
});

// With await — cleaner
const user = await getUser();
console.log(user);
```

> **Rule:** `await` can only be used inside an `async` function. Using it at the top level (outside any function) is invalid unless you are in a module that supports top-level `await`.

---

### 3. Error Handling with `try...catch`

When a Promise rejects, `await` throws the error — catch it with `try...catch`:

```js
function login(success) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (success) {
        resolve('Login successful');
      } else {
        reject('Invalid credentials');
      }
    }, 1000);
  });
}

async function authenticate() {
  try {
    const result = await login(false);
    console.log(result);
  } catch (error) {
    console.log('Error:', error);
    // Error: Invalid credentials
  }
}

authenticate();
```

This replaces `.catch()` at the end of a chain with a standard `try...catch` block.

---

### 4. Multiple `await`s

You can use multiple `await` statements in sequence — each one waits for the previous to finish:

```js
function step1() {
  return Promise.resolve('Step 1 complete');
}

function step2() {
  return Promise.resolve('Step 2 complete');
}

async function runSteps() {
  const result1 = await step1();
  console.log(result1); // Step 1 complete

  const result2 = await step2();
  console.log(result2); // Step 2 complete
}

runSteps();
```

---

### 5. Parallel Execution with `Promise.all`

Sequential `await`s run one after another — if both take 2 seconds, the total is 4 seconds:

```js
// Sequential — slow (4 seconds total)
const a = await task1(); // waits 2s
const b = await task2(); // waits another 2s
```

When tasks are independent of each other, run them in **parallel** using `Promise.all`:

```js
// Parallel — fast (2 seconds total)
const [a, b] = await Promise.all([task1(), task2()]);
```

**Example:**

```js
function fetchUsers() {
  return new Promise((resolve) => {
    setTimeout(() => resolve(['John', 'Jane']), 2000);
  });
}

function fetchPosts() {
  return new Promise((resolve) => {
    setTimeout(() => resolve(['Post 1', 'Post 2']), 2000);
  });
}

async function loadData() {
  const [users, posts] = await Promise.all([
    fetchUsers(),
    fetchPosts(),
  ]);

  console.log(users); // ['John', 'Jane']
  console.log(posts); // ['Post 1', 'Post 2']
}

loadData();
// Both finish in ~2 seconds instead of ~4 seconds
```

---

### Promise Chaining vs `async`/`await` — Comparison

**Promise chaining:**

```js
getUser()
  .then((user) => getPosts(user))
  .then((posts) => console.log(posts))
  .catch((error) => console.log(error));
```

**`async`/`await`:**

```js
async function run() {
  try {
    const user = await getUser();
    const posts = await getPosts(user);
    console.log(posts);
  } catch (error) {
    console.log(error);
  }
}
```

| Feature | Promise `.then()` | `async`/`await` |
|---|---|---|
| Readability | Medium | Cleaner |
| Chaining | Required | Not needed |
| Error handling | `.catch()` | `try...catch` |
| Looks synchronous | No | Yes |
| Uses Promises internally | Yes | Yes |

> **Key idea:** `async`/`await` is built on top of Promises — it does not replace them. Under the hood, it is still the same Promise mechanism.

## Promise States — Visual Summary

```
new Promise(executor)
        │
        ▼
    [ Pending ]
        │
   ┌────┴────┐
   │         │
resolve()  reject()
   │         │
   ▼         ▼
[Fulfilled] [Rejected]
   │         │
then()    catch()
   └────┬────┘
        ▼
    finally()
```

## Summary

| Method | Triggered when | Use for |
|---|---|---|
| `then(onFulfilled)` | Promise fulfilled | Handling successful results |
| `then(onFulfilled, onRejected)` | Either outcome | Handling both in one call |
| `catch(onRejected)` | Promise rejected | Error handling |
| `finally(onFinally)` | Either outcome | Cleanup tasks (always runs) |

- A **promise** encapsulates the result of an async operation.
- It starts in **pending** and settles as **fulfilled** or **rejected** — and never changes after that.
- Use **`then()`** to handle success, **`catch()`** to handle errors, and **`finally()`** for code that must always run.
- **Promise chaining** replaces nested callbacks and keeps async code flat and readable.
- Each `.then()` returns a **new promise** — always `return` a value if you need the next `.then()` to receive it; otherwise it gets `undefined`.
- Arrow functions **without curly braces** have an **implicit return**, so `.then((x) => someFn(x))` automatically passes the result forward.
- **`async`/`await`** is syntactic sugar over Promises — it makes async code look synchronous and is generally cleaner than chaining.
- An **`async` function** always returns a Promise, even if you return a plain value.
- **`await`** pauses execution until a Promise settles — it can only be used inside an `async` function.
- Use **`try...catch`** with `await` instead of `.catch()` to handle rejections.
- Use **`Promise.all`** to run independent async tasks in parallel instead of sequentially.
- In practice, you will mostly **consume** promises returned by libraries and APIs rather than creating them from scratch.
