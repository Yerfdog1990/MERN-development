# JavaScript: globalThis, Window & Fetch API

---

## 1. JavaScript `globalThis`

### The Problem — Different Global Objects in Different Environments

Before ES2020, the global object had different names depending on where JavaScript was running:

| Environment | Global Object |
|---|---|
| Web Browsers | `window` or `frames` |
| Web Workers | `self` |
| Node.js | `global` |

This made it difficult to write JavaScript that worked consistently across environments — you'd have to check which environment you were in and use the appropriate name.

### The Solution — `globalThis`

ES2020 introduced `globalThis` as a standard, universal way to access the global object regardless of environment.

```js
// Works in browsers, Web Workers, and Node.js
const canFetch = typeof globalThis.fetch === 'function';
console.log(canFetch); // true (in modern browsers)
```

In a web browser, `globalThis` is the same as `window`:

```js
globalThis === window; // true
```

> **Key idea:** Use `globalThis` when writing code that needs to run across multiple environments and you need a reliable reference to the global object.

## 2. The `window` Object

### The `window` Object is Global

In web browsers, `window` is the global object. All variables and functions declared globally with `var` automatically become properties and methods of `window`:

```js
var counter = 1;
var showCounter = () => console.log({ counter });

console.log(window.counter);  // 1
window.showCounter();          // { counter: 1 }
```

> **Note:** To avoid polluting the `window` object, use `let` or `const` instead of `var` for global declarations.

---

### Window Size

The `window` object has four size-related properties:

- `innerWidth` / `innerHeight` — size of the viewport inside the browser (excludes borders and toolbars)
- `outerWidth` / `outerHeight` — size of the entire browser window

To safely get the viewport size across all browsers:

```js
const width = window.innerWidth
  || document.documentElement.clientWidth
  || document.body.clientWidth;

const height = window.innerHeight
  || document.documentElement.clientHeight
  || document.body.clientHeight;
```

---

### Opening a New Window

```js
window.open(url, windowName, [windowFeatures]);
```

- `url` — the page to load
- `windowName` — the name/target of the window
- `windowFeatures` — a comma-delimited string of settings (e.g. `width`, `height`)

```js
// Opens in a new tab
window.open('http://localhost/about.html', 'about');

// Opens in a new separate window (width + height specified)
window.open('http://localhost/about.html', 'about', 'height=600,width=800');
```

To load a new URL into an **existing** named window, pass the same window name:

```js
window.open('http://localhost/contact.html', 'about'); // reuses 'about' window
```

---

### Resizing a Window

```js
// Resize to exact dimensions
window.resizeTo(width, height);

// Resize by a relative amount (negative shrinks, positive grows)
window.resizeBy(deltaX, deltaY);
```

```js
const jsWindow = window.open('http://localhost/about.html', 'about', 'height=600,width=800');

setTimeout(() => {
  jsWindow.resizeTo(600, 300); // resize to 600x300 after 3 seconds
}, 3000);
```

---

### Moving a Window

```js
// Move to an absolute coordinate
window.moveTo(x, y);

// Move by a relative amount
window.moveBy(deltaX, deltaY);
```

```js
setTimeout(() => {
  jsWindow.moveTo(500, 500); // move to position (500, 500)
}, 3000);
```

---

### Closing a Window

```js
window.close();
```

```js
const jsWindow = window.open('http://localhost/about.html', 'about', 'height=600,width=600');

setTimeout(() => {
  jsWindow.close(); // close after 3 seconds
}, 3000);
```

---

### The `window.opener` Property

A window opened with `window.open()` can reference the window that opened it via `window.opener`. This allows the two windows to exchange data with each other.

---

### Window Methods — Quick Reference

| Method | Description |
|---|---|
| `window.open(url, name, features)` | Opens a new window or tab |
| `window.resizeTo(w, h)` | Resizes to exact dimensions |
| `window.resizeBy(dx, dy)` | Resizes by a relative amount |
| `window.moveTo(x, y)` | Moves to an absolute position |
| `window.moveBy(dx, dy)` | Moves by a relative amount |
| `window.close()` | Closes the window |

## 3. The Fetch API

### What is the Fetch API?

The Fetch API is a modern, built-in browser tool for making HTTP requests. It does everything the older `XMLHttpRequest` object can do, but with a much cleaner syntax built on top of Promises.

`fetch()` is a method of the global `window` object:

```js
fetch(url);
```

---

### Sending a Request

`fetch()` takes a URL and returns a **Promise** that resolves into a `Response` object:

```js
fetch(url)
  .then(response => {
    // handle the response
  })
  .catch(error => {
    // handle the error
  });
```

---

### Reading the Response

Use the `.json()` method on the `Response` object to parse JSON data. It returns a Promise:

```js
fetch(url)
  .then(response => response.json())  // parse JSON — returns a promise
  .then(data => console.log(data));   // receive parsed data
```

In practice, `async/await` is cleaner:

```js
const response = await fetch(url);
const data = await response.json();
console.log(data);
```

Other `Response` methods for different data types:

| Method | Use for |
|---|---|
| `.json()` | JSON data |
| `.text()` | Plain text |
| `.blob()` | Binary data (images, files) |
| `.formData()` | Form submissions |
| `.arrayBuffer()` | Raw binary buffers |

---

### Handling HTTP Status Codes

The `Response` object has a `status` property with the HTTP status code:

```js
const response = await fetch(url);
if (response.status === 200) {
  // success
}
```

In practice, use the `ok` property — it returns `true` if the status is in the 200–299 range:

```js
const response = await fetch(url);
if (!response.ok) {
  throw new Error(`HTTP error! Status: ${response.status}`);
}
```

> **Note:** `fetch()` only rejects the Promise on **network failures** (e.g. no internet connection). A 404 or 500 response still resolves — you must check `response.ok` manually.

---

### GET Request Example — Fetching a User List

**`index.html`:**

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <title>Fetch API Demo</title>
    <script src="js/app.js" defer></script>
  </head>
  <body>
    <div id="root">
      <div id="content"></div>
      <p id="message"></p>
      <p id="loading"></p>
    </div>
  </body>
</html>
```

Three elements inside `#root`:
- `#content` — renders the user list
- `#message` — shows error messages
- `#loading` — shows a loading indicator

**`js/app.js`:**

```js
const getUsers = async () => {
  const url = 'https://jsonplaceholder.typicode.com/users';
  const response = await fetch(url);
  return await response.json();
};

const render = (users) => {
  return users.map(({ name, email }) => `<li>${name} (${email})</li>`).join('');
};

(async () => {
  const users = await getUsers();
  document.querySelector('#content').innerHTML = `<ul>${render(users)}</ul>`;
})();
```

**How it works:**
1. `getUsers()` fetches the API endpoint and returns the parsed JSON array.
2. `render()` maps each user to an `<li>` HTML string.
3. The IIFE calls both functions and injects the result into the DOM.

---

### Handling Errors with `try...catch`

```js
(async () => {
  try {
    const users = await getUsers();
    document.querySelector('#content').innerHTML = `<ul>${render(users)}</ul>`;
  } catch (err) {
    document.querySelector('#message').textContent = err.message;
  }
})();
```

If a network error occurs (e.g. invalid URL), the `catch` block runs and displays the error message. You can test this by changing `.com` to `.net` in the URL.

---

### Displaying a Loading Indicator

For slow networks, show a "Loading..." message before the request and clear it once done — whether the request succeeded or failed. Use `finally` for the cleanup:

```js
(async () => {
  const loadingElem = document.querySelector('#loading');
  loadingElem.innerHTML = 'Loading...';

  try {
    const users = await getUsers();
    document.querySelector('#content').innerHTML = `<ul>${render(users)}</ul>`;
  } catch (err) {
    document.querySelector('#message').textContent = err.message;
  } finally {
    loadingElem.innerHTML = ''; // always clears loading message
  }
})();
```

To test the loading message, simulate a 2-second network delay:

```js
const delay = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
await delay(2000);
```

### POST Request Example — Creating a Blog Post

For a POST request, pass a second argument to `fetch()` with the method, headers, and body:

```js
async function create(blogPost) {
  try {
    const url = 'https://jsonplaceholder.typicode.com/posts';

    const headers = {
      'Content-Type': 'application/json',
    };

    const body = JSON.stringify({
      title: blogPost.title,
      body: blogPost.body,
      userId: blogPost.userId,
    });

    const response = await fetch(url, { method: 'POST', headers, body });

    if (!response.ok) {
      throw new Error(`HTTP error! Status: ${response.status}`);
    }

    const data = await response.json();
    console.log('Success:', data);

  } catch (error) {
    console.error('Error:', error);
  }
}

create({
  title: 'Test Post',
  body: 'This is a test post',
  userId: 1,
});
```

**Breaking down the `fetch()` options:**

| Option | Value | Purpose |
|---|---|---|
| `method` | `'POST'` | Specifies the HTTP method |
| `headers` | `{ 'Content-Type': 'application/json' }` | Tells the server the body is JSON |
| `body` | `JSON.stringify(data)` | The serialized request payload |

**How it works step by step:**
1. Build the URL, headers, and serialized body.
2. Call `fetch(url, { method, headers, body })` — returns a Promise.
3. Check `response.ok` — throw an error if the request failed.
4. Parse the response with `response.json()`.
5. The `catch` block handles any network or thrown errors.

---

### GET vs POST — Comparison

| | GET | POST |
|---|---|---|
| Purpose | Retrieve data | Send / create data |
| Body | None | JSON string via `JSON.stringify()` |
| Headers | Usually none needed | `'Content-Type': 'application/json'` |
| `fetch()` call | `fetch(url)` | `fetch(url, { method, headers, body })` |

---

### Summary

- The Fetch API is a simpler, Promise-based alternative to `XMLHttpRequest`.
- `fetch(url)` returns a Promise that resolves into a **Response** object.
- Use `response.ok` to check for success — `fetch()` does **not** reject on HTTP error codes like 404 or 500.
- Use `response.json()` to parse JSON responses (it also returns a Promise).
- Use `try...catch` for error handling and `finally` for cleanup like hiding a loading spinner.
- For POST requests, pass a second argument with `method`, `headers`, and a `JSON.stringify()`-ed `body`.
