# Difference Between Async and Defer Attributes in HTML

When a browser encounters a `<script>` tag while parsing an HTML document, it normally stops parsing the HTML, downloads the JavaScript file, executes it, and then resumes parsing the page. This behavior is known as **render blocking** because the browser cannot continue building the page until the script has finished loading and executing.

The **async** and **defer** attributes were introduced to solve this problem by allowing JavaScript files to be downloaded without blocking HTML parsing.

Both attributes improve webpage performance by loading JavaScript files in parallel with HTML parsing, but they differ in **when the scripts execute** and **whether execution order is guaranteed**.

---

# Why Do We Need Async and Defer?

Consider the following HTML:

```html
<!DOCTYPE html>
<html>
<head>
    <script src="script.js"></script>
</head>
<body>
    <h1>Hello World</h1>
</body>
</html>
```

### What Happens?

1. Browser starts parsing HTML.
2. Browser encounters `<script>`.
3. HTML parsing stops.
4. Browser downloads `script.js`.
5. Browser executes `script.js`.
6. Browser resumes HTML parsing.

```text
HTML Parsing
     ↓
Script Found
     ↓
STOP Parsing
     ↓
Download Script
     ↓
Execute Script
     ↓
Resume Parsing
```

This delay can slow down page rendering and negatively affect user experience.

To solve this issue, developers use:

* `async`
* `defer`

---

# What is the Async Attribute?

The **async** attribute tells the browser to download the script file in parallel with HTML parsing and execute it immediately once the download is complete.

The browser does not wait for HTML parsing to finish before running the script.

---

## Characteristics of Async

### Parallel Downloading

The script downloads while HTML parsing continues.

### Non-Blocking

HTML parsing is not blocked during the download.

### Immediate Execution

As soon as the script finishes downloading, it executes immediately.

### Execution Order Not Guaranteed

If multiple async scripts exist, they execute whenever each finishes downloading.

### Best for Independent Scripts

Suitable for scripts that do not depend on:

* The DOM
* Other scripts

---

# Syntax of Async

```html
<script src="script.js" async></script>
```

or

```html
<script async src="script.js"></script>
```

Both are equivalent.

---

# How Async Works

```text
HTML Parsing
     ↓
Download Script (Parallel)
     ↓
Script Finished Downloading
     ↓
Pause HTML Parsing
     ↓
Execute Script
     ↓
Resume Parsing
```

Visualization:

```text
HTML:  ────────────────▶

Script Download:
        ─────▶

Script Execute:
             ●
```

The script executes immediately after downloading, regardless of whether the HTML document is fully parsed.


---

# Advantages of Async

### Faster Page Loading

Scripts download without blocking HTML parsing.

### Better Performance

Especially useful for third-party scripts.

### Independent Execution

Works well for scripts that do not rely on page content.

---

# Disadvantages of Async

### Unpredictable Order

Multiple async scripts may execute in any order.

Example:

```html
<script async src="library.js"></script>
<script async src="app.js"></script>
```

Possible execution:

```text
app.js
library.js
```

or

```text
library.js
app.js
```

depending on network speed.

---

### DOM May Not Be Ready

The script may execute before the HTML document is fully built.

Example:

```javascript
document.getElementById("title");
```

may return:

```javascript
null
```

if the element has not yet been parsed.

---

# What is the Defer Attribute?

The **defer** attribute tells the browser to download the script while HTML parsing continues, but delays execution until the entire HTML document has been parsed.

Unlike async, deferred scripts always wait until the DOM is ready.

---

## Characteristics of Defer

### Parallel Downloading

Scripts download while HTML parsing continues.

### Non-Blocking

HTML parsing is never interrupted.

### Delayed Execution

Scripts execute only after parsing completes.

### Order Preserved

Scripts execute in the order they appear.

### DOM Ready

Scripts run after the document structure is available.

---

# Syntax of Defer

```html
<script src="script.js" defer></script>
```

or

```html
<script defer src="script.js"></script>
```

---

# How Defer Works

```text
Execute Script
```

```text
Script Download:
─────▶

```

Notice that execution waits until parsing is finished.

### DOM Is Ready

### Improved Page Performance

Downloads occur without blocking rendering.

# Multiple Scripts: Async vs Defer

Consider:

```html
<script async src="first.js"></script>
<script async src="second.js"></script>
```

Execution order:

```text
Unknown
```

Possible:

```text
second.js
first.js
```

or

```text
first.js
second.js
```

---

Now consider:

```html
<script defer src="first.js"></script>
<script defer src="second.js"></script>
```

Execution order:

```text
first.js
second.js
```

Always.


```text

```

Works correctly every time.

# Async vs Defer Comparison

| Async                                   | Defer                                   |
| --------------------------------------- | --------------------------------------- |
| Downloads in parallel                   | Downloads in parallel                   |
| Executes immediately after download     | Executes after HTML parsing completes   |
| HTML parsing may pause during execution | HTML parsing never pauses for execution |
| Execution order not guaranteed          | Execution order guaranteed              |
| May run before DOM is ready             | DOM is fully built before execution     |
| Best for independent scripts            | Best for DOM-dependent scripts          |
| Suitable for analytics and ads          | Suitable for application code           |
| Faster execution                        | More predictable execution              |

# When Should You Use Async?

Use async when:

✅ Script is independent

✅ Script does not manipulate the DOM

✅ Script does not depend on other scripts

Examples:

* Analytics
* Advertisements
* Tracking tools
* External widgets

```html
<script async src="analytics.js"></script>
```

---

# When Should You Use Defer?

Use defer when:

✅ Script accesses HTML elements

✅ Script depends on the DOM

✅ Multiple scripts depend on one another

Examples:

* Application logic
* Form validation
* Event handling
* DOM manipulation

```html
<script defer src="app.js"></script>
```

# Common Interview Question

Consider:

```html
<script async src="A.js"></script>
<script async src="B.js"></script>
```

Question:

Will `A.js` always execute before `B.js`?

Answer:

❌ No.

Execution depends on which file finishes downloading first.

---

Consider:

```html
<script defer src="A.js"></script>
<script defer src="B.js"></script>
```

Question:

Will `A.js` always execute before `B.js`?

Answer:

✅ Yes.

Deferred scripts always execute in document order.

---

# Key Points

* Both `async` and `defer` improve page performance by downloading scripts without blocking HTML parsing.
* `async` executes scripts immediately after download.
* `defer` waits until HTML parsing is complete before execution.
* Async scripts do not guarantee execution order.
* Deferred scripts maintain execution order.
* Async scripts may run before the DOM is ready.
* Deferred scripts always run after the DOM has been built.
* Use async for independent third-party scripts.
* Use defer for application scripts and DOM manipulation.

## Summary

The **async** and **defer** attributes are used with the HTML `<script>` tag to improve page performance by allowing JavaScript files to download while HTML parsing continues. The **async** attribute executes scripts immediately after downloading, making it ideal for independent scripts such as analytics and advertisements. The **defer** attribute delays execution until the HTML document has been fully parsed and preserves script order, making it the preferred choice for DOM manipulation and application logic. Understanding the difference between async and defer helps developers build faster, more efficient, and more reliable web applications.
