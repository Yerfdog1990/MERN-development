# JavaScript Promises

A **Promise** is an object that encapsulates the result of an asynchronous operation. It represents a value that may not be available yet but will be resolved at some point in the future — either successfully or with an error.

---

## Callbacks

### What is a Callback Function?

A **callback function** is a function passed as an argument to another function, to be executed later.

In the context of async operations, a callback is a function that runs **after** an async task completes — for example, after a timer fires, after data returns from an API, or after a DOM event is triggered.

```js
// setTimeout — callback runs after 1 second
setTimeout(() => {
  console.log('Timer done');
}, 1000);

// fetch — callback runs when API responds
fetch(url).then((response) => {
  // this is a callback
});

// DOM event — callback runs when button is clicked
button.addEventListener('click', () => {
  // this is a callback
});
```

---

### Why Callbacks Are Needed — The Async Problem

In synchronous code, functions run one after another and return values immediately:

```js
function getUsers() {
  return [
    { username: 'john', email: 'john@test.com' },
    { username: 'jane', email: 'jane@test.com' },
  ];
}

function findUser(username) {
  const users = getUsers();
  const user = users.find((user) => user.username === username);
  return user;
}

console.log(findUser('john'));
// { username: 'john', email: 'john@test.com' }
```

This works fine. But in the real world, `getUsers()` might fetch data from a server — an operation that takes time. Using `setTimeout` to simulate a 1-second delay breaks everything:

```js
function getUsers() {
  let users = [];

  setTimeout(() => {
    // This runs AFTER getUsers() has already returned
    users = [
      { username: 'john', email: 'john@test.com' },
      { username: 'jane', email: 'jane@test.com' },
    ];
  }, 1000);

  return users; // Returns empty array immediately
}

console.log(findUser('john')); // undefined
```

**Why it fails:** JavaScript doesn't wait. `getUsers()` returns the empty array immediately, before the timeout has a chance to populate it.

**The fix — pass a callback** that runs once the data is ready:

```js
function getUsers(callback) {
  setTimeout(() => {
    callback([
      { username: 'john', email: 'john@test.com' },
      { username: 'jane', email: 'jane@test.com' },
    ]);
  }, 1000);
}

function findUser(username, callback) {
  getUsers((users) => {
    const user = users.find((user) => user.username === username);
    callback(user);
  });
}

findUser('john', console.log);
// { username: 'john', email: 'john@test.com' }
```

### The Two Problems with Callbacks

Callbacks work, but they come with two significant problems.

---

#### Problem 1 — Callback Hell (Pyramid of Doom)

Real-world applications chain many API calls together — each one dependent on the result of the previous. Consider a hotel booking flow:

1. **BookApp hotel** → on success → proceed to payment
2. **Proceed to payment** → on success → show booking status
3. **Show booking status** → on success → update booking history

Each step is an API call. Each API call needs a callback to handle the response. Each callback nests inside the previous one:

```js
bookHotel(hotelId, (error, bookingResult) => {
  if (error) {
    handleError(error);
  } else {
    proceedToPayment(hotelId, amount, (error, paymentResult) => {
      if (error) {
        handleError(error);
      } else {
        showBookingStatus(bookingResult, (error, status) => {
          if (error) {
            handleError(error);
          } else {
            updateBookingHistory(status, (error, result) => {
              if (error) {
                handleError(error);
              } else {
                // success — finally done
              }
            });
          }
        });
      }
    });
  }
});
```

Notice how the code grows **horizontally** — each level of nesting pushes further to the right. Code should grow **vertically** (downward), not horizontally. This horizontal pyramid shape is why it's called the **Pyramid of Doom**.

This creates real problems:
- Difficult to read and understand
- Difficult to manage and maintain
- Difficult to track down errors
- A nightmare for other developers joining the codebase

---

#### Problem 2 — Inversion of Control

When you pass a callback into a function, the **execution of your callback is controlled by that function** — not by you. This is called **inversion of control**.

```js
bookHotel(hotelId, proceedToPayment);
//                  ^
//   you have handed control of this function
//   over to bookHotel — it decides if/when to call it
```

In normal code, you call your own functions when you want. With callbacks, you give up that control. The callback only runs when the outer function decides to call it.

This becomes a problem when:
- The outer function (e.g. a third-party API) is slow or stuck in an idle state
- The server is down or not responding — your callback never runs
- The outer function has a bug and never calls your callback
- You have no way to guarantee your code will execute

You have handed the keys to someone else.

---

### Why Promises? — The Solution

Promises were introduced to solve both of these problems:

- **Callback hell** → Promises use **chaining** (`.then().then()`) so code grows vertically, not horizontally
- **Inversion of control** → Promises give you back control — you attach handlers to the promise yourself, rather than passing your function in to be called by someone else

```js
// Callback hell version (horizontal)
bookHotel(id, (err, result) => {
  proceedToPayment(result, (err, payment) => {
    showBookingStatus(payment, (err, status) => {
      updateBookingHistory(status, () => { ... });
    });
  });
});

// Promise version (vertical — clean and readable)
bookHotel(id)
  .then((result) => proceedToPayment(result))
  .then((payment) => showBookingStatus(payment))
  .then((status) => updateBookingHistory(status))
  .catch((error) => handleError(error));
```

## Promises in Detail

---

## Understanding Promise States

A promise object can be in one of three states:

| State | Description |
|---|---|
| **Pending** | Initial state — the async operation is still in progress |
| **Fulfilled** | The async operation completed successfully — has a resolved value |
| **Rejected** | The async operation failed — has an error reason |

**Key rules:**
- A promise starts in `pending`.
- It can only transition to either `fulfilled` or `rejected` — never both.
- Once settled (fulfilled or rejected), it **cannot change state again**.

```
Pending  →  Fulfilled (resolve called)
Pending  →  Rejected  (reject called)
```

---

## Creating a Promise

Use the `Promise()` constructor, which accepts an **executor function**. The executor receives two callbacks: `resolve` and `reject`.

```js
const promise = new Promise((resolve, reject) => {
  // Perform an async operation...

  if (/* success */) {
    resolve(value);   // Moves state to fulfilled
  } else {
    reject(error);    // Moves state to rejected
  }
});
```

### Example — Basic Promise

```js
const promise = new Promise((resolve, reject) => {
  setTimeout(() => {
    const success = true;

    if (success) {
      resolve('Operation completed successfully!');
    } else {
      reject('Something went wrong.');
    }
  }, 1000);
});
```

- The executor runs immediately when the promise is created.
- After 1 second, if `success` is `true`, the promise is **fulfilled** with the string value.
- If `success` is `false`, it is **rejected** with an error message.

## Consuming a Promise

### 1. The `then()` Method

`then()` is called when a promise is **fulfilled**. It accepts two optional callbacks: `onFulfilled` and `onRejected`.

```js
promise.then(onFulfilled, onRejected);
```

**Example:**

```js
function getUsers() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      resolve([
        { username: 'john', email: 'john@test.com' },
        { username: 'jane', email: 'jane@test.com' },
      ]);
    }, 1000);
  });
}

// Using named functions
function onFulfilled(users) {
  console.log(users);
}

const promise = getUsers();
promise.then(onFulfilled);

// Output (after 1 second):
// [
//   { username: 'john', email: 'john@test.com' },
//   { username: 'jane', email: 'jane@test.com' }
// ]
```

**Using arrow functions (more concise):**

```js
getUsers().then((users) => {
  console.log(users);
});
```

---

### Handling Both Fulfilled and Rejected in `then()`

Pass both `onFulfilled` and `onRejected` as arguments to `then()`:

```js
let success = true;

function getUsers() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (success) {
        resolve([
          { username: 'john', email: 'john@test.com' },
          { username: 'jane', email: 'jane@test.com' },
        ]);
      } else {
        reject('Failed to fetch the user list.');
      }
    }, 1000);
  });
}

function onFulfilled(users) {
  console.log('Users:', users);
}

function onRejected(error) {
  console.log('Error:', error);
}

getUsers().then(onFulfilled, onRejected);

// If success = true  → Users: [ { username: 'john', ... }, ... ]
// If success = false → Error: Failed to fetch the user list.
```

---

### 2. The `catch()` Method

`catch()` handles only **rejected** promises. It is shorthand for `.then(undefined, onRejected)` and is the preferred way to handle errors.

```js
promise.catch(onRejected);
```

**Example:**

```js
let success = false;

function getUsers() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (success) {
        resolve([
          { username: 'john', email: 'john@test.com' },
          { username: 'jane', email: 'jane@test.com' },
        ]);
      } else {
        reject('Failed to fetch the user list.');
      }
    }, 1000);
  });
}

getUsers()
  .then((users) => {
    console.log(users);
  })
  .catch((error) => {
    console.log('Caught error:', error);
    // Caught error: Failed to fetch the user list.
  });
```

**Why use `catch()` instead of the second argument of `then()`?**

Using a separate `catch()` at the end of a chain catches errors from **any** `then()` in the chain, not just the last one. It is cleaner and easier to manage.

---

### 3. The `finally()` Method

`finally()` runs a callback **regardless** of whether the promise was fulfilled or rejected. It is useful for cleanup tasks like hiding a loading spinner or closing a database connection.

**Without `finally()` — duplicated code:**

```js
const render = () => console.log('Rendering UI...');

getUsers()
  .then((users) => {
    console.log(users);
    render(); // Duplicated
  })
  .catch((error) => {
    console.log(error);
    render(); // Duplicated
  });
```

**With `finally()` — clean and DRY:**

```js
const render = () => console.log('Rendering UI...');

getUsers()
  .then((users) => {
    console.log(users);
  })
  .catch((error) => {
    console.log(error);
  })
  .finally(() => {
    render(); // Always runs — fulfilled or rejected
  });
```

## Promise Chaining

Because `then()` returns a new promise, you can **chain** multiple async operations sequentially. This eliminates callback hell.

```js
function getUsers() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve([
        { username: 'john', email: 'john@test.com' },
        { username: 'jane', email: 'jane@test.com' },
      ]);
    }, 1000);
  });
}

function findUser(users, username) {
  return new Promise((resolve, reject) => {
    const user = users.find((u) => u.username === username);
    if (user) {
      resolve(user);
    } else {
      reject(`User '${username}' not found.`);
    }
  });
}

// Chaining promises
getUsers()
  .then((users) => findUser(users, 'john'))
  .then((user) => {
    console.log('Found user:', user);
    // Found user: { username: 'john', email: 'john@test.com' }
  })
  .catch((error) => {
    console.log('Error:', error);
  })
  .finally(() => {
    console.log('Done.');
  });
```

**How it works:**
1. `getUsers()` resolves with a user array after 1 second.
2. The first `then()` receives the users and calls `findUser()`, returning a new promise.
3. The second `then()` receives the matched user and logs it.
4. `catch()` handles any rejection from any step in the chain.
5. `finally()` always runs last.

## Returning Values in `.then()` Chains

### The Problem — Forgetting to Return

After a `.then()` that doesn't return anything, the **next** `.then()` receives `undefined`, not the previous value.

```js
getUsers()
  .then((users) => findUser(users, 'john'))
  .then((user) => {
    console.log('Found user:', user);
    // ❌ No return here — user is lost
  })
  .then((user) => {
    console.log('Username:', user.username); // ❌ TypeError: Cannot read properties of undefined
  });
```

**Fix it by returning the value each time you want to pass it forward:**

```js
getUsers()
  .then((users) => findUser(users, 'john'))

  .then((user) => {
    console.log('Found user:', user);
    return user; // ✅ pass to next then()
  })

  .then((user) => {
    console.log('Username:', user.username);
    return user; // ✅ pass again
  })

  .then((user) => {
    console.log('Email:', user.email);
  })

  .catch((error) => {
    console.log('Error:', error);
  })

  .finally(() => {
    console.log('Done.');
  });
```

### The Rule

Each `.then()` receives:
- The **resolved value** from the original promise, or
- The **value returned** by the previous `.then()`

If nothing is returned, the next `.then()` gets `undefined`.

| What you return | What the next `.then()` receives |
|---|---|
| A value (`return user`) | That value |
| A promise (`return fetchData(x)`) | The resolved value of that promise |
| Nothing | `undefined` |
| Throws an error | Jumps to `.catch()` |

**Visual flow:**

```
Promise -> then(user) -> return user
                     ↓
               then(user) -> return user
                     ↓
               then(user)
```

---

### Implicit Returns in Arrow Functions

Arrow functions **without curly braces** have an implicit return — they return the expression automatically.

So this:

```js
.then((users) => findUser(users, 'john'))
```

is exactly equivalent to:

```js
.then((users) => {
  return findUser(users, 'john');
})
```

This is why the first `.then()` in the chaining example doesn't need an explicit `return` keyword — the concise arrow function syntax returns `findUser(...)` implicitly.

**Full chain flow explained:**

```
getUsers() resolves with users array
        ↓
first then() returns findUser(...)   ← implicit return via arrow function
        ↓
findUser resolves with user object
        ↓
next then(user) receives user
```

---

### Return Patterns — Examples

```js
// Return a value — next then() receives x + 1
.then((x) => x + 1)

// Return a promise — next then() receives the resolved value of fetchData(x)
.then((x) => fetchData(x))

// Return nothing — next then() receives undefined
.then((x) => {
  console.log(x);
})
```

**Demonstrating the difference:**

```js
// ✅ Works — users passed to second then()
getUsers()
  .then((users) => {
    console.log(users);
    return users;
  })
  .then((users) => {
    console.log('Second then:', users); // receives users
  });

// ❌ Breaks — second then() gets undefined
getUsers()
  .then((users) => {
    console.log(users);
    // no return
  })
  .then((users) => {
    console.log(users); // undefined
  });
```

> **Key idea:** Each `.then()` returns a **new promise**. If you return a value, the next `.then()` receives it. If you return nothing, the next `.then()` gets `undefined`. If you throw an error, execution jumps to `.catch()`.

## Practical Example — Loading JSON from a Server

The following example loads a JSON file from a server using `XMLHttpRequest` wrapped in a Promise.

**HTML:**

```html
<!DOCTYPE html>
<html>
<head>
  <title>JavaScript Promise Demo</title>
</head>
<body>
  <div id="message"></div>
  <button id="btnGet">Get Message</button>
  <script src="promise-demo.js"></script>
</body>
</html>
```

**`promise-demo.js`:**

```js
// Wraps XMLHttpRequest in a Promise
function load(url) {
  return new Promise(function (resolve, reject) {
    const request = new XMLHttpRequest();

    request.onreadystatechange = function () {
      if (this.readyState === 4 && this.status === 200) {
        resolve(this.response); // Success — resolve with the response
      } else if (this.readyState === 4) {
        reject(this.status);    // Failure — reject with HTTP status code
      }
    };

    request.open('GET', url, true);
    request.send();
  });
}

const url = 'https://www.javascripttutorial.net/sample/promise/api.json';
const btn = document.querySelector('#btnGet');
const msg = document.querySelector('#message');

btn.addEventListener('click', () => {
  load(url)
    .then((response) => {
      const result = JSON.parse(response);
      msg.innerHTML = result.message; // Display message from JSON
    })
    .catch((error) => {
      msg.innerHTML = `Error getting the message, HTTP status: ${error}`;
    });
});
```

**How it works:**

1. When the button is clicked, `load(url)` is called and returns a promise.
2. The executor creates an `XMLHttpRequest` and sends a `GET` request.
3. If the server responds with HTTP status `200`, `resolve()` is called with the response data.
4. If it fails, `reject()` is called with the HTTP status code.
5. `then()` parses the JSON and displays the message on the page.
6. `catch()` displays a friendly error message if the request fails.

## Quick Reference — `then`, `catch`, `finally`

```js
someAsyncOperation()
  .then((result) => {
    // Runs if the promise is fulfilled
    console.log('Success:', result);
  })
  .catch((error) => {
    // Runs if the promise is rejected (from any step in the chain)
    console.log('Error:', error);
  })
  .finally(() => {
    // Always runs — regardless of outcome
    console.log('Finished.');
  });
```

## Creating Your Own Promise

In practice you mostly consume promises returned by APIs and libraries like `fetch`. But you can also create your own using the `Promise` constructor.

### The `new Promise()` Constructor

The constructor takes an **executor function** with two parameters: `resolve` and `reject`.

```js
const promise = new Promise((resolve, reject) => {
  const isRequestSuccessful = true;

  if (isRequestSuccessful) {
    resolve('Promise resolved'); // fulfills the promise
  } else {
    const error = new Error('Something went wrong');
    reject(error); // rejects the promise
  }
});
```

- Call `resolve(value)` when the operation succeeds — the promise moves to **fulfilled**
- Call `reject(error)` when something goes wrong — the promise moves to **rejected**
- Use `new Error('message')` when rejecting, so you get both the message and a stack trace

### Simulating an Async Operation

Wrap the resolve/reject in `setTimeout` to simulate a delayed response, like a real API call:

```js
const promise = new Promise((resolve, reject) => {
  setTimeout(() => {
    resolve('Promise resolved after 3 seconds');
  }, 3000);
});

promise
  .then((response) => {
    console.log(response); // Promise resolved after 3 seconds
  })
  .catch((error) => {
    console.log(error.message);
  });
```

When you call `new Promise()` there is no async operation involved (unlike `fetch`), so the state moves to fulfilled/rejected synchronously if there is no `setTimeout`. The promise only shows as **pending** when there is a genuine delay.

### Passing Data Through `resolve`

Whatever you pass to `resolve()` becomes the value received by `.then()`:

```js
const db = [
  { id: 1, name: 'John' },
  { id: 2, name: 'Jane' },
];

const promise = new Promise((resolve, reject) => {
  setTimeout(() => {
    resolve(db); // passes the array to .then()
  }, 3000);
});

promise.then((data) => {
  console.log(data); // [{ id: 1, name: 'John' }, { id: 2, name: 'Jane' }]
});
```

### Handling Rejection with `catch`

```js
const promise = new Promise((resolve, reject) => {
  setTimeout(() => {
    const error = new Error('Something went wrong');
    reject(error);
  }, 3000);
});

promise
  .then((response) => {
    console.log(response);
  })
  .catch((error) => {
    console.log(error.message); // Something went wrong
  });
```

> **Note:** In the executor function, the first parameter is always `resolve` and the second is `reject`. If you only need `reject`, use an underscore for the unused first parameter: `(_, reject) => { ... }`

## Promise Static APIs

The `Promise` object has several static methods for working with multiple promises at once.

### `Promise.all()`

Takes an **array of promises** and returns a single promise that:
- **Resolves** with an array of all values — only when **every** promise in the array is fulfilled
- **Rejects** immediately with the error from the first rejected promise — ignoring the rest

```js
const promise1 = new Promise((resolve) => setTimeout(() => resolve('Promise 1 resolved'), 1000));
const promise2 = new Promise((resolve) => setTimeout(() => resolve('Promise 2 resolved'), 2000));
const promise3 = new Promise((resolve) => setTimeout(() => resolve('Promise 3 resolved'), 3000));

Promise.all([promise1, promise2, promise3])
  .then((results) => {
    console.log(results);
    // ['Promise 1 resolved', 'Promise 2 resolved', 'Promise 3 resolved']
  })
  .catch((error) => {
    console.log(error); // runs if any single promise rejects
  });
```

**Order is preserved** — results are returned in the same order as the input array, regardless of which promise resolves first.

**If any promise rejects:**

```js
const promises = [
  new Promise((resolve) => setTimeout(() => resolve('Resolved'), 1000)),
  new Promise((_, reject) => setTimeout(() => reject('Promise 2 rejected'), 2000)),
  new Promise((resolve) => setTimeout(() => resolve('Resolved'), 3000)),
];

Promise.all(promises)
  .then((results) => console.log(results))
  .catch((error) => console.log(error)); // Promise 2 rejected
```

Promise 3 still executes and settles internally, but its result is ignored — the overall result is the error from the rejected promise.

**Real-world use — fetching multiple GitHub profiles in parallel:**

```js
const users = ['user1', 'user2'];

const arrayOfPromises = users.map((user) =>
  fetch(`https://api.github.com/users/${user}`)
);

Promise.all(arrayOfPromises)
  .then((responses) => {
    responses.forEach((res) => console.log(res.url, res.status));
  })
  .catch((error) => {
    console.log(error.message);
  });
```

---

### `Promise.allSettled()`

Takes an array of promises and **always resolves** — waiting for every promise to settle (either fulfilled or rejected). Returns an array of result objects, each with a `status` and either a `value` (fulfilled) or `reason` (rejected).

```js
const promises = [
  new Promise((resolve) => setTimeout(() => resolve('Promise 1 resolved'), 1000)),
  new Promise((_, reject) => setTimeout(() => reject('Promise 2 rejected'), 2000)),
  new Promise((resolve) => setTimeout(() => resolve('Promise 3 resolved'), 3000)),
];

Promise.allSettled(promises).then((results) => {
  results.forEach((result) => console.log(result));
});

// { status: 'fulfilled', value: 'Promise 1 resolved' }
// { status: 'rejected',  reason: 'Promise 2 rejected' }
// { status: 'fulfilled', value: 'Promise 3 resolved' }
```

**When to use `allSettled` vs `all`:**

| | `Promise.all` | `Promise.allSettled` |
|---|---|---|
| Waits for | All to fulfill | All to settle (either outcome) |
| If one rejects | Immediately rejects | Continues, captures all results |
| Result shape | Array of values | Array of `{ status, value/reason }` objects |
| Use when | You need all results or nothing | You want to inspect every outcome |

---

### `Promise.race()`

Takes an array of promises and resolves or rejects with the **first promise to settle** — regardless of whether it is fulfilled or rejected.

```js
const promise1 = new Promise((resolve) => setTimeout(() => resolve('Promise 1'), 3000));
const promise2 = new Promise((resolve) => setTimeout(() => resolve('Promise 2'), 2000));
const promise3 = new Promise((resolve) => setTimeout(() => resolve('Promise 3'), 1000));

Promise.race([promise1, promise2, promise3]).then((result) => {
  console.log(result); // Promise 3  (resolves after 1 second — fastest)
});
```

The remaining promises still execute internally, but their results are ignored.

---

### `Promise.any()`

Takes an array of promises and resolves with the **first promise to be fulfilled** (not just settled). It ignores rejections unless **all** promises reject.

```js
const promise1 = new Promise((resolve) => setTimeout(() => resolve('Promise 1'), 3000));
const promise2 = new Promise((resolve) => setTimeout(() => resolve('Promise 2'), 2000));
const promise3 = new Promise((resolve) => setTimeout(() => resolve('Promise 3'), 1000));

Promise.any([promise1, promise2, promise3]).then((result) => {
  console.log(result); // Promise 3  (fulfilled first)
});
```

**`Promise.race` vs `Promise.any`:**

| | `Promise.race` | `Promise.any` |
|---|---|---|
| Triggers on | First **settled** (fulfilled or rejected) | First **fulfilled** only |
| If first to settle is rejected | Rejects immediately | Ignores it, waits for fulfilled |
| If all reject | Rejects | Rejects with `AggregateError` |

---

### `Promise.resolve()` and `Promise.reject()`

Two shorthand methods for creating already-settled promises without the `new Promise()` constructor.

**`Promise.resolve(value)`** — returns a promise that is immediately fulfilled with the given value:

```js
Promise.resolve('Immediate success')
  .then((value) => console.log(value)); // Immediate success
```

**`Promise.reject(reason)`** — returns a promise that is immediately rejected with the given reason:

```js
Promise.reject('Immediate failure')
  .catch((error) => console.error(error)); // Immediate failure
```

These are commonly used in testing, or when you need to return a promise from a function but already have the value:

```js
function getUser(id) {
  if (!id) return Promise.reject(new Error('No ID provided'));
  return fetch(`/api/users/${id}`);
}
```

### Promise Static APIs — Summary Table

| Method | Resolves when | Rejects when | Result |
|---|---|---|---|
| `Promise.all` | All promises fulfilled | Any one rejects | Array of values |
| `Promise.allSettled` | All promises settle | Never rejects | Array of `{ status, value/reason }` |
| `Promise.race` | First promise settles | First promise rejects | Single value or error |
| `Promise.any` | First promise fulfills | All promises reject | Single value or `AggregateError` |
| `Promise.resolve` | Immediately | Never | Fulfilled with given value |
| `Promise.reject` | Never | Immediately | Rejected with given reason |

## Advanced Chaining Patterns

### Error Handling Inside a Chain

When an error is thrown inside a `.then()`, execution skips all subsequent `.then()` blocks and jumps directly to `.catch()`:

```js
Promise.resolve(5)
  .then((num) => {
    console.log(`Value: ${num}`); // Value: 5
    throw new Error('Something went wrong!');
  })
  .then((num) => {
    console.log('This will never run'); // ❌ skipped
  })
  .catch((error) => {
    console.error(`Error: ${error.message}`); // Error: Something went wrong!
  });
```

The `.catch()` at the end acts as a safety net for the entire chain — any rejection or thrown error from any `.then()` will flow down to it.

---

### Dependent Task Chaining

Each `.then()` can pass its result to the next step. This is ideal when each async operation depends on the output of the previous one:

```js
function fetchUser(userId) {
  return Promise.resolve({ id: userId, name: 'John' });
}

function fetchOrders(user) {
  return Promise.resolve([{ orderId: 1, userId: user.id }]);
}

fetchUser(101)
  .then((user) => {
    console.log(`User: ${user.name}`); // User: John
    return fetchOrders(user);          // pass user to next step
  })
  .then((orders) => {
    console.log(`Orders: ${orders.length}`); // Orders: 1
  })
  .catch((error) => console.error(error));
```

Returning a Promise from `.then()` ensures the next `.then()` waits for that Promise to settle before executing.

---

### Wrapping Callbacks into Promises

Older APIs and libraries use callbacks instead of returning promises. You can wrap them to make them work in a promise chain:

```js
// Old callback-based function
function loadData(callback) {
  setTimeout(() => callback('Data loaded'), 1000);
}

// Wrap it in a promise
function loadDataAsPromise() {
  return new Promise((resolve) => {
    loadData((result) => resolve(result));
  });
}

loadDataAsPromise().then((data) => console.log(data)); // Data loaded
```

This pattern is called **promisification** — converting a callback-based function into one that returns a Promise.

---

### Sequential Execution with `reduce()`

For running an array of async tasks one after another (not in parallel), use `Array.reduce()` to chain them:

```js
const tasks = [1, 2, 3];

tasks.reduce((prevPromise, current) => {
  return prevPromise.then(() => {
    return new Promise((resolve) => {
      console.log(`Processing task ${current}`);
      setTimeout(resolve, 500);
    });
  });
}, Promise.resolve());

// Processing task 1
// Processing task 2  (after 500ms)
// Processing task 3  (after another 500ms)
```

Each task only starts after the previous one finishes. `Promise.resolve()` is the starting value — an already-resolved promise that kicks off the chain.

---

`async` and `await` are syntactic sugar built on top of Promises. They let you write asynchronous code that reads like synchronous code — no chaining, no callbacks.

---

### 1. `async` Functions

Marking a function with `async` makes it always return a Promise — even if you return a plain value:

```js
async function greet() {
  return 'Hello';
}

greet().then((message) => {
  console.log(message); // Hello
});
```

JavaScript automatically wraps the returned string in a resolved Promise. The above is equivalent to:

```js
function greet() {
  return Promise.resolve('Hello');
}
```

---

### 2. `await`

`await` pauses execution inside an `async` function until the Promise settles, then gives you the resolved value directly.

```js
function getUser() {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve('John');
    }, 2000);
  });
}

async function displayUser() {
  console.log('Loading...');
  const user = await getUser(); // pauses here until resolved
  console.log(user);
}

displayUser();
// Loading...
// John  (after 2 seconds)
```

**Comparing the two styles:**

```js
// With .then()
getUser().then((user) => {
  console.log(user);
});

// With await — cleaner
const user = await getUser();
console.log(user);
```

> **Rule:** `await` can only be used inside an `async` function. Using it at the top level (outside any function) is invalid unless you are in a module that supports top-level `await`.

---

### 3. Error Handling with `try...catch`

When a Promise rejects, `await` throws the error — catch it with `try...catch`:

```js
function login(success) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (success) {
        resolve('Login successful');
      } else {
        reject('Invalid credentials');
      }
    }, 1000);
  });
}

async function authenticate() {
  try {
    const result = await login(false);
    console.log(result);
  } catch (error) {
    console.log('Error:', error);
    // Error: Invalid credentials
  }
}

authenticate();
```

This replaces `.catch()` at the end of a chain with a standard `try...catch` block.

---

### 4. Multiple `await`s

You can use multiple `await` statements in sequence — each one waits for the previous to finish:

```js
function step1() {
  return Promise.resolve('Step 1 complete');
}

function step2() {
  return Promise.resolve('Step 2 complete');
}

async function runSteps() {
  const result1 = await step1();
  console.log(result1); // Step 1 complete

  const result2 = await step2();
  console.log(result2); // Step 2 complete
}

runSteps();
```

---

### 5. Parallel Execution with `Promise.all`

Sequential `await`s run one after another — if both take 2 seconds, the total is 4 seconds:

```js
// Sequential — slow (4 seconds total)
const a = await task1(); // waits 2s
const b = await task2(); // waits another 2s
```

When tasks are independent of each other, run them in **parallel** using `Promise.all`:

```js
// Parallel — fast (2 seconds total)
const [a, b] = await Promise.all([task1(), task2()]);
```

**Example:**

```js
function fetchUsers() {
  return new Promise((resolve) => {
    setTimeout(() => resolve(['John', 'Jane']), 2000);
  });
}

function fetchPosts() {
  return new Promise((resolve) => {
    setTimeout(() => resolve(['Post 1', 'Post 2']), 2000);
  });
}

async function loadData() {
  const [users, posts] = await Promise.all([
    fetchUsers(),
    fetchPosts(),
  ]);

  console.log(users); // ['John', 'Jane']
  console.log(posts); // ['Post 1', 'Post 2']
}

loadData();
// Both finish in ~2 seconds instead of ~4 seconds
```

---

### Promise Chaining vs `async`/`await` — Comparison

**Promise chaining:**

```js
getUser()
  .then((user) => getPosts(user))
  .then((posts) => console.log(posts))
  .catch((error) => console.log(error));
```

**`async`/`await`:**

```js
async function run() {
  try {
    const user = await getUser();
    const posts = await getPosts(user);
    console.log(posts);
  } catch (error) {
    console.log(error);
  }
}
```

| Feature | Promise `.then()` | `async`/`await` |
|---|---|---|
| Readability | Medium | Cleaner |
| Chaining | Required | Not needed |
| Error handling | `.catch()` | `try...catch` |
| Looks synchronous | No | Yes |
| Uses Promises internally | Yes | Yes |

> **Key idea:** `async`/`await` is built on top of Promises — it does not replace them. Under the hood, it is still the same Promise mechanism.

## Summary

| Method | Triggered when | Use for |
|---|---|---|
| `then(onFulfilled)` | Promise fulfilled | Handling successful results |
| `then(onFulfilled, onRejected)` | Either outcome | Handling both in one call |
| `catch(onRejected)` | Promise rejected | Error handling |
| `finally(onFinally)` | Either outcome | Cleanup tasks (always runs) |

- A **callback function** is a function passed as an argument to another function, executed after an async operation completes.
- **Callback hell** occurs when callbacks nest inside callbacks, making code grow horizontally and become hard to read and maintain — also called the **Pyramid of Doom**.
- **Inversion of control** is when you hand the execution of your own function over to an external function (like an API), losing the guarantee it will ever run.
- A **promise** encapsulates the result of an async operation.
- It starts in **pending** and settles as **fulfilled** or **rejected** — and never changes after that.
- Use **`then()`** to handle success, **`catch()`** to handle errors, and **`finally()`** for code that must always run.
- **Promise chaining** replaces nested callbacks and keeps async code flat and readable.
- Each `.then()` returns a **new promise** — always `return` a value if you need the next `.then()` to receive it; otherwise it gets `undefined`.
- Arrow functions **without curly braces** have an **implicit return**, so `.then((x) => someFn(x))` automatically passes the result forward.
- **`async`/`await`** is syntactic sugar over Promises — it makes async code look synchronous and is generally cleaner than chaining.
- An **`async` function** always returns a Promise, even if you return a plain value.
- **`await`** pauses execution until a Promise settles — it can only be used inside an `async` function.
- Use **`try...catch`** with `await` instead of `.catch()` to handle rejections.
- Use **`Promise.all`** to run independent async tasks in parallel — resolves when all fulfill, rejects if any one fails.
- Use **`Promise.allSettled`** when you want the outcome of every promise regardless of success or failure.
- Use **`Promise.race`** to get the result of whichever promise settles first.
- Use **`Promise.any`** to get the result of whichever promise fulfills first, ignoring rejections.
- **`Promise.resolve(value)`** and **`Promise.reject(reason)`** create already-settled promises instantly — useful for testing or early returns.
- Throwing inside a `.then()` skips all following `.then()` blocks and jumps directly to `.catch()`.
- **Promisification** is the pattern of wrapping callback-based functions inside a `new Promise()` to make them chainable.
- Use `Array.reduce()` with promises to run async tasks **sequentially** rather than in parallel.
- In practice, you will mostly **consume** promises returned by libraries and APIs rather than creating them from scratch.
