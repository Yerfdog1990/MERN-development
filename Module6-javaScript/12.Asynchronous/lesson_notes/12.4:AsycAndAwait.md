# Async and Await

`async` and `await` are an elegant way of writing Promises. They do not replace Promises — they are built on top of them. Instead of chaining `.then()` and `.catch()`, you write async code that reads like normal synchronous code.

---

## `async`

Adding the `async` keyword before any function makes it an **async function**. An async function always returns a **Promise**, even if you return a plain value.

```js
async function returnSomething() {
  return 'prakash';
}

const result = returnSomething();
console.log(result); // Promise { 'prakash' }  ← not 'prakash' directly
```

Even though you returned a string, JavaScript automatically wraps it in a fulfilled Promise. To get the actual value, you would still use `.then()`:

```js
returnSomething().then((value) => console.log(value)); // prakash
```

Compare with a regular function:

```js
function returnSomething() {
  return 'prakash';
}

const result = returnSomething();
console.log(result); // prakash  ← plain string
```

> **Key idea:** In front of any function, `async` makes the return value become a Promise. The function is now an asynchronous function.

---

## `await`

`await` can only be used **inside an `async` function**. It pauses the execution of the function on that line until the Promise settles (either fulfilled or rejected), then resumes and gives you the resolved value.

```js
async function showResponse() {
  const promise = new Promise((resolve) => {
    resolve('done');
  });

  const result = await promise; // pauses here until promise settles
  console.log(result);          // done
}

showResponse();
```

Without `await`, you would have to chain `.then()`:

```js
promise.then((result) => console.log(result));
```

With `await`, it becomes a single, clean line — no chaining needed.

> **Important:** When `await` pauses function execution, it does **not** block the entire JavaScript engine. JavaScript continues executing other code normally. Only the execution of that specific `async` function is paused at that line.

### Execution Order Example

This demonstrates that `await` only pauses the function — not the rest of the program:

```js
const getData = async () => {
  let y = await Promise.resolve('Hello World');
  console.log(y);
};

console.log(1);
getData();
console.log(2);

// Output:
// 1
// 2
// Hello World
```

`1` and `2` are logged first because `getData()` hits `await` and pauses — JavaScript immediately moves on to `console.log(2)`. Once the Promise resolves, `getData()` resumes and logs `'Hello World'`.

## Using `await` with `fetch`

The most common real-world use of `async`/`await` is fetching data from an API. Recall that `fetch` returns a Promise, and `response.json()` also returns a Promise — so both need to be awaited.

**With `.then()` chaining (old way):**

```js
fetch(url)
  .then((response) => response.json())
  .then((data) => console.log(data))
  .catch((error) => console.log(error));
```

**With `async`/`await` (clean way):**

```js
const getUserData = async () => {
  try {
    const response = await fetch(url); // wait for the HTTP response
    const data = await response.json(); // wait for JSON parsing
    console.log(data);
  } catch (error) {
    console.log('Error occurred:', error);
  }
};

getUserData();
```

Each line with `await` waits for that Promise to settle before moving to the next line. The code reads top-to-bottom, just like synchronous code.

You can also write it more concisely by chaining directly:

```js
const getUserData = async () => {
  try {
    const data = await fetch(url).then((res) => res.json());
    console.log(data);
  } catch (error) {
    console.log('Error occurred:', error);
  }
};
```

Or even in two clean awaits:

```js
const getUserData = async () => {
  try {
    const response = await fetch(url);
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.log('Error occurred:', error);
  }
};
```

> **Note:** With `fetch`, you must explicitly convert the response to JSON with `response.json()`. Libraries like Axios do this automatically.

## Error Handling with `try...catch`

With `.then()` chaining, errors are handled with `.catch()`. With `async`/`await`, errors are handled with `try...catch` — the standard JavaScript error handling mechanism.

```js
async function authenticate() {
  try {
    const result = await login(false); // this promise rejects
    console.log(result);
  } catch (error) {
    console.log('Error occurred:', error); // caught here
  }
}
```

If you use `await` without `try...catch` and the Promise rejects, you get an **uncaught Promise rejection** error. Always wrap `await` calls in `try...catch`.

```js
// ❌ No error handling — uncaught rejection if promise rejects
const data = await fetch(url);

// ✅ With try...catch
try {
  const data = await fetch(url);
} catch (error) {
  console.log(error);
}
```

### Line-by-Line Breakdown

```js
async function fetchData() {
  try {
    let response = await fetch('https://api.example.com/data');
    let data = await response.json();
    console.log(data);
  } catch (error) {
    console.error('Error fetching data:', error);
  }
}
```

| Line | What it does |
|---|---|
| `async function fetchData()` | Declares an async function — always returns a Promise |
| `await fetch(...)` | Sends an HTTP request and waits for the response without blocking the main thread |
| `await response.json()` | Converts the response body into JavaScript data (JSON format) — also returns a Promise, so needs `await` |
| `console.log(data)` | Prints the fetched data if the request is successful |
| `catch (error)` | Catches any error — network failure, invalid response, or a rejected Promise from either `await` |

## `async` Arrow Functions

`async` works with all function syntaxes, including arrow functions:

```js
// Regular async function
async function getUserData() {
  const response = await fetch(url);
  const data = await response.json();
  return data;
}

// Async arrow function — same thing
const getUserData = async () => {
  const response = await fetch(url);
  const data = await response.json();
  return data;
};
```

---

## The `await` Rule

`await` can only be used inside an `async` function. Using it outside will throw a syntax error:

```js
// ❌ Invalid — await outside async function
const data = await fetchData();

// ✅ Valid — inside an async function
async function run() {
  const data = await fetchData();
}
```

## Promises vs `async`/`await` — Side by Side

```js
// Promise .then() chaining
function getUserData() {
  fetch(url)
    .then((response) => response.json())
    .then((data) => {
      console.log(data);
    })
    .catch((error) => {
      console.log(error);
    });
}

// async/await — same result, cleaner code
async function getUserData() {
  try {
    const response = await fetch(url);
    const data = await response.json();
    console.log(data);
  } catch (error) {
    console.log(error);
  }
}
```

The concept is the same. The difference is only in syntax and readability.

| Feature | Promise `.then()` | `async`/`await` |
|---|---|---|
| Readability | Medium | Clean, reads like sync code |
| Chaining | Required | Not needed |
| Error handling | `.catch()` | `try...catch` |
| Passing values forward | Must `return` in each `.then()` | Just use `await` on the next line |
| Looks synchronous | No | Yes |
| Built on Promises | Yes | Yes |

---

## Summary

- `async` makes any function return a **Promise**, even if you return a plain value.
- `await` pauses the execution of an `async` function until a Promise settles — it can only be used **inside** an `async` function.
- `await` does not block the JavaScript engine — only the current `async` function pauses on that line.
- Use **`try...catch`** with `async`/`await` instead of `.catch()` to handle rejected Promises.
- Any line of code that returns a Promise can have `await` placed in front of it.
- `async`/`await` is just a cleaner syntax for Promises — it does not replace them.
- With `fetch`, you need two `await` calls: one for the HTTP response and one for `response.json()`.
