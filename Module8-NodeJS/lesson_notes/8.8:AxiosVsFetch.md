# Axios vs. Fetch — Which Should You Use? 

## 1. Overview

Both Axios and the Fetch API make HTTP requests (GET/POST/...) in JavaScript. The core trade-off: **Fetch is native and lightweight; Axios is a third-party library with more built-in conveniences.** Fetch can reproduce every key Axios feature with extra code — the question is whether you want to write that code.

### At-a-glance comparison

| Characteristic | Fetch API | Axios |
|---|---|---|
| Origin | Native JavaScript API | Third-party library |
| Installation | Built into browsers and **Node.js v18+** | `npm install axios` |
| JSON parsing | Manual — `.json()` | Automatic |
| Error handling | Minimal — rejects only on **network errors** | Comprehensive — rejects on non-2xx too |
| Interceptors | Not available (workarounds possible) | Built in |
| Request cancellation | `AbortController` | Built-in method (+ AbortController) |
| Response transformation | Manual | Automatic |
| Timeout | Manual (AbortController + setTimeout) | `timeout` config option |
| Progress events | Manual via `ReadableStream` | `onDownloadProgress` / `onUploadProgress` |
| Platform support | Modern browsers, Node 18+ | Browser + Node.js (incl. old browsers via XHR) |

## 2. Basic Syntax — Same POST, Both Ways

```js
// Axios — data auto-converted to JSON
const url = "https://jsonplaceholder.typicode.com/posts";
const data = { a: 10, b: 20 };

axios.post(url, data, {
  headers: {
    Accept: "application/json",
    "Content-Type": "application/json;charset=UTF-8",
  },
}).then(({ data }) => {
  console.log(data);
});
```

```js
// fetch() — same result, more manual steps
const options = {
  method: "POST",
  headers: {
    Accept: "application/json",
    "Content-Type": "application/json;charset=UTF-8",
  },
  body: JSON.stringify({ a: 10, b: 20 }), // manual stringify
};

fetch(url, options)
  .then((response) => response.json())    // manual parse
  .then((data) => console.log(data));
```

Key syntax differences:

- Body: Axios → `data` property; fetch → `body` property (must be `JSON.stringify`-ed).
- Response: Axios auto-parses into `response.data`; fetch needs `response.json()` first.
- Headers: handled identically in both.

## 3. Backward Compatibility

- Axios runs even on **IE11** because it uses `XMLHttpRequest` under the hood.
- Fetch requires Chrome 42+, Firefox 39+, Edge 14+, Safari 10.1+.
- But compatibility alone doesn't justify Axios — use a **fetch polyfill**:

```bash
npm install whatwg-fetch --save
```

```js
import "whatwg-fetch";
window.fetch(...);  // may also need a Promise polyfill on very old browsers
```

## 4. JSON Transformation

```js
// Axios — automatic
axios.get("https://api.github.com/orgs/axios")
  .then((response) => console.log(response.data));

// fetch — one extra step
fetch("https://api.github.com/orgs/axios")
  .then((response) => response.json())
  .then((data) => console.log(data))
  .catch((error) => console.error(error));
```

> Note: `.json()` doesn't *produce* JSON — it **parses** a JSON body into a JavaScript object.

## 5. Interceptors

Axios has them built in — global hooks for logging, auth token injection, retrying failed requests:

```js
axios.interceptors.request.use((config) => {
  console.log("Request was sent"); // runs before EVERY request
  return config;
});
// axios.interceptors.response.use(...) for responses (e.g., retry on network error)
```

Fetch has no interceptors, but you can monkey-patch the global function:

```js
fetch = ((originalFetch) => {
  return (...args) => {
    const result = originalFetch.apply(this, args);
    return result.then(console.log("Request was sent"));
  };
})(fetch);
```

Workable, but hacky — interceptors are one of the strongest practical reasons to pick Axios.

## 6. Download Progress

**Axios:** built-in `onDownloadProgress` (paired here with NProgress for UI):

```js
NProgress.start();
axios.get(url, {
  responseType: "blob",
  onDownloadProgress: (progressEvent) => {
    const percent = Math.round((progressEvent.loaded * 100) / progressEvent.total);
    NProgress.set(percent / 100);
  },
}).then((response) => {
  NProgress.done();
  document.getElementById("img").src = URL.createObjectURL(response.data);
});
```

**Fetch:** no progress event — you read the **`ReadableStream`** from `response.body` and count bytes against the `Content-Length` header:

```js
fetch(url).then((response) => {
  if (!response.ok) throw Error(response.status + " " + response.statusText);
  if (!response.body) throw Error("ReadableStream not supported");

  const total = parseInt(response.headers.get("content-length"), 10);
  let loaded = 0;

  return new Response(
    new ReadableStream({
      start(controller) {
        const reader = response.body.getReader();
        (function read() {
          reader.read().then(({ done, value }) => {
            if (done) { controller.close(); return; }
            loaded += value.byteLength;
            NProgress.set(loaded / total);   // progress!
            controller.enqueue(value);
            read();
          });
        })();
      },
    })
  );
})
  .then((response) => response.blob())
  .then((data) => {
    document.getElementById("img").src = URL.createObjectURL(data);
  });
```

Far more code — but streaming in the browser is something Axios itself can't do (see §9).

## 7. Simultaneous Requests

```js
// Axios: axios.all + axios.spread
axios.all([
  axios.get("https://api.github.com/users/iliakan"),
  axios.get("https://api.github.com/users/taylorotwell"),
]).then(axios.spread((obj1, obj2) => {
  console.log(obj1.data.login + " has " + obj1.data.public_repos + " public repos");
  console.log(obj2.data.login + " has " + obj2.data.public_repos + " public repos");
}));

// fetch: native Promise.all
Promise.all([
  fetch("https://api.github.com/users/iliakan"),
  fetch("https://api.github.com/users/taylorotwell"),
]).then(async ([res1, res2]) => {
  const a = await res1.json();
  const b = await res2.json();
  console.log(a.login, b.login);
}).catch(console.log);
```

Equivalent capability — fetch just needs the extra `.json()` steps. (`Promise.all` works with Axios too and is the modern preference over `axios.all`.)

## 8. Error Handling — The Big Behavioral Difference

**fetch() does NOT reject on HTTP errors (404, 500...).** It resolves normally with `response.ok === false`; it only rejects on **network failures**. Axios rejects on any non-2xx status.

```js
// fetch — manual status check required
try {
  const res = await fetch("...");
  if (!res.ok) {
    switch (res.status) {
      case 400: /* handle */ break;
      case 401: /* handle */ break;
      case 404: /* handle */ break;
      case 500: /* handle */ break;
    }
  }
  // handle good response
} catch (err) {
  // network error only
}
```

```js
// Axios — everything lands in catch, cleanly discriminated
try {
  const res = await axios.get("...");
  // handle good response
} catch (err) {
  if (err.response) {
    // server responded with 4xx/5xx
  } else if (err.request) {
    // request sent, no response (network error)
  }
}
```

Payload access recap: fetch → `body` (stringify to send, `.json()` to read); Axios → `data` (plain JS object both ways).

## 9. Advanced Use Cases

### Timeouts

```js
// Axios — one config option
axios.get(url, { timeout: 4000 })
  .then((r) => console.log(r))
  .catch(() => console.error("timeout exceeded"));

// fetch — AbortController + setTimeout
const controller = new AbortController();
const promise = fetch(url, { method: "GET", signal: controller.signal });
const timeoutId = setTimeout(() => controller.abort(), 4000);

promise
  .then((r) => console.log(r))
  .catch(() => console.error("timeout exceeded"));
```

### Cancelling requests

```js
// fetch — AbortController
const controller = new AbortController();
fetch(url, { method: "GET", signal: controller.signal })
  .then((r) => console.log(r))
  .catch(console.error);
const cancelRequest = () => controller.abort();

// Axios — cancelToken (legacy; AbortController also supported in modern Axios)
const source = axios.CancelToken.source();
axios.get(url, { cancelToken: source.token })
  .then((r) => console.log(r))
  .catch(console.error);
const cancel = () => source.cancel();
```

### Streaming

- **Browser:** fetch wins — `response.body` is a `ReadableStream`; Axios's closest browser feature is `onDownloadProgress`.
- **Node.js:** Axios supports `responseType: "stream"`:

```js
axios.get(url, { responseType: "stream" }).then((response) => {
  let responseData = "";
  response.data.on("data", (chunk) => {
    responseData += chunk.toString();
    console.log(`Received chunk: ${chunk.length} bytes`);
  });
  response.data.on("end", () => {
    console.log(JSON.parse(responseData));
  });
});
```

## 10. Decision Framework — When to Use Which

| Use case | Best choice |
|---|---|
| Simple browser requests | **Fetch** (native, lightweight) |
| Large-scale API calls | **Axios** (streaming, interceptors, timeouts) |
| Modern framework defaults / no dependencies | **Fetch** (built into browser + Node 18+) |
| Retry logic & fault tolerance | **Axios** (throws on non-2xx, built-in timeouts) |
| File uploads/downloads with progress | **Axios** (built-in progress events) |
| Reusable HTTP utility layer | **Axios** (instances, defaults, flexibility) |
| Authenticated requests & token management | **Axios** (interceptors) |

### What developers actually say

- **Error handling** is the #1 reason devs pick Axios — non-2xx throws by default.
- **Ease of use** — auto-JSON, interceptors, timeouts: "I could build my own, but then I'd have to build my own."
- **Performance** — fetch has a smaller bundle (even polyfilled) and no abstraction overhead.
- **Flexibility** — Axios can send a body with GET; fetch sticks to HTTP standards.
- **Inertia** — "if it isn't broken, don't fix it": teams with working Axios code rarely migrate.

### FAQ

- **Is fetch faster?** Yes — native, smaller, no extra abstraction, browser streaming support.
- **Will fetch replace Axios?** No — Axios is actively maintained; since **v1.7 Axios can even use fetch as its adapter** instead of XMLHttpRequest.
- **Why do devs still prefer Axios?** The only real drawback is being a dependency — which doesn't hurt most projects.

## 11. CORS Note (Applies to Both)

- CORS errors (`No 'Access-Control-Allow-Origin' header present`) hit Axios and fetch **identically** — the fix is always **server-side** configuration, never the client library.
- Common mistake: adding `Access-Control-Allow-Origin` to the **request** headers — it's a **response** header set by the server.
- Adding custom headers to a request triggers a **preflight `OPTIONS` request** in the browser to verify CORS before the real request is sent.

---

## 12. Quick Revision

- Fetch = native, minimal, manual (stringify, `.json()`, `res.ok` checks, AbortController for timeout/cancel).
- Axios = dependency, batteries included (auto-JSON, non-2xx rejects, interceptors, `timeout`, progress events, instances).
- Everything Axios does, fetch *can* do with extra code; browser streaming is the one thing only fetch does natively.
- Choose fetch for simple/no-dependency projects; choose Axios for large apps with auth, retries, uploads, or a shared HTTP layer.
