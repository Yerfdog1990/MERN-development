# Using Nodemailer in Node.js 

## 1. What Is Nodemailer?

- **Nodemailer** is a **zero-dependency Node.js module** for sending emails from a server — welcome messages, onboarding mails, OTPs, password resets, server error alerts.
- Email uses **SMTP (Simple Mail Transfer Protocol)**, not HTTP. Configuring SMTP by hand (Apache/XAMPP, ports, protocols) is painful; Nodemailer abstracts it away.
- Positioning in the ecosystem:
    - **Nodemailer** — easiest config; ideal for learning and small apps
    - **AWS SES / SendGrid** — production email at scale (backend-as-a-service)
    - **Twilio** — push notifications (OTP/WhatsApp-style), not email
    - **PHPMailer** — the PHP-world equivalent

### The standard workflow (4 steps)

1. `npm install nodemailer`
2. Create a **transporter** (SMTP config — the "delivery guy")
3. Define **mail options** (from, to, subject, body)
4. Send with `transporter.sendMail()` (callback or async/await)

---

## 2. Gmail Setup — App Passwords (Required)

**Never use your real Gmail password.** Google blocks bot access to accounts and requires:

1. Enable **2-Step Verification** on your Google account (myaccount.google.com → Security).
2. Gmail → profile → **Manage your Google Account** → **Security** → search **"App passwords"**.
3. Verify your identity, name the app/device, click **Generate**.
4. Copy the **16-character app password** (e.g., `tdrf azmm trrb ezxx`) somewhere secure — use *this* in Nodemailer.

The app password never exposes your real password and can be revoked independently.

## 3. Basic Email — Full Example

```bash
npm install nodemailer
```

```js
const nodemailer = require("nodemailer");

async function sendTestEmail() {
  // Step 1: reusable transporter (SMTP config)
  const transporter = nodemailer.createTransport({
    host: "smtp.mailtrap.io",  // or smtp.gmail.com etc.
    port: 2525,                // 587 or 465 for secure connections
    secure: false,             // true for 465, false for other ports
    auth: {
      user: process.env.SMTP_USER, // credentials from env vars — never hardcode
      pass: process.env.SMTP_PASS,
    },
  });

  // Step 2: mail parameters
  const mailOptions = {
    from: '"Your App Name" <no-reply@yourapp.com>',
    to: "recipient@example.com",
    subject: "Hello from Node.js!",
    text: "This is a plain-text email message.",
    html: "<h1>Welcome!</h1><p>This is an HTML email body.</p>",
  };

  // Step 3: send
  try {
    const info = await transporter.sendMail(mailOptions);
    console.log("Message sent! ID: %s", info.messageId);
  } catch (error) {
    console.error("Nodemailer error:", error);
  }
}

sendTestEmail();
```

### Transporter variants

```js
// Gmail (simplest — service shortcut)
const transporter = nodemailer.createTransport({
  service: "gmail",
  auth: {
    user: "youraddress@gmail.com",
    pass: "tdrf azmm trrb ezxx", // 16-char App Password
  },
});

// Outlook/Yahoo/etc. (explicit SMTP)
const transporter = nodemailer.createTransport({
  host: "smtp-mail.outlook.com",
  port: 587,
  secure: false,
  auth: { user: "you@outlook.com", pass: "app-password" },
});

// Company SMTP server
const transporter = nodemailer.createTransport({
  host: "smtp.yourcompany.com",
  port: 465,
  secure: true,
  auth: { user: "noreply@yourcompany.com", pass: "password" },
});

// Ethereal (fake SMTP for testing — no real credentials, mails captured in dashboard)
nodemailer.createTestAccount().then((testAccount) => {
  const transporter = nodemailer.createTransport({
    host: "smtp.ethereal.email",
    port: 587,
    secure: false,
    auth: { user: testAccount.user, pass: testAccount.pass },
  });
});
```

### Mail options reference

```js
const mailOptions = {
  from: '"My Company" <my@company.com>',   // sender
  to: "a@x.com, b@y.com",                  // comma-separated for multiple recipients
  cc: "email@gmail.com",                   // carbon copy
  bcc: "email@gmail.com",                  // blind carbon copy
  subject: "Welcome onboard!",
  text: "Plain text body",                 // fallback
  html: "<h1>HTML body</h1>",              // rich body
  attachments: [                           // any file type — array
    { filename: "pic-1.jpeg", path: "./attachments/pic-1.jpeg" },
    { filename: "document.pdf", path: "/path/to/document.pdf" },
  ],
};
```

## 4. Express Demo — Email API Endpoints

```js
/**
 * Nodemailer Demo — Email Sending via SMTP
 * Install: npm install nodemailer
 */
import express from "express";
import nodemailer from "nodemailer";

const app = express();
app.use(express.json());

const transporter = nodemailer.createTransport({
  service: "gmail",
  auth: {
    user: process.env.SMTP_USER, // your Gmail
    pass: process.env.SMTP_PASS, // Google App Password
  },
});

// simple fixed email
app.post("/send-email", (req, res) => {
  const mailOptions = {
    from: process.env.SMTP_USER,
    to: "recipient@gmail.com",
    subject: "Welcome onboard!",
    text: "Hello Aryan",
  };

  transporter.sendMail(mailOptions, (error, info) => {
    if (error) {
      return res.status(500).json({ error: "Failed to send email", details: error.message });
    }
    res.json({ message: "Email sent", messageId: info.messageId, response: info.response });
  });
});

// dynamic email from request body
app.post("/send-dynamic-email", (req, res) => {
  const { to, subject, text, html } = req.body;

  transporter.sendMail(
    {
      from: process.env.SMTP_USER,
      to: to || "recipient@gmail.com",
      subject: subject || "No subject",
      text: text || "No text content",
      html: html || undefined,
    },
    (error, info) => {
      if (error) return res.status(500).json({ error: error.message });
      res.json({ message: "Dynamic email sent", messageId: info.messageId });
    }
  );
});

// rich HTML email (+ optional attachments)
app.post("/send-rich-email", (req, res) => {
  const richMailOptions = {
    from: process.env.SMTP_USER,
    to: "recipient@gmail.com",
    subject: "Rich Email with Attachments",
    html: `
      <h1>Welcome!</h1>
      <p>This is a <strong>rich HTML email</strong>.</p>
      <ul>
        <li>Bold text</li>
        <li><em>Italic text</em></li>
        <li><a href="https://example.com">Links</a></li>
      </ul>`,
    // attachments: [{ filename: "document.pdf", path: "/path/to/document.pdf" }],
  };

  transporter.sendMail(richMailOptions, (error, info) => {
    if (error) return res.status(500).json({ error: error.message });
    res.json({ message: "Rich email sent", messageId: info.messageId });
  });
});

// verify SMTP config without sending anything
app.get("/verify-transporter", async (req, res) => {
  try {
    await transporter.verify();
    res.json({ message: "Transporter is ready to send emails" });
  } catch (error) {
    res.status(500).json({ error: "Transporter verification failed", details: error.message });
  }
});

const PORT = 3004;
app.listen(PORT, () => {
  console.log(`Nodemailer demo server running on http://localhost:${PORT}`);
});
```

> `transporter.verify()` is a handy pre-flight check — it confirms credentials/connection before you ever hit "send."

## 5. HTML Email Templates with Handlebars

Raw HTML strings inside JS get messy in production. Pair Nodemailer with **`nodemailer-express-handlebars`** to keep templates in files with `{{variables}}`:

```bash
npm i nodemailer nodemailer-express-handlebars
```

```html
<!-- views/email.handlebars -->
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>Welcome Email</title>
  <style>
    h2 { color: #c4c4c4; } /* style emails like any HTML page */
  </style>
</head>
<body>
  <h2>Hello {{name}}!</h2>
  <p>We're glad to have you on board at {{company}}.</p>
</body>
</html>
```

```js
const hbs = require("nodemailer-express-handlebars");
const nodemailer = require("nodemailer");
const path = require("path");

const transporter = nodemailer.createTransport({
  service: "gmail",
  auth: { user: process.env.SMTP_USER, pass: process.env.SMTP_PASS },
});

// attach the template engine to the transporter
transporter.use("compile", hbs({
  viewEngine: {
    extName: ".handlebars",
    partialsDir: path.resolve("./views"),
    defaultLayout: false,
  },
  viewPath: path.resolve("./views"),
  extName: ".handlebars",
}));

// send using the template
const mailOptions = {
  from: '"My Company" <info@mycompany.com>',
  to: "user@example.com",
  subject: "Welcome to our platform!",
  template: "email",            // → ./views/email.handlebars
  context: {                    // values substituted into {{variables}}
    name: "Adebola",
    company: "My Company",
  },
};

await transporter.sendMail(mailOptions);
```

### Bulk sending (e.g., welcome mail to many users)

```js
for (const user of users) {
  if (!user.email) continue;
  try {
    await transporter.sendMail({
      from: '"My Company" <my@company.com>',
      to: user.email,
      subject: `Welcome to My Company, ${user.name}`,
      template: "email",
      context: { name: user.name, company: "my company" },
    });
  } catch (error) {
    console.log(`Error sending to ${user.email}`, error);
  }
}
```

## 6. Production Best Practices

1. **Never hardcode credentials** — load SMTP user/pass from environment variables (`process.env.SMTP_USER`, `process.env.SMTP_PASS`), keep them out of git.
2. **Gmail = App Password only** — real passwords won't work and shouldn't be used; 2FA + 16-char app password is mandatory.
3. **Isolate development** — use a mock SMTP inbox like **Mailtrap**, **MailDev**, or Nodemailer's built-in **Ethereal** test accounts so test runs never spam real recipients.
4. **Reuse one transporter** — create it once at startup, not per request.
5. **Verify before sending** — `await transporter.verify()` catches bad config early.
6. **Scale-up path** — for high volume/deliverability, move to a provider API (AWS SES, SendGrid) rather than raw Gmail SMTP; Gmail accounts have daily sending limits.

---

## 7. Quick Revision

- Email = **SMTP**, not HTTP; Nodemailer abstracts SMTP in Node.js.
- Flow: **install → createTransport (delivery guy) → mailOptions (what/whom) → sendMail** (callback or async/await; `info.messageId` on success).
- Gmail requires **2FA + App Password** — never the real password; credentials always via `process.env`.
- `mailOptions` supports `to` (comma-separated), `cc`, `bcc`, `text`, `html`, and `attachments` (array of `{filename, path}` — any file type).
- Templates: `nodemailer-express-handlebars` → `template` + `context` replace `{{variables}}` in `.handlebars` files; style with normal CSS in `<head>`.
- Test with Ethereal/Mailtrap; verify config with `transporter.verify()`; graduate to SES/SendGrid for production scale.
