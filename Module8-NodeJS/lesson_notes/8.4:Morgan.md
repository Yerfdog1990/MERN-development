# Morgan in Node.js 

## 1. What Is Morgan?

- **Morgan** is an **HTTP request logger middleware** for Node.js/Express. Unlike general-purpose loggers (Winston, Pino, Bunyan), its **only job is logging HTTP requests** — it's added as middleware so every request passing through Express gets logged automatically.
- It captures data like **HTTP method, URL, status code, response time, response size, IP, and user-agent**, and formats it into clean, readable log lines — replacing the hand-written `fs.appendFile` logger middleware you'd otherwise build yourself.
- Recommended as a Node.js logging best practice for clean, systematized backend request tracking.

### Why log at all?

- Logs are an **audit of events** — they tell you what your code actually did, saving hours of debugging ("show me the log" is the first thing asked when something breaks in production).
- A log points to **where** a failure happened (e.g., which route, at what time the system was up/down).
- **What NOT to log:** personal data (user info) and sensitive data (passwords, credit card numbers).

## 2. Quick Start

```bash
npm install morgan
```

```js
const express = require("express");
const morgan = require("morgan");

const app = express();

// 'dev' format — colored console output
app.use(morgan("dev"));

app.get("/", (req, res) => {
  res.send("Hello from the server!");
});

app.listen(3000, () => console.log("Server running on port 3000"));
```

Register it **before your routes** (standard middleware placement) so all requests are captured.

## 3. The Five Predefined Formats

Pass a format name string to `morgan()`:

| Format | What it logs | Use case |
|---|---|---|
| `dev` | Method, URL, status (color-coded), response time, size | Local development/debugging |
| `tiny` | Minimal: method, URL, status, size, response time | Minimal output |
| `short` | tiny + remote address; shorter than common | Middle ground |
| `common` | Apache **common** log: IP, date, method, URL, HTTP version, status, size | Standard server logs |
| `combined` | Apache **combined** log: common + referrer + **user-agent** | Production tracking (most detail) |

Example outputs:

```text
dev:      POST /login 200 12.345 ms - 25
tiny:     GET / 200 2.534 ms
combined: ::1 - - [12/Jul/2026:06:53:00 +0000] "GET / HTTP/1.1" 200 123 "-" "Mozilla/5.0..."
```

```js
app.use(morgan("combined"));
app.use(morgan("common"));
app.use(morgan("dev"));
app.use(morgan("short"));
app.use(morgan("tiny"));
```

## 4. Custom Tokens and Format Strings

Formats are built from **tokens** (`:method`, `:url`, `:status`, `:response-time`, `:res[content-length]`, `:remote-addr`, `:date`, ...). Define your own with `morgan.token()`:

```js
// custom token
morgan.token("custom-date", () => new Date().toISOString());

// custom format string using built-in + custom tokens
app.use(morgan(":custom-date :method :url :status :res[content-length] - :response-time ms"));
```

### Structured JSON logging

Plain text strings are hard to parse at scale. Pass a **function** `(tokens, req, res)` to emit structured JSON instead:

```js
app.use(morgan((tokens, req, res) => {
  return JSON.stringify({
    method: tokens.method(req, res),
    url: tokens.url(req, res),
    status: tokens.status(req, res),
    responseTime: tokens["response-time"](req, res) + " ms",
    timestamp: tokens.date(req, res, "iso"),
  });
}));
```

## 5. Logging to a File (instead of console)

Use the `stream` option with an **append-mode** write stream (append, so old entries aren't overwritten — same lesson as `appendFile` vs `writeFile` in the custom logger):

```js
import fs from "fs";
import path from "path";
import morgan from "morgan";

// ensure logs directory exists
const logDirectory = path.join(import.meta.dirname, "logs");
fs.existsSync(logDirectory) || fs.mkdirSync(logDirectory);

// append-mode write stream
const accessLogStream = fs.createWriteStream(
  path.join(logDirectory, "access.log"),
  { flags: "a" }
);

app.use(morgan("combined", { stream: accessLogStream }));
```

## 7. Log Levels (General Logging Best Practice)

Define log levels with your team before building — they classify entries by **urgency** so you can triage at a glance:

| Level | Meaning |
|---|---|
| `FATAL` | Very severe — application will likely abort |
| `ERROR` | Serious problem/failed execution that must be dealt with (app may continue) |
| `WARN` | Potentially harmful/unexpected situation — notice it to prevent failures |
| `INFO` | Informational — a completed task / normal progress |
| `DEBUG` | Developer-only detail, little value in production |

> Morgan itself doesn't do levels — it logs requests. Levels come from a general-purpose logger (Winston, Pino...), which is why the two are commonly paired.

## 8. Pairing Morgan with Winston (Production Pattern)

Morgan captures HTTP traffic; **Winston** manages where and how logs are stored (multiple transports: console, files, cloud services like Loggly/CloudWatch). Pipe Morgan's output into Winston via the `stream` option:

```js
const morgan = require("morgan");
const logger = require("./logger"); // a winston logger instance

// custom token for error messages set on res.locals
morgan.token("message", (req, res) => res.locals.errorMessage || "");

const getIpFormat = () =>
  process.env.NODE_ENV === "production" ? ":remote-addr - " : "";

const successResponseFormat = `${getIpFormat()}:method :url :status - :response-time ms`;
const errorResponseFormat = `${getIpFormat()}:method :url :status - :response-time ms - message: :message`;

// successes → logger.info ; skip errors
const successHandler = morgan(successResponseFormat, {
  skip: (req, res) => res.statusCode >= 400,
  stream: { write: (message) => logger.info(message.trim()) },
});

// errors → logger.error ; skip successes
const errorHandler = morgan(errorResponseFormat, {
  skip: (req, res) => res.statusCode < 400,
  stream: { write: (message) => logger.error(message.trim()) },
});

module.exports = { successHandler, errorHandler };
```

Key tricks in this pattern:

- **`skip`** option filters which requests a given morgan instance logs (split success vs error streams).
- **`stream.write`** redirects morgan's output into any sink — here, Winston's `info`/`error` methods.

### Minimal Winston logger for reference

```js
const winston = require("winston");

const logger = winston.createLogger({
  level: process.env.NODE_ENV === "development" ? "debug" : "info",
  format: winston.format.combine(
    winston.format.colorize(),
    winston.format.printf(({ level, message }) => `${level}: ${message}`)
  ),
  transports: [
    new winston.transports.Console({ stderrLevels: ["error"] }),
    // or route by level to files:
    // new winston.transports.File({ filename: "error.log", level: "error" }),
    // new winston.transports.File({ filename: "combined.log" }),
  ],
});

module.exports = logger;
```

## 9. Morgan vs. Other Node.js Logging Tools

| Library | Type | Highlights |
|---|---|---|
| **Morgan** | HTTP request logger (middleware) | 5 ready-made formats, zero config, custom tokens |
| **Winston** | General-purpose logger | Most popular (~17.8k★); multiple transports (files, console, cloud: logz.io, AWS CloudWatch); highly configurable |
| **Pino** | General-purpose logger | "Very low overhead" — minimal resources, worker-thread processing; NDJSON output; `pino-pretty` formatter; `pino-http` for Express; default in Fastify |
| **Bunyan** | JSON logger | JSON logs by default, CLI log filtering, serializers, child loggers, log snooping for prod debugging; runs beyond Node (Webpack, Browserify, NW.js) |
| **npmlog** | npm's own logger | Custom levels, colored output; huge downloads because npm itself uses it |

Rule of thumb: **`console.log` for tiny side projects → a log library as the project grows** (console.log has a small performance cost and no levels/transports). Morgan for HTTP traffic + Winston/Pino for application logs is the common production combo.

### Beyond libraries

- **Log management systems** (real-time tracking/analysis): Sentry, Loggly, Graylog, Splunk, Datadog, Logstash/ELK.
- **Health monitoring tools** (uptime, crashes, perf): PM2, Sematext, App Metrics, ClinicJS, AppSignal, Express Status Monitor.

## 10. Quick Revision

- Morgan = third-party **HTTP request logging middleware**; `app.use(morgan("<format>"))` before routes.
- Five formats: `dev` (colored, development), `tiny`, `short`, `common`, `combined` (Apache-style, production).
- Customize with `morgan.token()` + format strings, or a function for **JSON logs**.
- `stream` option → log to files (append mode) or pipe into **Winston**; `skip` option → filter by status code.
- Don't log secrets/PII. Define **log levels** (fatal/error/warn/info/debug) with a general-purpose logger; Morgan handles the HTTP layer only.
