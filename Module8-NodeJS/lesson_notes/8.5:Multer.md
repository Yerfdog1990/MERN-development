# Using Multer in Node.js 

## 1. Why Multer Exists

- Web forms carry more than text: images, videos, PDFs, dropdowns — **multipart data**.
- Express's built-in body parsers (`express.json()`, `express.urlencoded()` — the body-parser family) populate `req.body` for **text inputs only**. They **cannot handle `multipart/form-data`**. Submit a file form and `req.body` logs empty.
- **Multer** is a Node.js middleware built specifically to parse `multipart/form-data`. It:
    - attaches text fields to `req.body` (like body-parser does),
    - attaches file info to **`req.file`** (single) or **`req.files`** (multiple),
    - saves the file(s) to disk or memory per your storage config.
- Only use Multer on multipart forms — it can't parse anything that isn't multipart.

### Form encoding background

Every form has an `enctype` (how the browser encodes data before sending):

- `application/x-www-form-urlencoded` (default) — alphanumeric data only
- `multipart/form-data` — required for file uploads

Two ways to send multipart data:

```html
<!-- 1. enctype attribute -->
<form action="/upload_files" enctype="multipart/form-data">...</form>
```

```js
// 2. FormData API (for fetch/XHR)
const form = new FormData();
form.append("name", "Dillion");
form.append("image", fileObject);
```

## 2. Installation and Basic Setup

```bash
npm install express multer
```

```js
const express = require("express");
const multer = require("multer");

const app = express();
const upload = multer({ dest: "uploads/" }); // simplest config — Multer creates the folder
```

> **Gotcha (basic `dest` config):** files are saved under **random hashed names with no extension** — they look "corrupted"/unreadable. This prevents naming collisions, but to keep readable filenames use `diskStorage` (§4). The extension is what makes a file readable — `bekas.png` can be renamed to anything, but `.png` must survive.

## 3. The Three Upload Modes

| Method | Form structure | Files land in |
|---|---|---|
| `upload.single(fieldname)` | One file in one field | `req.file` (object) |
| `upload.array(fieldname, maxCount)` | Multiple files, same field | `req.files` (array) |
| `upload.fields([{ name, maxCount }, ...])` | Files spread across different fields | `req.files` (object keyed by field name) |

```js
// single file — req.file
app.post("/profile", upload.single("avatar"), (req, res) => {
  // req.file  → file info; req.body → any text fields
  res.send("File uploaded successfully.");
});

// multiple fields — req.files.cover / req.files.photos
app.post("/gallery", upload.fields([
  { name: "cover", maxCount: 1 },
  { name: "photos", maxCount: 8 },
]), (req, res) => {
  res.send("Gallery files uploaded.");
});
```

> The field name argument (`"avatar"`, `"photos"`) **must match** the key used in the frontend `FormData`/form input name — mismatch is the #1 cause of `req.file === undefined`.

## 4. Disk Storage Engine (Custom Destination + Filename)

Full control over where files go and what they're called:

```js
const path = require("path");

const storage = multer.diskStorage({
  destination: (req, file, cb) => {
    cb(null, "public/uploads/"); // storage path
  },
  filename: (req, file, cb) => {
    // unique name: timestamp + random id + ORIGINAL extension
    const uniqueSuffix = Date.now() + "-" + Math.round(Math.random() * 1e9);
    cb(null, file.fieldname + "-" + uniqueSuffix + path.extname(file.originalname));
  },
});

const upload = multer({ storage });
```

Naming strategies:

```js
// keep the exact original name (readable, but collisions possible)
cb(null, file.originalname);

// unique + extension preserved (production-safe)
cb(null, uniqueSuffix + path.extname(file.originalname));
```

### Memory storage

Store the file **in RAM as a Buffer** (`req.file.buffer`) — useful for small files or when processing/forwarding before saving (e.g., streaming to S3/Cloudinary):

```js
const upload = multer({
  storage: multer.memoryStorage(),
  limits: { fileSize: 2 * 1024 * 1024 }, // keep limits tight — it's RAM
});
```

## 5. Security: `limits` and `fileFilter`

Protect the server from oversized and malicious uploads:

```js
const uploadSecure = multer({
  storage,
  limits: {
    fileSize: 2 * 1024 * 1024, // hard 2MB ceiling (bytes)
  },
  fileFilter: (req, file, cb) => {
    // validate BOTH mimetype and extension
    const allowedTypes = /jpeg|jpg|png|gif/;
    const isMimeValid = allowedTypes.test(file.mimetype);
    const isExtValid = allowedTypes.test(path.extname(file.originalname).toLowerCase());

    if (isMimeValid && isExtValid) {
      return cb(null, true);  // accept
    }
    cb(new Error("Invalid file format. Only images are permitted!")); // reject
  },
});
```

Mimetype-list variant:

```js
const fileFilter = (req, file, cb) => {
  const allowedTypes = ["image/jpeg", "image/png", "image/gif"];
  if (allowedTypes.includes(file.mimetype)) cb(null, true);
  else cb(new Error("Invalid file type. Only JPEG, PNG, and GIF are allowed."), false);
};
```

Video-only filter example:

```js
const fileFilter = (req, file, cb) => {
  const filetypes = /.mp4|.avi|.mkv/;
  const extname = filetypes.test(path.extname(file.originalname).toLowerCase());
  if (extname) return cb(null, true);
  cb("Error: Videos Only!");
};

const upload = multer({
  dest: "uploads/",
  fileFilter,
  limits: { fileSize: 100000000 }, // ~100MB for video
});
```

## 6. Handling Multer Errors

Multer raises errors asynchronously (size limit hit, filter rejection). Catch them in a standard **Express error-handling middleware** (bottom of the app):

```js
app.post("/upload-image", uploadSecure.single("image"), (req, res) => {
  res.status(200).json({ status: "Success", file: req.file });
});

// global error handler — distinguishes Multer's own errors from fileFilter errors
app.use((err, req, res, next) => {
  if (err instanceof multer.MulterError) {
    // Multer internal errors: LIMIT_FILE_SIZE, LIMIT_UNEXPECTED_FILE, ...
    return res.status(400).json({ error: `Multer Error: ${err.message}` });
  } else if (err) {
    // custom errors thrown inside fileFilter
    return res.status(400).json({ error: err.message });
  }
  next();
});
```

### Security rule: never register Multer globally

```js
app.use(upload.single("file"));   // ❌ NEVER — every endpoint now accepts file uploads
app.post("/profile", upload.single("dp"), handler); // ✅ per-route only
```

A global Multer lets attackers inject files into any open endpoint. Attach the instance **only to the specific POST/PUT routes** that need uploads.

## 7. Full Runnable Demo

```js
/**
 * Multer Middleware Demo — File Upload Handler
 * Express cannot handle multipart/form-data; Multer fills the gap.
 * Install: npm install multer
 */
import express from "express";
import multer from "multer";
import path from "path";
import fs from "fs";

const app = express();
app.use(express.json());
app.use(express.urlencoded({ extended: true }));

// ensure uploads directory exists
const uploadDir = path.join(import.meta.dirname, "uploads");
if (!fs.existsSync(uploadDir)) {
  fs.mkdirSync(uploadDir, { recursive: true });
}

// disk storage with readable filenames (recommended)
const storage = multer.diskStorage({
  destination: (req, file, cb) => cb(null, uploadDir),
  filename: (req, file, cb) => {
    cb(null, file.originalname); // keep extension → file stays readable
    // production-safe alternative:
    // const uniqueSuffix = Date.now() + "-" + Math.round(Math.random() * 1e9);
    // cb(null, uniqueSuffix + path.extname(file.originalname));
  },
});

const upload = multer({ storage });

// Route 1: single file
// Postman: POST /profile → Body → form-data → key "dp" (type: File)
app.post("/profile", upload.single("dp"), (req, res) => {
  if (!req.file) return res.status(400).json({ error: "No file uploaded" });

  res.json({
    message: "Profile picture uploaded successfully",
    file: {
      originalname: req.file.originalname,
      filename: req.file.filename,
      mimetype: req.file.mimetype,
      size: req.file.size,
      path: req.file.path, // useful for forwarding to Cloudinary/S3
    },
  });
});

// Route 2: multiple files, same field (max 5)
app.post("/gallery", upload.array("photos", 5), (req, res) => {
  if (!req.files || req.files.length === 0) {
    return res.status(400).json({ error: "No files uploaded" });
  }
  res.json({
    message: `${req.files.length} files uploaded successfully`,
    files: req.files.map((f) => ({
      originalname: f.originalname,
      filename: f.filename,
      size: f.size,
    })),
  });
});

// Route 3: different fields
app.post("/documents", upload.fields([
  { name: "avatar", maxCount: 1 },
  { name: "resume", maxCount: 1 },
]), (req, res) => {
  res.json({
    message: "Documents uploaded successfully",
    avatar: req.files.avatar,
    resume: req.files.resume,
  });
});

// Route 4: plain text form data (no Multer needed)
app.post("/data", (req, res) => {
  res.json({ message: "Data received", body: req.body });
});

const PORT = 3003;
app.listen(PORT, () => {
  console.log(`Multer demo server running on http://localhost:${PORT}`);
});
```

**Testing in Postman:** POST → Body → **form-data** → set the key name to match the route's field name (`dp`, `photos`, `avatar`, `resume`) → change key type from Text to **File** → attach → Send.

## 8. Frontend Integration (FormData + fetch)

```html
<!-- index.html -->
<form id="form">
  <input name="name" id="name" placeholder="Enter your name" />
  <input id="files" type="file" multiple>   <!-- multiple = select several files -->
  <button type="submit">Upload</button>
</form>
```

```js
// script.js
const form = document.getElementById("form");
form.addEventListener("submit", submitForm);

function submitForm(e) {
  e.preventDefault(); // stop browser's default form navigation

  const name = document.getElementById("name");
  const files = document.getElementById("files");

  const formData = new FormData();
  formData.append("name", name.value);              // → req.body.name
  for (let i = 0; i < files.files.length; i++) {
    formData.append("files", files.files[i]);       // → req.files (upload.array("files"))
  }
  // single file variant: formData.append("singleFile", files.files[0]);

  fetch("http://localhost:5000/upload_files", {
    method: "POST",
    body: formData, // do NOT set Content-Type manually — browser sets the multipart boundary
  })
    .then((res) => console.log(res))
    .catch((err) => console.log("Error occurred", err));
}
```

Matching backend:

```js
app.post("/upload_files", upload.array("files"), (req, res) => {
  console.log(req.body);   // text fields (name)
  console.log(req.files);  // uploaded files array
  res.json({ message: "Successfully uploaded files" });
});
```

## 9. FAQ / Troubleshooting

**`req.file` is undefined?**

1. Confirm the client is actually sending a file to that endpoint (form-data, key type = File).
2. Field name in `upload.single("x")` must equal the FormData/input key.
3. Using `upload.single` vs `upload.array` correctly? (`.array` → `req.files`, not `req.file`.)
4. Multer initialized and attached to that specific route?

**`req.body` empty on a file form?** You parsed with `express.json()`/`urlencoded()` only — they don't support multipart. Add Multer to the route.

**File looks corrupted after upload?** You used bare `{ dest: ... }` — the saved file has no extension. Use `diskStorage` and preserve `path.extname(file.originalname)`.

**Uploading onward to Cloudinary/S3?** Use `req.file.path` (disk) or `req.file.buffer` (memoryStorage) and forward via the provider's upload API.

---

## 10. Quick Revision

- Multer = third-party middleware for **`multipart/form-data`** (Express has nothing built in for files).
- Text fields → `req.body`; files → `req.file` / `req.files`.
- Three modes: `.single(field)`, `.array(field, max)`, `.fields([...])` — field names must match the frontend.
- Bare `dest:` = hashed names, no extension; **`diskStorage`** = custom path + filename (keep the extension!); **`memoryStorage`** = Buffer in RAM.
- Harden with `limits.fileSize` + `fileFilter` (check mimetype AND extension), catch `multer.MulterError` in an error middleware.
- **Never `app.use(upload...)` globally** — attach per-route only.
